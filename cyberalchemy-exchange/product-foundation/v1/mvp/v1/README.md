# Exchange MVP product design

Proposed plan, 2026-09-13. Owner: Exchange product owner. No authority effect.

1. [Whole-product design and journeys](EXCHANGE-MVP.md)
2. [Capabilities and their contribution to the thesis](CAPABILITIES-AND-THESIS.md)
3. [Integration roadmap](ROADMAP.md)
4. [Machine plan](plan.json) and [exact input snapshot](inputs.json)

The proposal defines ten participant outcomes over the existing implementation
inventory. It includes project purchases, free/paid community inference and paid
managed Alch hosting inside one Exchange application. Projects sold through it
remain offerings, not substitutes for building the Exchange.

## Later owner decision

[Quality-based automatic routing](../../QUALITY-ROUTING-DECISION.json) is now required
in the MVP. The original plan and its input hashes remain the prior planning epoch;
its blanket network deferral must not exclude this selected routing requirement.
Scoring ownership/method and any validator consensus remain open. A successor plan
must bind the chosen evaluation capability and its tests before implementation.

## Open Questions

The [product question register](../../OPEN-QUESTIONS.md) owns decisions. Source
and reference validation does not prove runtime conformance, deployment readiness
or customer value. Those have separate milestone acceptance criteria.
