Local authentication

Use KEP without a browser

Sign, encrypt and save on your machine through the CLI or the versioned API client.

Solana Devnet

Start locally

Run the verified CLI package supplied by your KEP operator, or use the source checkout during development. It verifies the service identity before reading your account.

kep --help

node cli/kep.mjs --help

node cli/kep.mjs login \
  --api https://your-kep-host \
  --keypair /private/solana-id.json \
  --recovery /private/kep-recovery.json \
  --json

Use account create only for a new account. The recovery destination must be private and must not already exist.

What the CLI handles

Account
Create, authenticate and recover
Identity
Export public receiving details
Exchange
Encrypt, upload, grant, receive and verify
Interruption
Resume an encrypted send journal or retry an exact acknowledgement

Sending requires explicit retention acceptance and transaction approval. Receiving writes only to the selected path and preserves an existing file unless overwrite is explicit. Reissue is outside this first release.

Use through code

import { openWorkspace, sendFile, receiveFile } from './cli/client.mjs';

Direct HTTP clients must implement the canonical authorization messages and cryptographic formats. Endpoint names by themselves are not enough. See CLI-API.md in the source package.

Security boundary

Never paste or upload a keypair, recovery key or content key. Public identity and handoff cards contain routing and encryption material, not authorization. Confirm file paths, retention and Devnet effects before running an agent.
