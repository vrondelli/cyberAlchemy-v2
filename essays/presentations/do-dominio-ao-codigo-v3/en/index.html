07 / Tactical Design

Reservation goes through the rule.

reserve(order: OrderId) {
  if (!this.isSellable()) {
    throw new UnitNotSellable();
  }

  this.allocatedOrder = order;
  this.recordEvent(
    new UnitReserved(
      this.id, order
    )
  );
}

Pseudocode inside SellableUnit.

CheckReevaluate the policy before accepting the reservation.
CommitAllocate the unit to the order.
Record the factUnitReserved is the Domain Event of an accepted reservation.
The operation must check the policy before committing the unit. It allocates the order and records UnitReserved. Two in-memory instances may have read the unit as free, so persistence must serialize reservations or detect version conflicts; only one may commit. An event describes an accepted result, not an unaccepted request. Next, test the policy conditions, then examine how contexts communicate the confirmed facts. 09 / Bounded Contexts and Domain Events

Who produces the fact? Who reacts?

Read the map top to bottom. UnitReceived is communicated to both Quality and Commerce. Quality performs inspection and communicates either InspectionPassed or InspectionFailed. Passing inspection together with the other conditions allows release. The Store updates its offer, then requests a reservation by command. The request can be rejected; only an accepted, persisted reservation produces the communicated UnitReserved fact. Arrows crossing contexts are integration contracts, not direct aggregate calls. Internal domain events and external message formats may differ. Next zoom in on reservation components. 09 / Tactical Design · Components

The aggregate decides. Integration happens outside.

The application handler loads SellableUnit and calls reserve. The aggregate checks the policy, allocates the unit, and records UnitReserved in memory. The application persists state and pending integration messages in one transaction with concurrency control. A publisher sends committed messages; the Store handler updates availability. The aggregate does not depend on that update to reject another reservation. Pending messages illustrate Transactional Outbox, a didactic implementation choice; this does not imply CQRS or Event Sourcing. Rejection or a failed commit does not publish a confirmed reservation. Reference: https://microservices.io/patterns/data/transactional-outbox.html . Open questions: delivery, deduplication, ordering, and storage implementation.
