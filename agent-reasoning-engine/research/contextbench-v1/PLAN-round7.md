# Exact-generation reasoning-state experiment

Status: selected successor construction; not frozen or live. Authority effect
none. Continuity: [round7-continuity.json](round7-continuity.json).

## Objective and gap

The enduring objective remains improved reusable ARE reasoning, useful
continuity, recovery, correctness, and completed outcomes within cumulative
model input plus output tokens. The initial objective remains GLM-5.3-flash
qualification, small context windows first. The current milestone remains the
unchanged [ContextBench acceptance contract](acceptance.json), with SWE-bench
excluded and reserved confirmation untouched.

Round five established structured terminal submission as candidate common
instrumentation. Round six attempted three of sixteen frozen cells, retained all
three failures, and left thirteen unstarted under its stopping rule. One control
had a network request failure. Both state cells measured a future-generation
projection before recycling and failed in that speculative tokenizer path. Zero
model requests received state, so H11 remains untested.

The exact gap is the synchronous render seam. It forced episode code to prepare
generation `n+1` before the recycler selected generation `n` or `n+1`. The
successor makes rendering awaitable and builds state only from the generation
the recycler actually requests.

Question: does exact-generation event-derived state improve native evidence
selection after actual recycling without speculative tokenizer work?

## Competing hypotheses

- H13: exact-generation state restores useful task process after recycling and
  improves paired native outcomes.
- H12-R7: source-recovery deduplication is sufficient; richer task state mainly
  adds tokens.
- H0-R7: semantic interpretation is limiting, so exact state exposure produces
  no native benefit.

H13 is selected because it repairs the observed zero-exposure instrument defect
without changing the intended H11 scientific variable. H12 and H0 remain typed
alternatives in [hypotheses-round7.json](hypotheses-round7.json).

## Fixed development decision rule

Use the same eight exposed language-stratified tasks at 8K, 7K recycle, and 96K
cumulative model-token cap per cell. Both arms use identical source access,
tools, output deferral, structured terminal submission, correction allowance,
provider profile, and native scorer. Only exact-generation state presentation
differs. Alternate within-pair order.

H13 requires at least +0.05 paired macro span F1, file F1 non-degradation,
valid-completion non-degradation, at least one verified post-recycle treatment
presentation, zero control presentations, zero speculative measurements, zero
false facts/source credit/effects, known model usage, and unchanged caps. Report
all failures and actual tokens. This exposed development result cannot itself
clear the benchmark.

Full clearance still requires all 1,136 identities, 8K/10K/12K, every declared
token tier, repository-cluster inference, and two reserved confirmation
repetitions.
