## Research method and gap

objective → gap → question → competing hypotheses → selection → experiment/tasks/criteria → results → observations → reviewed decision → successor

Round 22 accounted all 24 scheduled pairs. Its state-minus-control gain was
+0.0249569013 span F1 and +0.0359126984 file F1, while state used 94,797 fewer
cumulative branch model tokens. The path policy passed all 94 presentations,
but state produced 20 valid completions against 21 control and missed the +0.05

The strongest new mechanism evidence is lost breadth: summed distinct exposed
read IDs fell from 251 in Round 21 to 168 in Round 22, while recorded evictions
rose to 762. Only 10 of 35 finally selected IDs had appeared in an earlier state
projection, a descriptive signal that the four-path cap was too narrow.

Question: does a cumulative state containing one newest receipt-bound handle for
each of up to eight newest paths preserve useful breadth without restoring
duplicate-path anchoring?

- H37-R23 (selected): eight-path, one-handle cumulative evidence improves the
  fixed quality, validity, and model-token gates.
- H36-R23: delta-only evidence is better than a cumulative working set.
- H38-R23: a mixed early/recent path horizon is better than newest-only paths.
- H0-R23: deterministic evidence projection has no stable causal benefit.

Dual terminal envelopes and the 30-second local secret-resolution deadline remain symmetric instruments and change no model request, task, scorer, or semantic threshold.

## Fixed decision rule

Each state projection selects the eight paths with the most recent confirmed
observations. Within those paths it retains one newest distinct delivered
handle, then restores chronological order. Every handle must remain bound to a
successful model receipt. The projection labels the entries observed, never
relevant. Control receives no task state.

Both arms accept either one declared terminal submission tool call or a terminal
raw JSON object only when the same exhaustive schema and source-provenance
validator accepts it. Invalid terminal content receives at most two corrections.
All attempts count inside the unchanged 96,000 cumulative model-token cap.

Task identities, shared-prefix snapshots, branch order, three repetitions, 8K
context limit, 7K recycle boundary, 2,048 output cap, finalization reserve,
tokenizer policy, scorer, and acceptance thresholds remain unchanged. Every
Round 23 identity runs once; no within-round tuning or favorable rerun is allowed.

## Measurement mapping

- Native span and file F1 measure selected-context overlap, not repair correctness.
- Valid completion measures protocol completion, not semantic correctness.
- Receipt-bound exposure and path caps establish that the intended treatment
  reached the model; they do not prove that the model used it.
- Cumulative model input plus output tokens are the only optimized cost.
- A development pass permits untouched confirmation. It does not itself clear
  the full benchmark, larger GLM windows, other models, or other domains.
