# Identify ARE state effects from a shared pre-treatment trajectory

Status: selected successor construction; not frozen or live. Authority effect
none. Continuity is owned by `round15-continuity.json` under policy v3.

## Objective hierarchy

Enduring objective: improve reusable ARE reasoning, useful continuity, recovery,
correctness, and completed outcomes while minimizing cumulative model input plus
output tokens.

Initial GLM objective: finish GLM-5.3-flash qualification, completing the 8K
small context-window chapter before larger windows or other models.

Current milestone: clear the unchanged ContextBench acceptance contract through
frozen evidence-led rounds. Round 15 is an exposed development study and cannot
clear the benchmark. There is no SWE-bench benchmark stage in this campaign;
ContextBench's pinned repository-task provenance does not change that scope.

## Research method

objective → gap → question → competing hypotheses → selection → experiment/tasks/criteria → results → observations → reviewed decision → successor

Round 14 completed all sixteen independently sampled cells with known token
usage. Five complete pairs averaged +0.1084769 span F1 and the state arm used
107,942 fewer model tokens, but it missed the eight-pair, exact-exposure and
state-token gates. More fundamentally, every arm had an independent stochastic
pre-treatment trajectory. Task 4 differed even though its treatment arm never
recycled and never received state. Round 14 therefore cannot identify a causal
effect of ARE state.

Gap: the current runner cannot hold all pre-treatment model output, tool results,
repository mutations, delivery evidence, token receipts and recycling state
identical while varying only the first post-recycle state presentation.

Question: when control and treatment continue from the same exact first-recycle
boundary, does evidence-only ARE state improve useful native ContextBench
selection and valid completion within cumulative model input plus output tokens?

- H25-R15 (selected): a shared exact prefix followed by repeated, order-balanced
  control/state forks identifies a useful causal state effect.
- H20-R15: after the causal instrument works, a smaller receipt-bound delta may
  preserve quality with fewer model tokens than evidence-only state.
- H0-R15: deterministic state has no reliable benefit after pre-treatment model
  variance is removed; semantic interpretation or task-specific variance limits
  the result.

All hypotheses carry the enduring objective, initial GLM objective, current
milestone, exact method chain, reviewed predecessor and retained counterevidence.

## Fixed decision rule

Use GLM-5.3-flash at the 8K context limit, 7K recycle boundary, unchanged prompt,
tools, evidence-only state, native scorer and 96,000 cumulative model-token cap
per complete task trajectory. The prefix runs from the initial request through
the last completed tool exchange before the first request whose admission causes
recycling. Export the boundary before rendering or dispatching that request.

Bind the prefix task and source hashes, base and work repository state, source
snapshots, complete conversation/tool exchange, events, captures, admissions,
delivery handles, recycling checkpoint and archives, tokenizer/model receipts,
known cumulative usage, limits, provider profile and exact next step/generation.
The boundary digest must be identical for all branches. Branch writes and new
receipts must be isolated and must cite the shared boundary digest.

For each admitted prefix, run three control/state branch pairs. Use a frozen
balanced order schedule; never choose repetitions or order after seeing output.
Control omits task state. Treatment adds the unchanged evidence-only projection
exactly once to the first post-boundary request. Apart from that declared
projection and its measured token cost, the rendered request envelope and all
pre-treatment bytes must agree. Later trajectories may diverge naturally.

Only tasks reaching a valid shared first-recycle boundary test H25. Report tasks
that finish or fail before exposure as instrument-ineligible with their full
prefix token cost; do not score them as zero treatment effects or silently
replace them. A branch pair is decision-eligible only when both branches inherit
the exact boundary, treatment receives its declared presentation, control
receives none, all usage is known and both produce independently reconstructed
native results.

The development target remains paired macro span F1 gain at least +0.05, file
F1 and valid-completion non-degradation, zero false projected facts/source
credit/repository effects, and zero unknown model usage. Report prefix tokens
once as the product trajectory cost and separately disclose the extra branch
repetitions used for evaluation. A positive result must retain its direction
across repetitions and must not depend on selecting a favorable repetition.

Do not lower acceptance thresholds, change state content, tune from within-round
outputs, replace failed tasks, replay a failed branch, or claim ContextBench
clearance from this exposed study. The fixed final acceptance still requires
all 1,136 task identities and two reserved-confirmation repetitions at 8K, 10K
and 12K with the acceptance contract's three token tiers and statistical gates.
