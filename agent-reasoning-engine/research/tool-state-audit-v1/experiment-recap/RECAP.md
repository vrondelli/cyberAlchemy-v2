# ARE / GLM experiment recap

Date: 2026-09-10. Candidate research evidence, authority effect none. Prepared under `CA2-ROUTE-RESEARCH` and the [requested delegation](../DELEGATION.md). No new model/tokenizer calls, Docker execution, credentials, source fixes or commits. This is a historical evidence synthesis; the parallel tool and trace audits own current implementation findings.

The best-supported conclusion is narrower than “ARE improves reasoning”: **preserving necessary source evidence that still fits can improve the same model's completion, while successful archive mechanics, stricter workflow gates and smaller prompts do not by themselves establish useful state or correct repairs.** The earlier experiments already test parts of state usefulness. A new plan should extend those results rather than claim that state usefulness has never been tested.

The strongest positive GLM comparisons are H21's ordinary source-preservation pilot and H23's lossless envelope projection near an admission boundary. Neither establishes compressed reasoning-state usefulness under a fixed cumulative input-plus-output token budget. The latest two real-task comparisons show no repair advantage for early syntax feedback or forced construction checkpoints; the former never encountered syntax-invalid code and the latter blocked needed read recovery.

## What “state” means in this history

| Mechanism | Actual evidence | What it does not prove |
| --- | --- | --- |
| Workflow policy | Inspect/synthesize/finalize phases, stage/test/submit gates, reserved construction checkpoints, optional recovery tools | That the model has the facts needed for those actions; that the remaining actions are reachable |
| Deterministic continuity | Journal/archive identity, exact source hashes, tool-pair integrity, recovery cursors, persisted objective/workflow metadata | Correct semantic recall, use of relevant evidence, or correct repair |
| Source-body preservation | H18 shows masking loss without recycling; H21 keeps admitted original bodies; H22 checks two independently revised facts | A compact representation of hypotheses, decisions, uncertainty or reasoning state |
| Model-visible presentation | Metadata reminders, neutral/boundary cards, native submission schema; H23 removes redundant envelope metadata but preserves payload | That fewer tokens universally improves reasoning; H23 does not compress essential source content |
| Typed reasoning-state projection | Earlier real-reasoning compaction/adaptive-reuse designs and scripted lifecycle tests | A verified GLM end-task gain under equal cumulative token budgets; relevant historical live result files are absent in the inventoried run directory |

The new objective is therefore best phrased as **same-model reliability, continuity, recovery and completion versus cumulative model input + output tokens**, with full benchmark outcome retained. Request-window occupancy, call limits and output-per-call ceilings remain experimental controls, not substitutes for that cost axis. Failed calls with unknown usage must stay unknown and in the outcome denominator.

## 2. GLM motivation and single-turn fitting baseline, September 7

The [original research](../../../../research/agent-reasoning-engine/glm-context-memory-reuse-2026-09-07/README.md) proposed selective observation masking based on papers/source inspection, not a reproduced external result. Kite retrieval, GEPA prompt optimization and richer memory benchmarks were suggestions, not installed or measured GLM techniques. Its motivating repaired recycling canary passed seven patch checks but used all 12 model calls and 11 recycles, 19 reads over four paths and 29,204 input tokens. Prompt and runtime changed together, so it did not demonstrate efficiency or isolate causes. That linked canary is outside the main inventory and this recap relies on the research report's attribution.

[GLM fitting](../../../../implementation/agent-reasoning-engine/benchmarks/glm-fitting-v1/README.md) authored 48 short supplied-profile tasks: 24 train/12 development/12 held-out. Six families are lookup, declared references, synthetic conflict, synthetic continuation, JSON-field repair and abstention. Disjoint source bytes do not remove shared templates/vocabulary. Offline abstainer smoke is 4/24, zero model calls and unknown tokens. The live six-task routing pilot is 6/6, 3,386 input + 91 output tokens. The [24-task training run](../../../../implementation/agent-reasoning-engine/benchmarks/glm-fitting-v1/evidence/live-training24-8000-2026-09-07/README.md) is 24/24, 24 model/24 tokenizer calls, **23,435 input + 386 output = 23,821 model tokens**, zero recycles. Its routing six overlap the earlier pilot.

Hard window 16,384, soft 8,000, reserve 2,048, margin 256; supplied evidence, no tools, one call/task. `clear-v1` is only a label here: there is no prior history to clear. This clean ceiling result motivated harder multi-step tasks; it proves neither retrieval nor real coding recovery. The development and held-out fitting sets were not consumed by those live runs.

## 7. Reporting revisions and confounds to preserve

1. **Selected tuning success is not frozen reliability.** Working-loop's final4/4, v20's9/10 and original real-task all-pass examples follow visible failed development attempts. Frozen v20 repetition is3/8; five full qualification attempts are retained, not replaced by final36/36.
2. **Retained-candidate validation is not another model trial.** Public-validation replays, disposable containers, independent oracles and second full-test evaluation assess existing proposals. They must not double the success denominator.
3. **Schema and raw semantics overlap but differ.** Contract-rejected code may pass behavior; native-valid code may fail it. Supplemental raw-source tests preserve this distinction and do not retroactively accept original output.
4. **A terminal report may revise interpretation without new calls.** External feedback `RESULT.md` versus `FINAL-RESULT.md` separates model-quality errors from broad `run_error` grouping; reservation raw `early/delayed` keys mean reserved/baseline. Its frozen analyzer says inconclusive, while mechanism review explicitly records counterevidence/revise-hypothesis. Preserve both predicates and named outcomes.
5. **Runner/evaluator revisions are part of the treatment history.** Bounded-delivery EOF, schema-recovery handoff between stages, external ledger initialization/final-response capture, dirty-image patch export, test-name normalization and strict infrastructure-stop fixes affect comparability. None should silently overwrite old failures.
6. **Exposure is mandatory for mechanism claims.** No-recycle recovery runs,H17's confounded controls,H20/H21 ordinary masking,H23 stronger-pressure pre-delivery blocks,and feedback's zero syntax-invalid candidates answer different questions. Mechanical continuation after a recycle does not prove useful semantic state.
7. **Cumulative tokens differ from context size and calls.** H21 uses equal model calls but+5.1% measured tokenizer input. H23's316–320 saved tokens are matched individual request reductions; total episode use includes changed trajectories. Early smaller-envelope Svelte episodes have different model behavior. No identified study establishes a broad fixed-total-input+output-budget frontier over state representations.
8. **Historical source visibility is incomplete.** Early exports intentionally omit full raw request histories; some reports require now-missing private `/tmp` inputs. The final 467-trial analysis validates exported bindings, not a newly reconstructed historical wire archive. Runtime code today is not proof of what an old provider saw.
9. **Narrow models/tasks and sequential provider conditions.** Controlled tasks repeatedly reuse source/variants; later Svelte work stays within one repository. Output budgets,timeouts,paging policies and public checks change across stages. Preserve failed/unknown usage and transport interruptions; do not infer intrinsic model limits or claim provider-internal compaction is observable.
10. **Historical naming is overloaded.** `M1` in GLM finish means known-fixture qualification; `M1` in external success means first real verified repair. `H1` in feedback/reservation is package-local; it is not the older hypothesis-study H1. Package-qualified IDs prevent false lineage joins.

## 8. Evidence-backed next research direction

These are recommendations for the parent's plan, not a new execution authorization or replacement of existing product gates.

- **Start with the tool audit and exact recoverability.** The latest checkpoint counterexample is already concrete: a correction instruction asks for an action that the phase removes. Preserve one bounded path from each recoverable error to the needed tool, while distinguishing schema repair, exact edit repair, task understanding and transport failures. Evaluate source-current contract fixes offline before another live cohort.
- **Retain H21 and H23 as existing baselines with limits.** Use admission-before-masking and complete-payload envelope projection where supported. They already test source availability and near-boundary presentation; do not restart a “does preserving useful evidence matter?” study with no acknowledgement of their evidence. Do not claim H21 passed its strict all-known screen or that H23 handles source-heavy pressure.
- **Test the missing state representation question directly.** Compare complete admitted source bodies, an equal-information compact evidence view, and a typed working-state view (current objective, supported findings, rejected alternatives, unresolved questions, next required action and exact source references). Hold task,model,tools,recovery affordances and evaluator constant. Include a neutral/length control when separating presentation from added instruction is the hypothesis. Any model-built state has its construction/update tokens charged to that arm.
