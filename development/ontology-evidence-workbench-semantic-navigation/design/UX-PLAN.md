# UX Plan: Profiled Clusters, Relation Semantics, and Path

Status: candidate design; planned behavior only

## User Outcome

A reviewer should start in a small explainable area, understand what each
visible control does, identify how two nodes relate without depending on color,
move through portals and Path, and always recover the prior scene. This design
does not claim the reviewer comprehends or trusts the ontology.

## Entry Surface

- Remove the unavailable freshness instruction and retain only qualified build
  and adapter provenance plus analyzed date and authority ceiling.
- Name the artifact: `candidate-local presentation projection derived from the
  Body War ontology`.
- Initial focus enters the startup modal target. Every dismissal restores the
  declared graph-entry heading/control with visible focus.
- After dismissal, render only the owner-approved projected context home.
- Keep `Show all loaded graph` visible as an explicit escape.

## Cluster and Portal Cards

Each card presents:

1. project-owned context/cluster name and short purpose;
2. redundant category icon plus adjacent role/kind text;
3. current-projection node and connecting-relation counts;
4. exact source-backed reason the portal exists;
5. one native action with a destination-focused accessible name;
6. a reminder that the cluster is presentation scope, not ontology membership.

The core does not choose the four-versus-twelve mapping. Missing approval
blocks the Body War Home behavior. Zero-count values follow only the approved
hide/disable/retain policy and never rely on color alone.

## Relation Visual Language

- One stable color per exact `sourcePredicate`, across graph, selected edge,
  portal, Path, narrow, grayscale and forced-colors scenes.
- One stable solid/dash pattern per `presentationRelation`.
- Every edge instance retains arrow marker and text direction.
- Exact predicate label is visible in bounded scenes and accessible/actionable
  elsewhere.
- Selected relation details show source, predicate, source direction,
  projected direction when different, target, provenance and authority.
- Inert edges are absent from sequential focus. Actionable edges use one
  documented direct or roving model, visible focus, and Enter/Space behavior.

## Path

- Controls are labeled `From concept`, `To concept`, policy name, and
  `Find routes`; From and To must be distinct.
- Result region has a unique accessible name and announced state.
- Every hop uses the complete relation record plus traversal orientation.
- Comparator and route-local presentation are both admissible, but Body War
  must select one before its Path wave is executable.
- Results state that a route establishes no membership, branch, causality,
  execution, promotion, or authority.
- Activation, populated/not-found/error result, cancel, Escape, Close and focus
  restoration are separately asserted.

## Controls and Modes

- `Overview`, `Learn`, and `Deep Dive` expose exactly one selected state and a
  distinctly named owned result region. Their content purpose is project data.
- Filter and Export use an explicitly selected disclosure/dialog pattern with
  pattern-appropriate expanded/modal state, ownership and restoration.
- Path is a graph tool; Theme and keyboard help are utilities.
- Every visible control has purpose text, accessible name, state, result, error
  behavior and restoration target. Unsupported actions are absent, not dead.

## Contrast and Responsive Contract

- Named 16px enabled control text reaches 4.5:1 in every applicable state.
- Required boundaries, focus indicators, edges and markers reach 3:1.
- At 1440x1000, graph and information rail do not overlap.
- At 390x844, transient details use a focus-managed sheet; the covered canvas
  is inert and hidden from assistive navigation until dismissal.
- Reduced motion removes animation while keeping static direction/state.
- Forced colors and grayscale preserve text, patterns, system-color strokes and
  focus; icons remain redundant.

## Evidence Matrix

The implementation and re-audit must replay:

- activation/result/dismissal/restoration for modal, modes, disclosures, Path,
  Theme, search, help, portals, all-loaded escape and actionable edges;
- exact relation identity/direction/color/pattern across default, selected,
  portal, forward/reverse Path, narrow, grayscale, forced colors and reduced
  motion;
- every task/control/state/mode row in the frozen Body War baseline.

## Human Evidence Ceiling

Browser checks may prove mechanics, labels, fields, state, focus, contrast,
responsive geometry and redundant encodings. Screenshot review may compare
hierarchy, density, whitespace, collision and icon treatment. Only an
authorized human study may support comprehension, trust, workload, preference,
discoverability, meaningful mode distinction, or task success.
