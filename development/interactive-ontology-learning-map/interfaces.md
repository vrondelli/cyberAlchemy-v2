# Interfaces

## Source manifest interface

Accepts explicit source ID, owner namespace, allowed path, revision/hash, extractor selector, excerpt policy, and privacy class. Default source decision is deny.

## Snapshot interface

Exposes versioned records, relations, separately stored views, layouts, unresolved references, validation receipts, hashes, and ETags. Canonical serialization order is stable-ID order.

## Learning interface

Four equal surfaces share selection state: focus-question journey, bounded spatial graph, authored DOM hierarchy, and native relation table. Detail panels expose plain definition, source, object kind, claim/proof posture, authority state/effect, owner route, and “why linked?”.

## Accessibility interface

All spatial actions have keyboard/touch/non-drag alternatives. The general graph is not represented as an ARIA tree. Only real hierarchies may use treeview semantics. Disclosures are buttons with expanded state; reduced motion and non-color signals are mandatory.

## Boundary interface

Source adapters read owned sources; the compiler returns a projection receipt. No adapter writes source state. The L0 witness stays under `./prototype/`. A future production website may consume immutable outputs only after a separate product/architecture decision selects that host and interface.
