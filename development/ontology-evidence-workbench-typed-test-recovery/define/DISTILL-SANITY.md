# Define Distill Sanity

- Verdict: pass.
- Coherent unit: one failure-evidence capability plus a non-selecting
  compatibility decision packet. The package may make failures actionable;
  it may not choose how DOM compatibility is repaired.
- Split pressure accepted: public Task Session maintenance, Inventory repair,
  retry authorization, and product/browser execution remain separate routes.
- Recomposition: admitted failure evidence and a later owner-selected
  compatibility branch can feed one safe successor attempt, but neither this
  package nor the decision packet authorizes that attempt.
- Navigation: Design exposes both repair branches; Plan decomposes only the
  evidence capability and routes the compatibility decision separately.
