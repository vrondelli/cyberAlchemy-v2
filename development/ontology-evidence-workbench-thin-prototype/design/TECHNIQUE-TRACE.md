# Design Dispatch Technique Trace

| Technique | Applied to | Gate/evidence effect |
| --- | --- | --- |
| `sequence` | approved Define → scope extraction → selection → architecture/UX → Plan | Plan cannot consume authored-only or failed selection |
| `x_ray` | expose package/runtime/temporary-root structure | makes hidden ownership visible |
| `concrete_path_evidence` | source contracts and Design manifest | stale or missing source blocks |
| `owner_boundary_check` | development, implementation, upstream, Poker-Team, ontology, and release owners | prevents false lifecycle claims |
| `state_namespace_boundary` | writable new package versus read-only historical/source namespaces | isolates the clean lane |
| `artifact_contract_bridge` | planned witness rows to future Plan evidence | keeps Design contract separate from execution proof |
| `validation_loop` | denominator plus unchanged two-pass selection | establishes `design-validator-pass` |
| `residue_ledger` | unimplemented type/gateway/browser/teardown gaps | prevents plan-ready inflation |
| `handle_handoff` | exact Design artifact paths and result digest | Plan consumes handles rather than copied context |

Every technique changes a view, gate, evidence check, or unresolved gap.
