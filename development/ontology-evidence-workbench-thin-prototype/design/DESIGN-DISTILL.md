# Design Distill Validation

- Mode: Validate
- Target context: one local browser-testable Poker-Team OEW witness
- Proposer claim: the coherent design unit is the existing dashboard plus an
  exact data gateway and browser receipt, not a new runtime
- Balancer objections:
  - **scope inflation:** importing immutable L1 verification would recreate the
    old chain;
  - **hidden glue:** typed repair, current overlay admission, build, gateway,
    browser, receipt closure, and teardown must all have owners;
  - **meaning loss:** a static viewer cannot recompose into the trust rail,
    inspector, and receipt journey;
  - **authority drift:** browser pass may be overstated as ontology or product
    acceptance.
- Reconciliation:
  - preserve independent L1 as a later compatible lane;
  - keep one thin runtime flow but split implementation into atomic SWUs;
  - require an exact prototype claim ceiling and read-only Task Session closure;
    keep independent immutable verification in L2;
  - forbid new package/dependency roots.
- Smallest coherent design unit: build-from-owned dashboard + fail-closed exact
  evidence gateway + one bounded Poker-Team Chromium journey
- Split pressure: pass to Plan for four atomic mutation units; Design itself
  remains one recomposable architecture
- Recomposition proof: the unit closes the research-identified browser witness
  gap while preserving existing upstream, adapter, ontology, and eventual L1
  owners
- Deferred: generalized runtime, independent immutable L1 ceremony, full
  accessibility/responsive matrix, editing, release, and production
- Premortem: most likely failure is adding build/browser plumbing while focused
  typed tests remain vacuous; guardrail is explicit test-path discovery before
  Vite and serving
- Verdict: pass
