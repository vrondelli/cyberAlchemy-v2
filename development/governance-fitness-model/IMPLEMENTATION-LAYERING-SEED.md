# Implementation Layering Seed

This is a Design companion. It is not an implementation plan, Work Pack, or
Task Session route.

## L0 — Two isolated structural witnesses

Decision: can posture effect and rule meaning remain separate while both are
non-authoritative?

- SCU-A: materialize one candidate posture contract, one pure resolver contract,
  one adapter-result contract, and a complete surface inventory fixture.
- SCU-B: materialize the durable governance ontology package with one C10
  Governance Rule, inherited A6 and harm Evidence, one friction metric contract,
  one pending Governance Assessment, one Governance Policy, and one Product
  Binding. Constitution and Validator bindings remain absent unless separately
  adopted.
- No root hook, CI, Make, tool, submodule, product ontology, authority, or
  runtime integration.

Promotion evidence: structural validation and negative fixtures only.

## L1 — Isolated observe-only harness

Decision: can one detector's native failure be preserved while the adapter has
no work-facing effect and performs no protected write?

- Use one disposable fixture repository.
- Compare working tree and Git index before and after.
- Prohibit network and external effects.
- Do not attach the adapter to the real repository.

Promotion evidence: GF-W01 through GF-W04 and two deterministic runs.

## L2 — Parent repository pilot

Decision: can every inventoried parent-owned governance surface become advisory
without hiding product, safety, publication, or deployment failures?

- One surface at a time, each with a separate adapter and rollback.
- Preserve existing CI job names when external required checks depend on them.
- Do not include independent Git roots without their owner decision.

Promotion evidence: exact surface coverage, no-effect receipts, and external
required-status inspection.

## L3 — Fitness observation pilot

Decision: can the seven-refresh sequence become evidence against one stable rule
identity rather than repeated lifecycle epochs?

- Materialize a typed local event corpus.
- Run the first `GovernanceAssessment`.
- Route one non-binding recommendation to the rule owner.
- Keep Saturn as the future owner of repeated observation/tuning.

Promotion evidence: complete metric contract, countermetric, privacy boundary,
and owner review of the recommendation.

## L4 — Optional enforcement project

Decision: does evidence justify any rule becoming effectful again, on which
surface, and under whose authority?

This is deliberately outside the current design. It requires a new Define,
Design, Plan, exact owner decision, surface-specific negative controls,
rollback, friction budget, and independent validation. It must not be activated
by changing one posture string.

## Deferred complexity

- per-rule posture overrides;
- a policy DSL;
- signed or remote posture distribution;
- dashboards and portfolio aggregation;
- automatic expiry or restoration;
- generic multi-repository orchestration;
- a new product-side Governance Fitness capability node;
- automatic pruning or Saturn ingestion.

## Next route

Owner review, then a proper Invoke Define/Design admission cycle for the two L0
SCUs. Plan and Task Session remain unavailable.
