# Open questions

This is a local prototype, with no product approval or operational authority.

- Q1: Which exact gold dataset version, license, provenance and access policy should replace the synthetic materialization fixture?
- Q2: Does contribution grant access, credits, royalties, or a combination? Public metadata is the proposed default; protected data remains policy controlled.
- Q3: Which participant inference interface should the first ARE connector support, and what latency, token and tool budgets apply?
- Q4: Which current KEP implementation and key-custody model will own signed offers, delivery and acknowledgements? This prototype only exercises the exchange contract using local fixtures.
- Q5: Which AlchLang runtime profile should own executable world recipes? The initial recipe is a local carrier prototype, not an admitted language extension.
- Q6: What tests, voting eligibility, review quorum and owner decision are required before a capability becomes hostable? A vote alone must not deploy code.
- Q7: Which workload isolation, metering, availability and provider attestation requirements apply to community hosting?
- Q8: Start with Tailscale, own the mesh control plane with Headscale, or invest in native P2P after measuring connectivity? Deployment remains separately scoped.
- Q9: How should competing world histories, attribution disputes and revisions of contributed knowledge be resolved?
- Q10: Which simulation outcomes establish usefulness outside the game? Passing a simulation is evidence about that simulation only.
