## Open the desktop

The assistant's current SSH process forwards local `127.0.0.1:16080` to the
VM's loopback-only browser gateway. Open **Chrome or Edge outside the Codex
browser panel** and paste:

```text
http://127.0.0.1:16080/vnc.html?autoconnect=true&resize=scale
```

Connection evidence: HTTP 200 from Linux and native Windows PowerShell;
WebSocket HTTP 101 plus an RFB/VNC handshake through the tunnel. The user
reported a desktop-link error. The Codex browser opener queued its request,
and Windows computer-use initialization failed with a workspace-URI error;
neither proves that the external browser displayed the desktop. External
browser confirmation remains pending.


Or run from Windows PowerShell:

```powershell
wsl.exe -d Ubuntu -- bash /home/vrondelli/projects/domainspec-core/cyberAlchemy-v2/development/robot-world-kep/unity-ui/cloud-setup/connect-vast-50043105.sh
```

Leave that terminal running. Ctrl+C closes the tunnel and leaves the VM running.
If the port is occupied, use the existing tunnel; do not kill an unidentified
listener. `--check` performs a remote read-only service/editor check without
opening another tunnel. If Vast changes the public IP or mapped port, inspect
the console and update the exact endpoint before reconnecting.
