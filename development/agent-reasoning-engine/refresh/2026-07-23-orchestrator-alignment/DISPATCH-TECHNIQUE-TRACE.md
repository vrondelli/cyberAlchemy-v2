# Dispatch technique trace — orchestrator alignment refresh

| Technique | Activation trigger | Artifact / gate effect | Validation expectation |
|---|---|---|---|
| `sequence` | Evidence status must be resolved before deltas and routing. | Orders Inventory lookup → source/target selection → signal normalization → proposal → validation. | No proposal is emitted before witness and external contract postures are classified. |
| `concrete_path_evidence` | Alignment claims span two repository roots and several lifecycle states. | Pins exact files, selectors, Git SHAs and SHA-256 digests in the context pack. | Every material delta maps to a live source path and RefreshSignal. |
| `owner_boundary_check` | Invoke, Craft, Inventory, ACI and target implementation have different authorities. | Splits proposed changes by owner and prevents direct cross-owner mutation. | Only new files under this refresh package change. |
| `state_namespace_boundary` | CAV2 private authority, orchestrator source, generated Craft/Inventory views and implementation evidence must not collapse. | Names read-only and proposal-only namespaces in `DISPATCH.json`. | No private source is copied into public Arcanum; generated views retain their owners. |
| `artifact_contract_bridge` | A terminal L0 receipt and accepted ACI W0 decision must update planning without inflating either claim. | Converts evidence into status correction plus a typed binding blocker. | L0 remains bounded; ACI remains non-runtime and non-binding. |
| `residue_ledger` | Bus/ACP/APT maturity and anti-bias efficacy remain unresolved. | Preserves external maturity, integration, durability and efficacy residue. | No open target-lifecycle gap is silently closed. |
| `recomposition_proof` | The tempting unit is “integrate both systems,” which is too large. | Selects one documentation-only `ACI-REASONING-BINDING` contract as the smallest post-promotion unit. | The unit maps ownership and records, then recomposes into SWU-002/003/006 without implementing them. |
| `validation_loop` | The refresh contains Markdown, JSON, a dispatch route and exact target invariants. | Gates schema validation, JSON parsing, source hashes, target invariance, links and whitespace. | All checks must pass before the owner receipt reports `pass`. |
| `execution_receipt_handoff` | Later apply and design routes need a bounded authoring receipt. | Emits `OWNER-RECEIPT.json`; it authorizes no mutation. | Receipt names artifacts, validations, blockers, residue and next route. |

## Skipped techniques and capabilities

- Fan-out, dialectic and tournament: skipped because this run classifies
  already-frozen artifact states and performs no independent semantic
  adjudication.
- Full Distill execution: skipped after the baseline exposed a single closed
  optimization point—status correction plus one future binding contract.
  Recursive reduction would either drop owner boundaries or reintroduce the
  full integration bundle. The `recomposition_proof` technique records the
  required Distill-style closure check.
- Decision Gate: skipped because no binding owner choice is made in this
  proposal. The unresolved choice is preserved as a target-lifecycle blocker.
- Runtime subagents: `none`; there is one proposal-only authoring owner, no
  delegated mutation, and no independently executable work lane.
