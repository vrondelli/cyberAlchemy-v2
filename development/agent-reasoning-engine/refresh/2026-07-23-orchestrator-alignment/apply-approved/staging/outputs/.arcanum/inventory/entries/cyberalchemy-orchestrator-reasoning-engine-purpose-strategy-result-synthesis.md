## Accepted result

The repository's explicit purpose is not to create a reasoning engine. Its
stated purpose is governed multi-agent orchestration for decision hygiene:
opposed perspectives, independence, aggregation, human authorization,
provenance, and audit.

At the frozen commit, the strongest current classification is an
**agent-workflow governance framework plus a read-oriented orchestration control
plane**, accompanied by a narrow agent-selection utility and an experimental
publication bus. The repository does not own a deployed confirmation-to-chain
execution runtime; separate human or agent sessions may still execute workflows
outside that code path.

The broader build-from-owned direction is an orchestration and
epistemic-governance substrate that could support governed collective reasoning.
The claim graph, semantic inference/revision loop, knowledge-provenance runtime,
and execution runtime remain proposed or unbuilt.

## Classification boundary

The accepted minimum witness for a reasoning engine is machine-readable
epistemic input, a repository-owned executable object-level inference or
evaluation procedure, and a traceably derived semantic output. That procedure
may invoke an external model, but persona selection or delegating the target
reasoning to independently prompted agents does not qualify by itself.

The current reasoning-engine claim is therefore a typed non-vacuity KILL: no
repository-owned path consumes semantic premises, claims, rules, or evidence and
derives a substantive conclusion through repository-defined semantics. Current
code derives ledger metadata, selects agents, and validates publication and
provenance. The vague `hybrid reasoning engine` label is also rejected as
definitional category inflation.
