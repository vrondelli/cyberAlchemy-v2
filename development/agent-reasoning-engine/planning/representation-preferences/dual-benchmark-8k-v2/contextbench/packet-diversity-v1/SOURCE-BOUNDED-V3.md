# Bounded source restoration integration

`prepare-bounded-v3.mjs` and `source-closure-bounded-v3.mjs` are additive descendants of the corresponding preparation/source-closure modules. Ranking, packet creation, confirmed delivery binding, Git blob verification and native source projection remain unchanged. The only integration change is admission of source restoration writes through the caller's shared stage guard. Original modules and frozen artifacts remain untouched.

`restoreVerifiedBase` and `restoreRequestCompleteBase` now require `stage_guard` and `stage_root` alongside the existing storage guard and donor/directory inputs. The stage root must already exist and have one `createStageOutputGuard({root: stage_root})` instance shared across all donors and later stage writers. Each source file and `.packet-base-manifest.json` reserves its full encoded bytes before any parent-directory creation or file write. Missing directories are included by the guard's prospective allocation/entry accounting; the restorer does not create its base directory outside a lease. All Git blobs are verified before output starts, and source writes remain exclusive.

Optional `write_file`/`make_directory` injection supports synthetic failure tests; production defaults use the existing synchronous filesystem operations. Success completes each lease. Failure cancels/settles the lease against the actual remaining footprint, retains partial files, and rethrows the original error with the reservation receipt and partial-source directory. A settlement failure is attached separately rather than masking the original write error. Returned manifest identity and native full-delivery projection remain compatible.

Six targeted synthetic tests pass: every source/directory/manifest effect has prior admission; full-stage denial causes no source output effects; partial file and manifest failures settle their leases while retaining bytes; multiple donors share one guard; mismatched stage roots reject; and native complete projection restores a terminal-only file without changing prefix candidates. Git repositories and source receipts are synthetic local temporary fixtures. No actual retained repository, gold/reference file, provider, tokenizer, download or network call was used.

## Caller integration requirements and open questions

The future bounded preflight must create its stage root under an admitted launch boundary, construct one stage guard, and pass it plus the exact root to each restoration. Its metadata/tokenizer journals and native request/recycler/ledger writes are not yet wired; evaluator subprocess writes also remain outstanding. This module therefore does not establish an end-to-end stage cap. Caller code must retain failures and fixed task slots rather than deleting partial evidence or silently replacing a donor. Independent exact-source review remains pending; see [BOUNDED-EXECUTION-PLAN.md](BOUNDED-EXECUTION-PLAN.md).
