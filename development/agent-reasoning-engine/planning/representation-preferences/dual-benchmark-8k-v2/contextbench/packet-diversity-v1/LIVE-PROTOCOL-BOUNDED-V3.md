Each model request uses actual native admission at most8,000 tokens with2,048 reserved output. Preserve native stricter recycle threshold. Change only validated candidate ordering; retain the same archived evidence, other messages, source projection, provider profile and prefix receipts within each pair. The run wrapper verifies all source bindings and preparation hashes before dispatch; shared storage/provider/unknown/lifecycle/persistence failures stop future work and retain all slot outcomes.

## Bounded storage amendment

This protocol explicitly adopts [BOUNDED-EXECUTION-PLAN.md](BOUNDED-EXECUTION-PLAN.md) for this successor only. Preparation, generation and evaluator stages each enforce32MiB aggregate output, with24MiB ordinary output and8MiB final-result reserve. Shared synchronous leases cover native transport/recycler writes, timing, source restoration and both generation workers. Existing frozen archives and Git caches remain read-only. The evaluator must materialize only exact gold-plus-prediction blobs through the same stage budget, run unchanged native metrics in a read-only no-network sandbox, and never create Git worktrees or download parser artifacts. Evaluator-only reference information cannot enter candidate generation.

A storage rejection after a model response preserves received token usage before any fallible observer/persistence hook. A receipt proving a pre-HTTP guard rejection records zero model spend; missing or contradictory dispatch evidence retains its8K reservation. Failure paths must durably retain all16 slots through final reserved capacity. Actual dispatch rechecks host/stage state after secret resolution. Immutable previous preparations, freezes and failures remain evidence.

This operational amendment changes no hypothesis, candidate ordering, task selection, token ceiling, scoring metric or scientific threshold. Offline tests and preparation cannot be called benchmark success. Independent review of the exact bounded implementation precedes model dispatch.
