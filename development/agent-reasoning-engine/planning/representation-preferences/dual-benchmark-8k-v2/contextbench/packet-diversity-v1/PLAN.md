## Hypothesis and precise intervention

H1: marginal coverage of public-task lexical terms and non-overlapping pinned-base source spans preserves more useful delivered evidence in the same packet limits, improving final native selection without a file-quality regression. H0: lexical diversity favors distractors or displaces relevant observations, leaving offered coverage/selection unchanged or worse. These hypotheses concern the component, not discovery, general reasoning or15% campaign savings.

`ranking.mjs` computes a deterministic full permutation of validated candidates. At each position its descending score is: predecessor preferred-read flag, uncovered task-term count, presence of new source lines, fraction of candidate lines not yet covered, total task-term count, previously unseen path, base span width, receipt recency. Exact ties use codepoint path then read identity. Coverage is isolated by path and base hash. It neither manufactures reads nor merges source fragments. The lexical tokenizer is the existing frozen featureWords function. No task IDs, benchmark gold, observed scores or task-specific exceptions enter the algorithm.

The versioned terminal module retains the predecessor's projection, deduplication, renderer, handle schema, byte/token fitting and receipt-bound native export. Its default legacy mode reproduces predecessor model bytes and bindings. The treatment explicitly opts into the new ranker. Private ranking audit is excluded from model context. Original frozen implementation and completed result files remain unchanged.
