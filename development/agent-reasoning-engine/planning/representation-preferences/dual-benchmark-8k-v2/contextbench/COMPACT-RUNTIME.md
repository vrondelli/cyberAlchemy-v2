## Implementation boundary

The shared renderer in compact-prompt.mjs applies the reviewed lossless search encoding before native token measurement, request capture and dispatch. It preserves assistant messages, including retained reasoning, and all non-search tool payload strings. It adds the complete paid guide only when an encoded search result appears. Already encoded results are validated and re-encoded canonically; rendering is idempotent. Invalid search JSON, tool identity conflicts and oversized requests fail closed. No schema, source text, tool arguments or source observation is removed.

The additive minimal-repair-compact.mjs uses the unchanged phase budgets, history selection, repository tools and native driver. Only rendering and evidence bindings change. compact-evidence-join.mjs and compact-terminal-export.mjs retain the original join and native projection/export checks, selecting the reviewed receipt-first compact delivery reader. The wire hash is checked before decoding; expanded payloads never receive fabricated provider receipts.

The original runtime files and all reviewed results stay unchanged. The frozen production runner still selects the original arms. This prototype is not yet wired into that runner. The current ARE and independent-investigation arms still require explicit additive integration before a common-codec comparison can run.

## Offline integration evidence

Five tests in compact-runtime.test.mjs exercise the actual GLM wire adapter, private transport registration, request ledger, native recycler, repository tools, edit validation and native source export. Only HTTP responses and token counts are scripted in memory; there are no sockets or provider calls.

The positive trajectory searches twenty observations, delivers the encoded result with receipt-bound retained reasoning, performs a real edit, retrieves base evidence and exports an explicit terminal selection. Five synthetic model receipts reconcile to 5,150 model tokens. Tokenizer and model message/tool bytes match exactly. The follow-up includes the seven-token reasoning reservation.

Negative trajectories demonstrate that the same raw result exceeds native admission, failed model delivery receives no source credit, and altered retained reasoning fails before the next tokenizer/model request. Rendering also reproduces the previously reviewed raw-to-encoded prompt pair exactly and is idempotent.

These tests do not measure GLM comprehension, live runtime fit, quality or real task savings.
