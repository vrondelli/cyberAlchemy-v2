# Independent phase runtime candidate

Additive offline component; no provider admission. Implements planner structural validation and sequential phase admission from [the contract](INDEPENDENT-INVESTIGATION-CONTRACT.md). Original benchmark objectives remain unchanged. Open questions below own remaining implementation work.

`validateInvestigationPlan` accepts a bounded JSON string with exactly three questions and investigation descriptions, assigns q1/q2/q3 and rejects extra fields, blank/oversized text, duplicate normalized questions and common source-path/task-ID patterns. It cannot prove semantic grounding, detect every possible filename or guarantee distinct hypotheses. Planner input isolation and prompt policy must enforce the remaining contract. The lexical rejection is conservative and must be evaluated before launch.

`createInvestigationPhases` consumes the same append-only receipt array as the transport; it never filters or renumbers that array. It reuses existing cumulative token admission for both the complete arm and the current phase. It enforces 8K request reservations, phase token/call caps and the shared96K/96-call ceiling. Phases advance in fixed order; unused budget is not transferred. Phase completion is a caller assertion: this component does not validate an investigator finding or join result. The episode adapter must validate these before advancing.

A request must reserve before HTTP dispatch, then settle exactly one matching successful model receipt. Provider failures, unknown usage, mismatched receipts, over-reservation usage or persistence failure stop later dispatch. Known received usage remains visible even on failure. Missing receipts retain the pending reservation. Each unmatched unknown model receipt retains an 8K reserve; one matching receipt may consume the pending reservation, never multiple attempts. Known token fields remain counted even when dispatch metadata contradicts them. Partial known usage reduces only its own reservation, and missing receipts keep a separate unresolved attempt. The conservative total is not accepted known spend. Malformed receipt items and receipt-prefix corruption permanently stop this controller, even if the original bytes are restored. Synchronous persistence must use the existing guarded writer. The provider's durable attempt ledger remains authoritative for HTTP attempts; this state is additional phase metadata, not a replacement ledger.

Nine offline test groups cover cross-phase cumulative budgets and global receipt indexes, all96K allocation, exact8K reservations, call limits, tokenizer failure, unknown model usage, receipt drift, unreserved calls, missing receipts, wrong request binding, persistence failure, actual usage overruns and invalid planner structures. No model call occurred. These tests do not prove benchmark quality, actual transport integration or final evidence joining.

## Open questions

Restart/replay is deliberately unsupported: creation requires an empty arm receipt list. The live adapter must stop on process interruption and preserve provider ledger costs. Planner/branch generation, protocol-valid isolated histories, cross-branch evidence joining, minimal-history baseline, exact prompt schemas, real tokenizer qualification and source freeze remain pending. Before live admission, integrate reserve/settle at the actual dispatch boundary and test failure races with native transport. The current component alone cannot admit a benchmark run.
