# Executable independent episode candidate

Offline-tested orchestration of planner, three isolated investigations and terminal join. Parent [contract](INDEPENDENT-INVESTIGATION-CONTRACT.md); no provider dispatch admission. Open questions below own remaining integration.

`runIndependentEpisode` composes the reviewed phase controller, planner validator, branch-local evidence binder, finding validator and branch-aware native exporter. One receipt list and phase controller span all phases. Each investigation starts with only the original task, its question and source-use policy. It cannot see other branches' histories or provisional findings. Tool-call IDs may repeat across branches; native branch binding preserves that separation.

Planner output is strict bounded JSON. Investigators call source tools and finish with exactly one `submit_investigation`; mixed source/final batches fail. Source replies receive the unchanged native observation handles before entering the next request. Findings are checked against that branch's delivered evidence. Phase boundaries determine global receipt index assignments, eliminating caller-chosen receipt slices within this orchestrator. The final join receives original objective, provisional findings and the common terminal packet; only explicitly submitted handles enter native export.

The driver contract currently has separate `prepare` and `dispatch`. Preparation may measure tokens but must return the identical prompt, output cap, wire profile, request digest and measured input upper bound. The phase controller reserves before dispatch. The returned model receipt must match the exact prepared wire body; there is one settled attempt. The driver must use native transport, credential handling, request measurement, ledger and failure receipts when integrated. The current scripted driver is a test fixture only.

Persistence is synchronous and must be connected to the existing guarded durable writer. Every phase state, request capture, response capture, source result, finding and final packet is persisted. Provider/persistence/validation failure stops subsequent phases and returns retained receipts and known/unknown accounting; no implicit retry. This implementation has no resume and no silent context trimming. A request that cannot fit8K fails before model dispatch. A reviewed protocol-valid bounded history strategy remains necessary if actual branch trajectories exceed that window.

Three end-to-end offline groups cover an eight-call successful fixture, isolated branch histories, shared cumulative cost, exact receipt index assignments, colliding source tool IDs, native final export, invalid planner output, oversized-window admission, provider unknown usage and persistence failure. All source data and model replies are synthetic; the measured960fixture tokens are scripted test values, not real efficiency evidence. No benchmark-quality or provider-token claim follows.
