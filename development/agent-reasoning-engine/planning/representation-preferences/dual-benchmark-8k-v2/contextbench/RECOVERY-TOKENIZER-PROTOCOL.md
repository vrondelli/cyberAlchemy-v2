# Prospective matched recovery input measurement

This is an input-size diagnostic, not a benchmark success claim. Enduring objective: reusable ARE reasoning-state retention, perfect quality and at least 15% cumulative model-token reduction separately on ContextBench and LongMemEval, beginning with GLM-5.3-flash at 8K. Research method: objective → gap → question → competing hypotheses → selected experiment/tasks/criteria → evidence → observation → reviewed decision → successor.

## Question and hypotheses

Does a demand-driven entry reduce complete-request input tokens compared with a corrected, populated eager catalog on the same previously observed request boundaries? H1 predicts a strict aggregate reduction. H0 predicts no reduction in a complete, valid fixed comparison. Missing measurements, construction/admission failures or infrastructure errors are inconclusive, not scientific counterevidence. Neither predicts measured quality from this diagnostic. The alternative explanation that opening turns or reduced visibility erase savings remains unresolved until full trajectories.

## Fixed cohort and projection

Use all 97 actual acknowledged recovery presentations across the four treatment histories in RECOVERY-VISIBILITY.json. Retain the 18 pre-evidence boundaries. The other 79 must use populated eager snapshots once evidence is available. No selecting favorable boundaries, substituting histories, retries, gold/reference access or model generation.

At each boundary bind the original prompt to its dispatched receipt; retain only earlier captures and receipts for archive construction. Preserve the task, source/tool results, history and every unrelated schema exactly. Replace only the exact acknowledged recovery introduction, catalog and recovery schemas. Eager uses the repaired freshness controller, original recovery tools and receipt-bound freshness notice. Demand uses one `open_recovery` tool and its entry message, under the explicit counterfactual assumption that it has not been opened. Reject any history already containing recovery calls. Snapshot timing, opening decisions and new model responses are not simulated.

## Measurement and accounting

Measure the full `{model, messages, tools}` with the existing GLM tokenizer endpoint. Page construction also uses the actual tokenizer via the same bounded measurer, respecting its existing 256-token/1024-byte page bound. Every request attempt is durably recorded by digest, dispatch posture, status and token count. Cache identical tokenizer bodies; count actual HTTP calls separately from measurement invocations. No chat endpoint is called. Maximum 512 tokenizer calls, two workers, one attempt per body, 30-second request timeout, 15-minute overall deadline. Secret lookup must be bounded to at most 30 seconds; after the deadline the stage may take up to that bound to drain lookup, and no late HTTP dispatch is permitted. Abort further work on source drift, malformed responses, provider errors or storage failure; await all started work and preserve partial rows/calls. No automatic restart.

Use a fresh 32 MiB stage with 24 MiB ordinary and 8 MiB final reserve, existing D:1 GiB and guest8 GiB guards; C: excluded. Do not duplicate source prompts into output: immutable source hashes plus exact projection code reconstruct each measured input. Retain failed attempts and prior scientific counterevidence.

## Predeclared diagnostic criteria

All 97 pairs and all four histories must complete with known tokenizer responses and unchanged sources. H1 receives input-size support only if aggregate demand input is strictly lower than eager input; report each history and every boundary, including regressions. Report the fraction below an illustrative 8K total using the original output reservation, but this is not live admission: provider tokenizer counts alone do not prove retained-reasoning bounds. The diagnostic does not apply the campaign's 15% threshold to input alone or claim saved model expenditure. Generation/output/opening costs are unmeasured.

Native hypotheses and experiment must validate before dispatch. Independent code/projection review and exact source freeze precede measurement. After measurement, independent reconciliation and native observation/decision precede any successor. A full-trajectory experiment still needs compact final persistence, live integration, reviewed fixed quality/cost criteria and untouched confirmation for broader claims.

## Open questions

Will an extra opening turn consume the input saving? Will the model open or refresh appropriately? Can improved availability improve discovery and final span/file quality? Do measured requests meet the live retained-reasoning admission policy? These are explicitly outside this input-only diagnostic and cannot be answered by a positive size result.
