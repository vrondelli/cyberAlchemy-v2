## Required precision before a ContextBench freeze

1. **Choose component diagnostic or full trajectory explicitly.** The diagram currently shows a matched live comparison while the text permits an archived-boundary probe. Either is legitimate, but D03 must identify which is being run. A shared archived boundary must hold delivered archive, task, prior state, model/profile, budgets, answer/selection policy and native scorer fixed, changing only packet construction. Use the same predeclared boundaries for both arms and preserve every assigned slot. A full independent-trajectory rerun holds discovery policy fixed, not necessarily the realized source reads; do not describe those stochastic prefixes as identical exposure.
2. **Separate diagnostic success from the campaign gate.** A packet probe may establish better offered coverage or model selection on already delivered evidence. It cannot establish whole-trajectory15% savings, improved source discovery, code repair, general memory retention or benchmark perfection. Requiring perfect selection on every archived boundary would also be an unfair component gate where the archive itself cannot contain a perfect answer. Declare component criteria before outputs; keep the full-trajectory perfect-treatment/valid-completion/15% objective unchanged for later qualification.
3. **Account for shared-prefix reuse honestly.** Report actual physical probe spend and, if providing a logical full-task comparison, include the same historical prefix in both logical arms while counting it once physically. Terminal-call saving is not full-task saving. Do not combine a new probe's quality with the previous study's12.64% saving as though they came from one paired experiment. Any eventual claim needs the whole relevant trajectory and failure costs under a single frozen comparison.
4. **Freeze a general algorithm, not task-specific adjustments.** “Task-agnostic” should mean the same algorithm and fixed parameters across tasks; public task text may be an input if declared. Specify exact source-only features, ordering/tie-breaks, deduplication, fit limits, omissions and provenance checks. Preserve packet maximums and full-request8K admission in both arms. Gold-derived witness IDs, source paths/spans, per-task tuning or outcome-selected boundaries must never enter the generator or ranking. Aggregate evaluator evidence can motivate a general question, but must not become a location hint.
5. **Keep the counterpart stable.** Do not simultaneously change discovery, retention, tool availability, output allocation, terminal correction or stopping while claiming the packet caused a difference. A later full-trajectory combination needs its own freeze and accounting. Report all six native span/file metrics and completion, not only the metric that improves.

These are precise freeze obligations, not reasons to block source-only prototyping or demand new user permission. The plan already states the main limitations; the experiment record must make them executable.

## LongMemEval comparison and fair success gate

The full-S branch correctly retains four fixed reserved question IDs, pinned variant identity, nested-label stripping, actual target-tokenizer qualification and a common final answer policy. Original history strictly above8,000 tokens is a source-length prerequisite; cumulative ingestion/answer/judge tokens are a separate cost measurement. Neither oracle histories nor byte counts substitute for genuine full histories. Preserve an ineligible task's gate failure instead of choosing a replacement based on outcomes.

Chronological compact-note ingestion versus deterministic archived-source retrieval is an end-to-end memory-architecture comparison. Query-aware retrieval and question-unaware ingestion intentionally have different phase access. Equal source availability and final answer policy are necessary, but do not imply identical model-visible evidence or isolate a compression effect. The adapter review documents this distinction and the need to count full ingestion rather than treat it as free setup.

The planned success gate is fair: **all eight answer slots valid/completed/accounted; treatment four-for-four native-correct; at least15% complete model-token saving; nonregression reported separately**. Control does not have to be perfect. This matches the completed ContextBench study's treatment-perfection convention and avoids rejecting real improvements merely because control errs. Earlier broad wording in PLAN about every evaluated outcome must not override the explicit counterpart distinction in the new freeze.

Acquisition success alone is not model-quality evidence. Reviewed streaming extraction, complete file/hash/ID verification, equal-policy adapter compatibility, isolated references, exact chunk/actual-request admission and complete judge reservations precede generation. Prior scope-policy diagnostic accuracy and earlier oracle savings cannot be joined into a full-S result.
