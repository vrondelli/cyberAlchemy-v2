# Full-S source adapter implementation

Status: bounded offline implementation following [ADAPTER-REVIEW.md](ADAPTER-REVIEW.md). Twelve synthetic tests pass. This task loaded no acquired S dataset, reference answer, provider credential or outcome and made no tokenizer, generation or network calls. Synthetic meter results are test inputs, not measurements of the real cohort. No source package, generation budget or execution freeze is claimed ready.

## Source binding and fixed cohort

[adapter.mjs](adapter.mjs) exports `loadSourceManifest(manifest)`. There is no default dataset path or old development-row fallback. The manifest must declare schema `longmemeval-full-s-source-manifest/v1`, variant `longmemeval_s_cleaned.json`, the pinned revision/SHA, package directory, exact `acquisition.json` SHA and four row bindings in this order: `09ba9854_abs`, `06db6396`, `cc06de0d`, `54026fce`.

Each row binding names `source-<question_id>.json`, its raw-file SHA-256, the SHA-256 of the question's UTF-8 text and the exact question date. The caller must obtain those question/date identity bindings from the reserved **source-only** oracle metadata and independently verify variant compatibility; the loader does not read an oracle or evaluator file implicitly. The acquisition receipt must verify the pinned full-object SHA/size/revision, 500 records, exactly four selected rows and no evaluator-reference output. Files must be regular nonsymlink files within the explicit package, with bounded byte size. Row and acquisition hash drift fails.

Rows must have exactly the six whitelisted source fields; messages must have exactly role/content. Extra gold annotations, unsupported roles, missing sessions, date-format/cardinality errors fail; nonmonotonic dates preserve exact original positional order. `flattenHistory` emits stable positional `sN-mN` aliases over every original dated turn without imposing the old 14,000-character partition threshold. The loader returns bound source/history digests and explicitly leaves tokenizer qualification pending.

## Comparison and projection

Both answers use exactly `ANSWER_SYSTEM + ' ' + SCOPE_POLICY`. Control receives its final plain notes; treatment receives selected archived turns. The question and date are identical. Control ingestion reuses the compact-note instructions with only the misleading “next chronological conversation chunk” phrase replaced locally by “next conversation chunk in original source order (dates remain attached)”, carries prior notes and never receives the future question. This is the declared sequential-memory versus archive-retrieval architecture comparison, not equal model-visible evidence or lossless compression.

`project(row)` reproduces the original user-first, question-lexical overlap, source-position-tie ranking. It greedily selects whole turns within 10,000 JavaScript string characters and restores original source order. Character limits are labeled as UTF-16 string length, not byte or token counts. Long individual turns do not cause an unrelated partition failure: a turn exceeding the projection limit is omitted whole and recorded. Archive/projection digests, original omissions, priority order and user-turn coverage remain explicit.

`fitProjection(row, meter)` is the separately declared deterministic fit step from the review. It measures the complete answer request; if unfit, it removes the lowest-priority selected whole turn, restores original source order and measures again. Every removal and measurement is recorded. It neither changes ranking nor introduces new evidence. If even the empty-evidence framing fails admission, it returns a blocked result; it does not shorten the question, policy or individual turn.

## Actual-wire admission and planning

`wire(messages, outputCap)` builds the declared GLM payload, including shared model/profile and output reservation. The injected meter must measure this complete request and return `{input_tokens, wire_sha256}` bound to the exact provider canonical serialization; use the exported `sha(request)` for that digest. No real tokenizer implementation is supplied or called by this package. `admitActualWire` rejects an unbound measurement and returns admission only when actual input is at most 6,976 and actual input plus the complete 384/1,024 output reservation is at most 8,000. It grants no dispatch effect. A later runner must measure each actual carried-note request immediately before sending this exact unchanged wire payload and verify provider usage against its reservation.

`planIngestion` proposes original-source-order **whole-turn** chunks using a 16,000 serialized UTF-16-character heuristic. Oversized single turns remain whole. It measures each proposed complete request once; a rejected multi-turn chunk splits deterministically at its midpoint, then measures each child independently, left before right. No token monotonicity is assumed, and no character estimate admits a request. This requires one measurement per accepted initial proposal plus two per binary split, instead of measuring every growing turn prefix. The first chunk has no carry reservation; later chunks reserve 384 tokens above their empty-note prompt measurements. That addition is a planning estimate, not a proof about future notes. An unfit single turn blocks the task rather than being silently truncated, fragmented, dropped or retried with a looser rule. On success, the concatenated chunks' archive digest must exactly equal the complete flattened history. Actual notes may still require a blocked dispatch if the fresh complete request does not fit; a runner must not silently change frozen chunk boundaries.

`planConfirmation` retains all four tasks in fixed AB/BA order, two concurrent pairs maximum, one repetition and eight planned answer slots. It separately measures history-only original source length and requires **strictly more than 8,000** input tokens for every task. That length includes the declared history-only message framing and excludes the answer reservation; cumulative trajectory spend is a different metric.

For each successfully planned chunk count `n`, generation reservation is `7,360 × n + 16,000`; the separate proposed two-arm judge reservation is 16,000, giving `7,360 × n + 32,000` total. Missing/failed chunk planning yields a null generation ceiling rather than substituting the old oracle cap. Original-history qualification, treatment admission and control-answer carry planning all contribute to the plan's admission flag. Even an admitted plan is explicitly **not frozen**, and actual judge prompt admission remains pending. The result reports meter invocation count; tokenizer work and deterministic CPU work are not silently treated as free or as generation-token savings.

`createTokenizerSession(meter, {max_calls, timeout_ms})` supplies a shared global bound. Prospective defaults are 256 dispatched tokenizer calls and 900,000 ms for the whole session, not per request. `planConfirmation(rows, meter, {tokenizer_limits, proposal_characters})` creates one session covering all four source-length measurements, chunk proposals/splits, projection fit attempts and control-answer measurements. `planIngestion` and `fitProjection` accept the same `tokenizer_limits` when used independently. To share a bound across separate API calls, pass the same exported session; wrapping the same raw meter separately creates separate budgets and is not a global run bound. No retry occurs. Exhaustion or meter failure throws, carries `error.tokenizer_budget`, and prevents subsequent dispatch through that session. No partially returned plan is qualified. Final plan receipts report limits, elapsed time and calls including dispatched failed calls.

The asynchronous meter receives `(request, {signal})` and must honor AbortSignal cancellation and avoid blocking the event loop. The whole-session timer aborts the outstanding request; a timed-out noncooperating promise cannot enable another request on that session. Its actual transport shutdown remains the tokenizer bridge's responsibility. Synchronous noncooperating code cannot be forcibly interrupted by a JavaScript timer; a late response is rejected by a second elapsed-time check. Real integration must verify transport cancellation. Standalone actual-wire admission is also bounded; a runner should explicitly share its separately budgeted session across all fresh dispatch checks. The planning session does not cache admission or eliminate those checks.

These defaults are prospective instrumentation, not modifications of a live/frozen instrument. No number of real chunks, calls or model tokens is invented here.

## Remaining gates and open questions

The verified real source package and a reviewed source-only identity manifest remain inputs. The real complete-wire tokenizer bridge, source-length qualification, real-cohort preflight within the implemented call/time budget, actual chunk/projection sizing and measured cumulative ceiling remain unimplemented integration steps. The execution runner must preserve ingestion dependencies, independently terminalize failed answer slots, stop shared work on unknown usage/capacity/persistence failure, retain every failed call cost and survive result-journal failure. None of those responsibilities is implied to be solved by this source adapter.

The evaluator lane must independently bind the existing sealed oracle references to compatible S questions, preserve blinding and admit its actual prompts under the same 8K contract and separately frozen budget. Independent review and a new S-variant freeze must precede generation. Will each history meet the strict long threshold? Can every turn fit without a new fragmentation protocol? Will static retrieval omit necessary distractor-scale evidence? Can compact notes remain useful at this ingestion depth? These are unresolved questions, not reasons to relax the comparison or claim measured savings from fixture tests.
