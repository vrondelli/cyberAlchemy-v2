# Full-S history adapter review

Status: read-only design review, not an execution freeze or performance result. This review consulted adapter source, [PLAN.md](PLAN.md) and [FULL-HISTORY-SOURCE.md](FULL-HISTORY-SOURCE.md), not outcomes, references, model calls or network resources. The streaming projection implementation belongs to the other workstream and is not modified here.

## Proposed bounded comparison

Use the four already reserved IDs `09ba9854_abs`, `06db6396`, `cc06de0d`, `54026fce` in that fixed order, now explicitly bound to the separately versioned cleaned **S** histories. Do not replace an ID after seeing an answer, judge result or length. Require exactly one source row per ID, verified full-object hash, source-only row/history hashes and successful target-model tokenizer qualification **strictly above 8,000 original-history tokens** for every row. If a row fails qualification, report the gate failure and preserve the fixed set; do not silently claim a four-task long-history result.

One repetition, four paired tasks, **two concurrent pairs maximum**, each pair's model calls sequential. Alternate control/treatment order by fixed task index: AB, BA, AB, BA. Both arms receive exactly the same final answer system text: v1 `ANSWER_SYSTEM` plus v2 `SCOPE_POLICY`. Same question/date, model/profile, 1,024 answer-output cap, retry policy, source archive and blind native evaluator. Eight planned answer slots remain in the denominator even if ingestion, admission or generation fails.

**Control:** chronologically ingest every source unit using the existing compact-note instruction, 384 output tokens per ingestion call, then answer from its final notes with the common answer policy. The future question remains absent during ingestion. Count every ingestion input, previous-note carry and output. Neither dropped chunks nor restarting after a failed predecessor is permitted.

**Treatment:** retain the same complete source-only archive outside the model, then at query time apply the frozen deterministic user-priority/question-lexical whole-turn selection policy and answer once from selected original units with the common answer policy. No model-based ingestion, extraction or ranking is introduced. If the existing 10,000-character projection does not fit the actual prompt budget, a separately frozen deterministic fit step removes lowest-priority selected units and reorders survivors chronologically; it must record all omissions. Never use oracle sessions, answer-linked annotations or judge feedback to choose units. Keep this ranking unchanged for the confirmation; improving ranking after these IDs' outcomes consumes their confirmation status.

This compares two **memory architectures**, not isolated lossless compression: sequential model-written notes versus full-archive deterministic retrieval. The treatment can inspect archived source at question time, while the control's ingestion does not know the future question. This phase distinction is explicit and intentional. It is fair as an end-to-end architecture comparison over the same accessible source, but not a claim of equal model-visible evidence or equal information retained. A narrower causal compression study would require a different matched-exposure design.

## Chunking, admission and complete costs

Freeze chronological whole-turn chunk boundaries after tokenizer-only sizing. Use the conservative existing 6,976 input ceiling, 384 ingestion-output reserve and 1,024 answer-output reserve; every full actual wire request is measured immediately before dispatch. Previous-note carry is dynamic: adding a nominal384 to an empty-note count is only a planning estimate, since framing/escaping and tokenizer behavior can differ. An over-budget actual request is a recorded blocked slot, not permission to truncate notes or reduce source exposure. A later reviewed adaptive chunker could preserve coverage with additional calls, but those calls and their reservations must be included before claiming savings.

Let n_i be each frozen control chunk count. A simple conservative generation reservation per pair is **7,360 × n_i + 16,000**: all control ingestion calls plus both answer calls. Add a separate fixed **8,000 reservation per arm** for one native judge attempt, subject to actual judge prompt qualification, giving **7,360 × n_i + 32,000** per pair. Campaign ceiling is the sum across all four pairs; replace neither n_i nor this ceiling with the old oracle budgets. If the judge requires a different reviewed policy, freeze its bound explicitly before generation. No chunk counts or token budget are claimed measured by this review. Original source-history qualification strictly above8,000 target-model tokens is separate from cumulative trajectory usage. Report both: the former measures source length once, while the latter sums every model input/output across ingestion, answering and judging, including repeated context. A trajectory exceeding8,000 cumulative tokens does not establish that its original history exceeds8,000 tokens.

Observed cost is actual provider input plus output for every ingestion, answer and judge attempt, including reasoning/cached input and unsuccessful calls. Unknown usage holds its complete reservation and prevents passing. Report tokenizer requests, deterministic extraction/ranking time, network acquisition and storage separately; deterministic CPU preprocessing is not zero end-to-end resource cost, but it is not model-token usage. Never subtract the control's ingestion cost as “setup” while crediting treatment savings. For this one-question-per-history study, charge ingestion in full per task/arm; do not assume reuse across future questions that were not tested.

Run blind native judging only after every generation slot is terminal/sealed, with references isolated in the evaluator process. The shared answer policy does not make the native judge interchangeable; freeze the same official evaluator version and prompt mapping for both arms. Preserve known-cost failures and null answers in all reported denominators.

## Exposure controls and falsifiers

Re-audit prior execution manifests immediately before freeze. Treat the fixed S variants as a new source binding of already reserved question IDs, not unrelated questions. Verify question/date agreement with their oracle source-only records and report discrepancies instead of substituting one. No outcomes are consulted to resolve discrepancies. Both arms must bind the same complete S history digest; treatment omissions and control chunk-union coverage are separately explicit. History instructions remain quoted/untrusted evidence, not active system/user directions.

Hypothesis: deterministic archived-source retrieval with the common answer policy preserves native correctness/completion while saving at least15% of all model tokens against sequential compact-note ingestion on the same four full histories. Null: retrieval omits needed updates, chronology, assistant evidence or abstention clues; notes perform better, or added answering/judging cost erases savings. The user-priority heuristic may crowd out crucial assistant turns. The small notes cap may make control weak, which limits generalization to stronger memory baselines.

Falsifiers include any completion loss, native quality regression, unknown usage, source-coverage violation, query/reference leakage, a request exceeding8,000 including reserved output, or cumulative saving below15%. The active perfect-score objective requires all eight planned answer slots to be valid, completed and fully accounted, and all four treatment answers to be native-correct. Control need not be perfect: requiring that would reject genuine improvements. Report native quality nonregression separately; nonregression alone cannot establish treatment perfection. Four tasks remain bounded confirmation evidence, not benchmark-wide perfection or a causal proof that one extraction representation improves reasoning.

## Dependency DAG and Open Questions

Verified full-byte S projection → strict source-only adapter schema and exposure re-audit → full-history target-tokenizer qualification → deterministic chunk/projection compatibility → equal answer policy plus actual-request admission → complete ingestion/answer/judge reservations → independent review/freeze → four fixed paired tasks/two workers → sealed blind native scoring → complete cost/quality decision.

Open questions: do all four S rows pass source/length/whole-turn feasibility gates? What are measured chunk counts and the resulting campaign budget? Can the same native reference be bound safely for each S question? Does static retrieval retain the evidence actually needed at this distractor scale? Extraction success, fixture tests and larger source files do not answer these empirical questions.
