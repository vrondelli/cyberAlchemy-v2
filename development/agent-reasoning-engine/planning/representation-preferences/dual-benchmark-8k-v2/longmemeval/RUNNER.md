# Scope policy diagnostic runner

Status: offline-tested candidate; this document does not grant live admission. No credential, tokenizer, or generation calls were made by these tests.

This ablation compares the frozen v1 retrieval answer prompt with the generic v2 scope policy on identical archived evidence. It is a policy diagnostic, not a whole-trajectory 15% savings proof. Neither this runner nor its tests make provider calls automatically or load evaluator files. Four original development source rows remain fixed; every task receives both arms once. Task indices 0/2 run baseline then scope, 1/3 reverse that order. Both calls are independent, sequential within a pair, and retain planned slots after failures.

## Integration

Import `buildPairs`, `validateSchedule`, `preflight`, and `runPair` from `runner.mjs`. Build and save the four-pair manifest before freeze. Freeze the manifest, local policy/runner files, original source bindings, and transitive imported predecessor adapter, executor, transport and provider code; the coordinator verifies these hashes before dispatch. `validateSchedule(pairs)` rejects missing or duplicate tasks and proves four 16,000-token reservations total 64,000. `validatePair` recomputes fixed-source/policy bindings; it complements rather than replaces the coordinator's code freeze.

For tokenizer-only preflight, inject `createProvider({directory: NEW_PREFLIGHT_DIRECTORY})` from the v2-owned `./provider.mjs` and call `preflight(pairs, provider)` once. It records eight full prompt measurements, requires every input at most 6,976 and input plus reserved 1,024 output at most 8,000, and reports actual prompt measurements separately from ceilings. Provider records contain exact requests and receipts. Preflight makes no generation requests; an error requires an explicit new diagnostic disposition, not a silent retry.

For live execution, schedule exactly the four validated pairs under the coordinator's approved shared worker limit and 64,000 branch reservation. Each invocation is `runPair({pair, directory: NEW_PAIR_DIRECTORY, provider: createProvider({directory: NEW_PAIR_DIRECTORY}), token_budget:16000})`. The provider is mandatory and injectable. Calls are re-tokenized immediately before generation by the inherited executor. The runner writes an exclusive start marker, so the same pair directory cannot be restarted; transport call IDs also reject retries. Root must prevent duplicate task scheduling across different directories. The 1,024 output cap includes reasoning; all actual input and output, including known failed-call usage, count. Unknown model usage holds its entire 8,000 reservation and prevents a precise savings claim. Tokenizer/admission failures before generation count zero model usage. Unknown model usage, capacity status 429/503, or provider receipt persistence failure stops the pair: the other arm remains an explicit blocked slot, and no new provider request is made. Other known failures may allow the independent opposite arm if its full reservation fits. Capacity status/code propagate to the parent scheduler.

Each result preserves two answer slots, exact messages and hashes, source/projection hashes, provider receipts, known usage, held unknown reservations and failures. Aggregate all four pairs, including blocked or failed slots. Do not substitute held ceilings for measured usage. Judge calls are excluded from this runner and require their separately planned budget and usage ledger.

For blind native-rubric scoring, the coordinator creates a separate opaque answer mapping, stripping arm, task-order and policy metadata from judge-visible packets. Include question and the frozen native reference/rubric only in the scorer process; this runner never consumes them. Keep both failed slots and ambiguous judgments in the final table. The judge output must bind answer hashes; preserve raw response and count all judge input/output, including failed calls, separately. No outcome-based cohort or policy changes are permitted within this frozen run.

## Persistence and provider ancestry

The v2-owned [provider](provider.mjs) is a narrow descendant of the frozen [pilot provider](../../benchmark-pilot-v2/execution/selectivity-v2/provider.mjs). It reuses the original model, payload serialization, validator and secret-backed transport path; adds injected `exchange` and synchronous `write`/`exists`/`mkdir` dependencies; and replaces the unsafe final journal write with receipt-preserving error propagation. The frozen predecessor is unchanged. Injected exchange tests perform no credential reads or network requests. A known generation response followed by journal failure raises an error carrying the original usage and output receipt; unknown transport usage remains unknown. Initial request-journal failures make no exchange and carry zero model usage. In-memory consumed IDs also prevent retry when no receipt could be written.

The runner accepts synchronous `write` injection for persistence-failure testing. A failed final result write throws `pair-result-persistence-failure` carrying the full in-memory `result`. Only when every call's usage is known does it additionally attach aggregate `usage` and a `receipt.usage`. If any usage is unknown, neither exact aggregate field is attached; `unknown_usage` and `held_tokens` remain explicit. The parent must catch and durably preserve the in-memory result in its own failure journal, stop scheduling on health failures, and retain the failed completion disposition. Offline tests cover known and unknown result-journal errors, known provider-response journal failure, unknown transport plus journal failure, zero-send request-journal failure, and capacity stop behavior. Freeze verification, parent failure-journal integration and bounded live admission remain coordinator work.
