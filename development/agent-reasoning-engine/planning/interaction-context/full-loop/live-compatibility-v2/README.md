# Codex 0.153.1 interaction-learning canary

This is a canary-only compatibility successor to the unchanged full-loop candidate.
The installed binary generated 416 experimental schemas. The selected closure
covers 17 methods and preserves the referenced type definitions. The profile binds
those exact observations and the existing wrapper interface. Neither repository-v1
nor interaction-learning-canary-v1 was changed.

Local checks:

```sh
python3 validate.py
node --test harness.test.mjs harness-v3.test.mjs
```

Use Node v26.8.1. The live executables are recorded experimental epochs, not retry
commands. Each refuses to overwrite its result. RUN-MANIFEST*.json binds its exact
inputs. A new live run needs a fresh envelope/output and an explicit finite budget;
these historical results must not be refreshed by changing digests or statuses.

The initial live epoch completed three turns and then hit selection.no-match on
an under-specified fourth request. The corrected scenario names context management
in every request and uses equal five-turn arms to stay within 24 total model calls.
A zero-call startup timeout in v3 exposed a harness timeout of 60 seconds. V4 restores
the repository canary's existing 240-second startup bound, preserving the first
envelope's 30-minute deadline and the cumulative budget. All failures are retained.

Each arm uses an ephemeral read-only scratch thread with the exact configured
model gpt-5.6-sol, provider fallback disabled, shell and multi-agent features disabled,
and no model-judge or optional-provider calls. Unexpected tool items stop the run.
The proxy transmits the wrapper's exact post-checkpoint messages unchanged. It
captures completions, lesson applications, and provider token-usage notifications.

Quality means literal compliance with a frozen includes/excludes-jargon rubric.
V0 has no retained lesson, V1 adds a generic summary, and V2/V3 use the same explicit
scoped preference in this scenario. Thus this small fixed-order test can validate
live plumbing and explicit preference behavior, but cannot isolate inferred
learning or demonstrate general semantic improvement. A tied baseline is no gain.

Construction frontier: live product-test evidence for the existing local prototype.
Operational support: this package resolves only the selected canary protocol
binding. Production protocol rollout, product approval, serving activation,
publication, and broader external evaluation remain separate owner work.
