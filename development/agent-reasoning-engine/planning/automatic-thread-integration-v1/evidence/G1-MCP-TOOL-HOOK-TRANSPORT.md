# G1 MCP tool hook transport candidate — 2026-09-28

Status: disposable pinned-host transport, opt-in relay, and joined managed
session tests passed; not host activation or a complete effect-boundary proof.
Authority effect: none. The TUI is discontinued and outside this path.

## Finding

Codex's current [hook contract](https://learn.chatgpt.com/docs/hooks#mcp-tool-hooks)
documents `mcp_tool` lifecycle handlers. They call an already-connected MCP
server with structured event arguments, including type-preserving full-value
placeholders. This may avoid the installed native Windows **command-hook**
callback's missing-stdin symptom for an invoked `PreToolUse` event. The general
ARE MCP server still exposes decision/evolution/evidence tools; a separate
[hosted hook relay](../../../../../implementation/agent-reasoning-engine/packages/are-mcp-server/src/hook-server.mjs)
now accepts a lifecycle event and returns the Codex hook-output shape. The disposable
[canary](../../../../../implementation/agent-reasoning-engine/packages/codex-app-server-wrapper/scripts/mcp-hook-transport-canary.mjs)
now verifies the transport against both pinned installed CLIs.

The same documented contract says a missing server at hook delivery, an
unavailable tool, or a hook error **does not block** the operation. A separate
[`required` MCP configuration](https://learn.chatgpt.com/docs/extend/mcp)
can stop session startup when the server cannot initialize; it does not make
later hook delivery fail closed. `PreToolUse` also excludes hosted tools
and some specialized paths; `write_stdin` does not invoke it again for an
already-admitted command. Therefore MCP hooks alone cannot establish the
complete, fail-closed effect boundary required by the
[session-control contract](../SESSION-CONTROL-CONTRACT.md). The normal Windows
managed-session model-turn pause remains necessary.
