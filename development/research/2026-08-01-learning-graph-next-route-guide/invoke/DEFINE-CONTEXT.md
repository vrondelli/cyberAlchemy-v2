# Define Context

## Goal

Turn the accepted learning-graph research blueprint into a governed feature
contract that can later compile exact-bound learner-projection data and render
it in the existing implementation-conformance ontology view.

## Bounded Target

- Subject: `implementation.payment.LegacyLimitRule` and
  `implementation.payment.MaxAmountRule` frozen fixtures.
- Host candidate:
  `projects/domainspec-v2/development/implementation-conformance/ontology-experiment/architecture-ontology-view.html`.
- Output concept: a disposable, regenerable learner projection with typed
  records, explicit proof tiers, abstention, deterministic question revision,
  and a display-only route suggestion.

## Constraints

- Do not define or promote a canonical `LearningGraph` ontology.
- Do not infer learner comprehension, confusion, intent, or semantic identity.
- Do not treat absence of an evaluator finding as positive per-assertion proof.
- Keep `TypeScript adapter owner` at candidate owner-route string ceiling.
- Do not select, register, dispatch, execute, promote, publish, release, or
  deploy from the projection.
- Do not create a second generic learning-map product.
- Preserve exact source paths, SHA-256 digests, JSON pointers, proof ceilings,
  and fail-closed invalidation.

## Approval Interpretation

The user's explicit `invoke define design and plan` request authorizes this
authoring package. It does not supply learner-view mutation admission,
owner-resolved semantic-admission evidence, destination-owner admission, product
implementation authorization, SWU selection, or lifecycle promotion approval.

## Discovery Gate

Discovery is satisfied by the accepted research package at `../findings.md`
and its independently accepted audit. No discovery waiver is used.
