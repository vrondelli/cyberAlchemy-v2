## Design Intent

Design one deterministic projection contract and one candidate extension of the
existing implementation-conformance HTML host. The system must make evidence
boundaries more visible without adding ontology authority, learner cognition,
or executable route semantics.

## Delivery Boundary

Included: exact-bound projection schema/compiler, fixture validation, current
snapshot reader, orientation/focus/abstention/question/suggestion presentation,
view parity, keyboard mechanics, no-outbound/no-execution checks.

Excluded: canonical vocabulary, real TypeScript adapter, personal learner-state
persistence, comprehension claims, learner-view mutation admission,
owner-resolved semantic admission, destination-owner admission, dispatch/execution,
promotion, publication, deployment, and production readiness.

## Owner Approval State

User approval covers L1 authoring. The learner-view/navigation owner has not
admitted implementation in the existing host; that remains an execution gate.
