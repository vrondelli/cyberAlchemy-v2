# The Inventory's Account of How CAV2 Authority Works

This brief reconstructs how cav2 authority works *as the inventory read-models tell it*.
Every load-bearing claim cites the inventory file it rests on and the CAV2-D number /
rule name the inventory attributes it to. I did not open the spec. Note up front: the
inventory marks **every one of these four syntheses and all their cards `status:
candidate` / non-authority** — "These cards promote nothing" — so the entire account is
self-described as a read-model, not canonical. Specific candidate/open flags are called
out inline.

---

## 1. THE MODEL — three layers + one mold

**Authority = the DECISION layer.** Authority is "who or what is allowed to make
something *count*, and only for which purpose — a **permission attached to an owner +
scope**, not a property a thing has." The load-bearing rule: "authority moves by **owner
route**, not by proximity, usefulness, or repetition."
→ `authority-ontology-governed-artifact-synthesis.md` (§three layers, Authority row) +
card `authority-is-permission-by-owner-route`; attributed to **`CAV2-D34`** and
**AUTHORITY-MODEL §Authority Rule**.

**Ontology = the DESCRIPTION layer / map that cannot decide.** Ontology is "the typed
node/edge MAP of what is + how it relates. Can model authority … but **cannot decide
it**." It is the `Projection` kind (ontology route + source owner) which "must not
collapse into a promotion decision." Direction is one-way: **authority governs ontology,
not the reverse.**
→ same synthesis (Ontology row) + card `ontology-models-authority-cannot-decide-it`;
attributed to **AUTHORITY-MODEL §Non-Collapse rule 2** ("Ontology can model authority, but
it cannot decide authority") and **§Authority Kinds (`Projection` row)**.

**Governed artifact = the VEHICLE / joint.** Explicitly **NOT a primitive** ("typed
negative") — "just `artifact` + the authority model wrapped around it. 'Governed' = routed
through an owner gate." It is the unit authority acts on and the joint where ontology and
authority meet: a node in the map AND an authority-bearing object that only counts once an
owner gate clears it AND only if its kind is an enumerated row.
→ same synthesis (Governed-artifact row) + card
`governed-artifact-is-the-vehicle-not-a-primitive`; attributed to **`CAV2-D34/D35/D36/D49`**
(kind/provenance/traceability/default-deny) and the 2026-06-23 typed-negative finding.
*Flag: the inventory marks the base term `artifact` (`CAV2-D31`) as an open
definitions-governance review.*

**CAV2 = reflexive meta-authority (mold → casting).** CAV2 is "a **system/meta authority**
— authority-about-authority. It decides no domain facts; it decides how anything BECOMES
authority: the kinds, the promotion lifecycle, the owner routes, the gates." Layering:
**system/meta authority (CAV2 + Arcanum method) = the MOLD; a domain authority = the
CASTING.** Reflexive — CAV2 governs itself (the operational-ontology B-op branch = CAV2
modelling its own operations). This is framed as the ontologize product thesis (it sells
castings).
→ same synthesis (§CAV2 as reflexive meta-authority) + card
`cav2-is-reflexive-meta-authority-mold`; attributed to **`CAV2-D41`** ("the traffic map for
what is allowed to count, who can make it count, and what it must not be confused with"),
**`CAV2-D48`** (promotion lifecycle), **`CAV2-D49`** (kinds), **`CAV2-D37`** (gates).
*Flag (the inventory's own "honest caveat"): meta-authority "in METHOD/POSTURE, **not yet
ENFORCEMENT** (review-mode; OQ-1 + OQ-2 open). The mold works; it is hand-operated, not yet
a machine."*

## 2. THE INVARIANTS

**Non-Collapse rule 2 — ontology models but cannot decide.** Covered above; it is the
load-bearing wall between the map and the decision layers, and the inventory cites a
*witness*: the B-op schema's own line 8, "this schema assigns no promotion authority."
→ card `ontology-models-authority-cannot-decide-it` +
`b-op-encodes-non-collapse-and-the-map-decision-split`; attributed to **§Non-Collapse rule
2** with the schema line as baked-in evidence. *Residue: "none material."*

**"No-authority-without-a-lifecycle" — RE-SCOPED, flag this.** The inventory is explicit
that this headline was **re-skinned**: per review CR-1 (2026-06-23), "the prior `no
authority without a lifecycle` framing **re-skinned the Authority Rule**" and was
re-scoped to a **`closed authority-kind enumeration`** invariant — default-deny for
unenumerated kinds.
→ `authority-lifecycle-invariant-synthesis.md` (Decision spine, Invariant row) + card
`no-authority-without-lifecycle-invariant`; staged as `CAV2-CAND-LIFECYCLE-002`, **promoted
to `CAV2-D49`** and **enacted review-mode** via a kind-table default-deny catch-all row.
*Flags: deterministic validator pending (**OQ-1**); the live un-enumerated case is **OQ-2**
(`invariant`/`axiom` govern from outside the kind table); the synthesis's own
**collapse-test** says the rule "**folds to zero** if a catch-all default-deny row is added
to the kind table — that row *is* this rule." So the invariant is candidate-but-promoted,
and self-flagged as collapsible.*

**Lifecycle scope is authority-bearing kinds only — NOT "everything."** Evidence, residue,
ledger events, logs, generated projections are inputs or terminal — governed, not each
carrying a promotion ladder.
→ same synthesis (Scope row) + card `lifecycle-invariant-scope-authority-bearing`;
attributed to **`CAV2-D34`** / **Non-Collapse rule 1**. *Residue: the exact enumeration of
"authority-bearing kinds" is not yet fixed.*

**Build-from-owned is already authority (`CAV2-D48`).** The inventory answers "is this only
in Claude Code memory?" with **No** — "`CAV2-D48` *is defined as* 'the build-from-owned
generalization', and the research skill's precedent gate enforces it." Claude Code memory is
"a **low-authority capture surface, not authority**." Naming the parent lifecycle is itself a
**build-from-owned generalization inference** (the shape is visible across owned sources —
`CAV2-D43`, `CAV2-D46`, the Discipline Growth Rule, the promotion ladder — but the unifying
object is named in none, so it is owner-gated, not a mechanical lift).
→ `moat-stack-and-authority-triage-synthesis.md` + card
`build-from-owned-is-already-authority`, and `authority-lifecycle-invariant-synthesis.md`

## 3. THE LIFECYCLE — capture surface → authority write surface

**Two write surfaces.** The inventory distinguishes a **capture write surface** (low
authority — Claude Code memory, chat notes, evidence, residue, ledgers) from the
**authority write surface** (where something is made to count). Crossing between them is
never automatic.
→ `moat-stack-and-authority-triage-synthesis.md` ("Claude Code memory is a low-authority
capture surface, not authority") + `authority-lifecycle-invariant-synthesis.md` (Scope row:
evidence/residue/ledger/logs are inputs, not promoted).

**The promotion gate + owner decision.** "Authority movement requires owner-routed decisions
and non-collapse rules; evidence, research, generated projections, implementation success,
and narrative repetition cannot silently become authority." In the B-op encoding: **MAP** =
the node+edge graph; **DECISION** = the status climb (candidate→premise→promoted, L0–L7)
**fired by the owner gate**; **VEHICLE** = the typed governed-artifact node.
→ `scientific-authority-lifecycle-synthesis.md` (Relation Semantics: `decided_by`,
`may_signal` "Signal does not promote", `viewed_by` "View is not authority") + card
`authority-owner-decision-gate` (attributed to **`CAV2-D41` authority model**); and
`authority-ontology-governed-artifact-synthesis.md` (§B-op encoding) + card
`b-op-encodes-non-collapse-and-the-map-decision-split`.

**The executable front-door: authority-triage.** The sigil takes any captured candidate and
classifies: does it need authority? is it already owned (build-from-owned sweep)? what kind?
apply **`CAV2-D49`** default-deny, route to the narrowest owner. "It **promotes nothing** —
routes only."
→ `moat-stack-and-authority-triage-synthesis.md` (§authority-triage sigil) + card
`authority-triage-sigil`; attributed to **AUTHORITY-MODEL Narrowest-Owner Rule + Authority
Kinds + D48/D49**. *Flag: candidate; validated 7/7 on the memory corpus but promotion to
`arcanum/arcana/` pending two more corpora + a boundary scrub.*

**The scientific-method analogy.** The whole lifecycle reads as the scientific method run
over operational evidence: hypothesis (code/spec/workflow claim) → experiment (domain run) →
observation (OutcomeEvent/MetricObservation/residue) → falsification (contradiction path,
challenge contract) → replication (second-context exercise) → theory (promoted architecture
pattern authority) → law-like pressure (invariant/constitution/discipline/validator after
owner review). The promotion segment proper is just
`PromotionCandidate → ArchitecturePatternAuthority`.
→ `scientific-authority-lifecycle-synthesis.md` (§Scientific Method Reading, Relation Map,
Boundary) + cards `scientific-authority-lifecycle-thesis`,
`operational-evidence-to-promotion-candidate`, `pattern-authority-promotion-path`;
attributed to **`CAV2-D41`** (non-collapse law) and **`CAV2-D43` pattern promotion
lifecycle**. *Flags: name and schema are not canonical; no validator for
`pattern_candidate → architecture_pattern_authority`; the relation names are "not promoted
ontology edges."*

**"Condense knowledge" is NOT a primitive.** A self-correction worth flagging: the inventory
rules that knowledge-condensation is "the **purpose** the authority-promotion-lifecycle
serves, NOT a separate `CAV2-D` primitive" — staging it as a term would trip the re-skin
gate (overlaps `CAV2-D2`/`D18`/`D19`/`distill`); it routes to the value/philosophy surface,
not definitions-governance.
→ `authority-lifecycle-invariant-synthesis.md` (Purpose row) + card
`condense-knowledge-is-purpose-not-primitive`.

## How tight is this condensation? (cartographer's own-terms verdict)

On its own terms the account is coherent and internally cross-checked: the four syntheses
form a descriptive→normative stack (SAL is descriptive, the lifecycle-invariant synthesis is
the normative layer over it, and it explicitly forbids citing the SAL cards as authority for
the invariant — CR-3). The model's three layers map cleanly onto three CAV2-D anchors
(D34 / Non-Collapse-2 / governed-artifact-as-D34+wrapper) and onto the B-op schema's own
self-denial of promotion authority, which the inventory treats as a witness rather than an
assertion. The mold/casting framing is the one genuinely synthetic move and the inventory
labels it a **build-from-owned generalization inference**, not a lift.

Honest boundaries the inventory itself draws (not me overriding it): **everything is
candidate**; the headline invariant was **re-skinned and re-scoped** and is **self-described
as collapsible** (collapse-test); meta-authority is **method/posture, not enforcement**
(OQ-1 validator pending, OQ-2 unenumerated kinds live); the B-op bridge is **not executed**;
the base term `artifact` (`CAV2-D31`) is **open**. Claim ≤ proof holds: the inventory never
asserts these as shipped authority, and neither does this brief.
