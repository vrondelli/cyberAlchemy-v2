## Smallest coherent unit and recomposition/recursion contract

The smallest proposed shared unit is the **Shared Artifact Mechanics Contract**—not a universal artifact ontology. It closes only: source-direction declaration; schema identity/digest; generator identity/version/digest; deterministic regeneration and byte comparison; source-admission reference shape; and typed relation envelope. It must not provide taxonomy, lifecycle interpretation, authority classification, admission decisions, semantic defaults, bounded-context classification, local relation meaning, promotion, or enforcement. [SYN2-4; `cyberAlchemy-v2/development/research/2026-08-31-cyberalchemy-lab-context-artifact-architecture/synthesis-round-2.md#SYN2-4-Shared-Artifact-Mechanics-Contract`]

The recursive unit is an **owner-local recursive capability-instance envelope**:

```text
capability_instance_id + capability_ref + semantic_owner_ref
+ one independent CAV2 context_id
+ optional evidenced bounded_context_ref[]
+ Project/Goal coordination refs + owner-local business ontology
+ D64 parent/instance binding + D65 construction binding
+ directional context-map contracts + residue + budget/stop
+ recomposition route + terminal handoff
```

The owner-local artifact survivor is an **owner-local logical record contract**, not a folder convention:

```text
record_kind: artifact_type | artifact_instance
artifact_type: artifact_type_id, semantic_owner_ref, schema_ref/digest,
  producer/origin constraints, lifecycle vocabulary refs
artifact_instance: artifact_instance_id, artifact_type_ref,
  capability_instance_id, context_id, origin/owner, durability/authority,
  source-direction, evidence/residue/relation refs
```

Each instance must resolve its exact type; all identities are independent; a higher altitude requires a fresh complete D64 binding; local evidence returns only through the named recomposition route; and missing/stale bindings stop fail-closed. [SYN2-3, SYN2-5; `cyberAlchemy-v2/development/research/2026-08-31-cyberalchemy-lab-context-artifact-architecture/synthesis-round-2.md#Owner-local-capability-instance-envelope`; `cyberAlchemy-v2/development/research/2026-08-31-cyberalchemy-lab-context-artifact-architecture/synthesis-round-2.md#Owner-local-logical-artifact-record-contract`]

## Deterministic enforcement obligations and negative tests

The proposed boundary object must declare identity, owner-local type, capability/Context identities, schema ref/digest, lifecycle posture, source-admission ref, generator identity/version, residue, and typed outbound relations; it must generate `ARTIFACT.md` byte-deterministically and must not let the projection introduce semantic, acceptance, promotion, conformance, or release claims. This is a proposal, not current enforcement. [SYN2-7, SYN2-9; `cyberAlchemy-v2/development/research/2026-08-31-cyberalchemy-lab-context-artifact-architecture/synthesis-round-2.md#SYN2-7-Boundary-object-and-hidden-glue-contract`]

One positive witness must bind a local type, instance, machine source, generated projection, schema, owner, Context/capability envelope, source-admission reference, relation envelope, and exact generator; it must demonstrate two-run byte identity without claiming admission or implementation. The required negative mutants reject: hand-edited projection; schema-digest mismatch; missing/wrong `artifact_type_ref`; missing/inferred owner; stale generator binding; label/directory-only cross-context dependency; missing recursion stop/recomposition; and copied or schema-valid external material labelled admitted.
