# Spec Audit: CCB Validation Workflow Tests

**Date:** 2026-03-24 12:05 (UTC-3)
**Tags:** #acquisition #ccb #testing

## Summary

This session involved a thorough review and audit of the `missing-critical-reason-and-kit-quality-gate-implementation.md` specification against the `test_parallel_bulk_import.py` test suite in the acquisition domain. The primary goal was to verify the proposed logic and identify any inconsistencies or missing tests in the document before development begins.

We discovered that while the pipeline logic and data migration strategies outlined in the spec were robust, the test names referenced in Part 1 had diverged from the actual codebase. In addition, the universal fallback test previously labeled as "remaining `REASON_NO_TEMPLATE`" actually needed to be updated to `REASON_MISSING_CRITICAL`. Finally, the quality gate test section in Part 2 was missing a negative test case for the newly introduced `missing_critical` reason. All these issues were successfully resolved by editing the specification document.

### Test Names Alignment
- **Problem/Goal:** The test names provided in the specification for evaluating the `REASON_NO_TEMPLATE` to `REASON_MISSING_CRITICAL` migration did not correspond to the actual names in `test_parallel_bulk_import.py`.
- **Decision:** The specification must reflect the true state of the codebase.
- **Changes:** Updated the table in the implementation plan to use the correct existing test names (e.g., `test_gemini_extraction_without_critical_ids_fails_quality_gate` instead of `test_missing_both_cpf_and_id_documento`).

### Universal Fallback Partial Document Test
- **Problem/Goal:** Line 784 (`test_universal_fallback_creates_partial_doc_when_critical_fields_missing`) was incorrectly marked as remaining `REASON_NO_TEMPLATE` in the spec.
- **Decision:** Because this test evaluates partial extraction missing critical fields via the universal fallback, it is directly affected by the proposed changes and must assert `REASON_MISSING_CRITICAL`.
- **Changes:** Moved this test from the "remain" list to the "change" list in the spec.

### Missing Quality Gate Test Case
- **Problem/Goal:** The spec introduces `REASON_MISSING_CRITICAL` but did not include a test case ensuring documents with this reason are excluded from the `folder_docs` kit evaluation.
- **Decision:** Include a negative test case to verify that the kit evaluation properly rejects this new reason code.
- **Changes:** Added `test_excludes_dvs_with_missing_critical_reason` to the list of new tests required under `TestStepKitEvaluation`.

Key outputs:
- `specs/002-ccb-validation-workflow/missing-critical-reason-and-kit-quality-gate-implementation.md` — Updated spec with accurate test names and complete test coverage references.

## Key Decisions

- **Test Alignment:** The implementation plan for the CCB validation workflow must reference exact test names from `test_parallel_bulk_import.py` to prevent confusion during execution.
