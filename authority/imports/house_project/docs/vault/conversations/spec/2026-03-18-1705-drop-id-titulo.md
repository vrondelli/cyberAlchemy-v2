# Drop id_titulo from AquisicaoManual and AquisicaoManualStaging

**Date:** 2026-03-18 17:05 (UTC-3)
**Tags:** #models #acquisition #refactor #testing

## Summary

This session removed the `id_titulo` column from the `AquisicaoManual` and `AquisicaoManualStaging` Django models and remapped all CSV column inputs (`IdTituloVx`, `id_titulo_custod`, bare `id_titulo`) to target `numero_titulo` instead. The column was redundant because `numero_titulo` already carried the same value. The change spanned 25+ files across models, upload rules, remessa fields, celery tasks, approve/delete/rollback use cases, API views, estoque SQL policies, CSV file handlers, legacy management commands, and all associated tests. A Django migration (`0032_drop_id_titulo.py`) was created to physically drop the column. All 1374 tests pass.

### Dropping id_titulo from Models
- **Problem/Goal:** The `id_titulo` column on `AquisicaoManual` and `AquisicaoManualStaging` was redundant — it carried the same value as `numero_titulo` and added confusion to the CSV upload/export contract.
- **Decision:** Drop `id_titulo` entirely from both models. Remap all CSV column sources (`IdTituloVx`, `id_titulo_custod`, bare `id_titulo`) to `numero_titulo`. Leave `RemessaAquisicao` (legacy table) untouched.
- **Changes:** Removed the field from both Django model classes, created migration `0032_drop_id_titulo.py`.

### CSV Column Mapping Update
- **Problem/Goal:** Multiple CSV column names (`IdTituloVx`, `id_titulo_custod`, bare `id_titulo`) previously mapped to the model's `id_titulo` field. With the field gone, these inputs need to target `numero_titulo`.
- **Decision:** Update `FORMATTING_MAP` in `upload_rules.py` to map all three variants to `numero_titulo`. Keep `_derive_columns` fallback for bare `id_titulo` → `numero_titulo` to handle external CSVs that don't go through FORMATTING_MAP.
- **Changes:** Updated `upload_rules.py`, `remessa_fields.py`, `xlsx_csv_files_handler.py`.

### Cascading Code Updates
- **Problem/Goal:** Many files referenced `id_titulo` in model constructors, SQL queries, API download headers, celery task builders, remessa approval/deletion, and estoque aggregation SQL.
- **Decision:** Systematically remove all references.
- **Changes:** Updated `celery_tasks.py`, `approve_remessa.py`, `delete_remessa.py`, `api_views.py`, `sql_policies.py`, `xlsx_csv_files_handler.py`, `upload_aquisicao_manual2.py`, `seed_mock_data.py`, and 5 legacy management commands with raw SQL.

### Test Fixture Updates
- **Problem/Goal:** ~15 test files had `id_titulo=...` in model constructor calls and CSV test data that would fail after the model change.
- **Decision:** Remove `id_titulo` kwargs from all test model constructors. Update CSV column derivation tests to use `IdTituloVx` (which now maps to `numero_titulo`). Fix `conftest.py` sample CSV builder that used different `IdTituloVx` values — which now creates different `numero_titulo` values and changes contract grouping.
- **Changes:** Updated all test fixtures across `domains/aquisicao/tests/`, `domains/liquidacao/tests/`, and `infrastructure/tests/`.

Key outputs:
- `migrations/aquisicao/0032_drop_id_titulo.py` — migration to drop the column
- `domains/aquisicao/domain/upload_rules.py` — updated FORMATTING_MAP and _derive_columns

**Why these tests matter:** Without these updates, every test that creates `AquisicaoManual` or `AquisicaoManualStaging` instances would fail with "unexpected keyword argument 'id_titulo'", and the E2E upload tests would fail because the CSV validation expects `numero_titulo` to be populated.

## Key Decisions

- **Drop not rename:** The column was dropped entirely rather than renamed, since `numero_titulo` already existed and carried the same value.
- **Backward-compatible CSV parsing:** Bare `id_titulo` column header in incoming CSVs is still accepted — it maps to `numero_titulo` via both `FORMATTING_MAP` and `_derive_columns` fallback.
- **RemessaAquisicao untouched:** The legacy `RemessaAquisicao` table (which also has `id_titulo`) was left as-is per user direction.
- **Data loss accepted:** Existing `id_titulo` values in production will be lost when the migration runs — explicitly approved by user.
