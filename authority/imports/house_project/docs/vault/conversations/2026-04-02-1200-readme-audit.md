# README Pattern Audit — /specs/

**Date:** 2026-04-02 12:00 (UTC-3)
**Tags:** #vault #agents

## Summary

This session performed a systematic audit of all 13 READMEs in `/specs/` against the `readme-pattern.md` specification, which requires 4 sections: "What is this?", "Business Context", "Why it matters", and "📁 Navigation". The motivation was to ensure the navigation surface is reliable for agents traversing the spec tree.

The audit found that only 2 READMEs were fully compliant (`specs/newspaper/README.md` and `specs/003-remessa-upload-with-events/README.md`), 1 needed a minor rename (`specs/002-ccb-validation-workflow/README.md` — Navigation section label), and 10 were non-compliant due to missing, partial, or differently-named sections.

All non-compliant READMEs were restructured during the session to meet the 4-section requirement. The audit confirmed the readme-pattern itself is sound — it was applicable without exception across 13 heterogeneous spec folders. However, the finding that 10 of 13 were non-compliant suggests the pattern was not consistently followed during creation, and there is currently no enforcement mechanism to prevent future drift.

The session surfaces a process gap: there is no hook, CI check, or agent instruction that validates README structure at creation time. This is flagged as a backlog item.

## Epistemic Impact

- **validates** `readme-pattern.md`: The pattern proved applicable to all 13 READMEs; 2 were already compliant without intervention, confirming the standard is sound.
- **questions** assumption that pre-existing READMEs follow the pattern: 10 of 13 were non-compliant, suggesting enforcement has been inconsistent. Future README creation should explicitly reference `readme-pattern.md`.
- **Spec drift fixed:** 11 READMEs had drifted from the standard. All corrected within the session.
- **promoted_candidates:** README compliance enforcement mechanism — a linting rule, CI check, or explicit step in `close-session.md`/`readme-pattern.md` to catch drift proactively.
