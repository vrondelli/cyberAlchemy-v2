# Property-closed software correctness audit

## Customer input

One bounded business property, its implementation subject, trusted inputs,
explicit finite or executable bounds, and an owner-approved test environment.

## Delivery sequence

1. Define the property and its meaning owner.
2. Select verification methods by semantic trait.
3. Search for implementation or evidence-pipeline counterexamples.
4. Explain any causal defect and construct a bounded repair.
5. Re-run every route and mutation control.
6. Deliver sealed author evidence plus independent technical replay.

## Deliverables

- property and obligation ledger;
- implementation and trust-boundary map;
- raw formal-tool and executable evidence;
- counterexample and mutation dossier;
- repair correspondence report;
- V0-V3 enforcement result;
- independent replay verdict;
- residual-risk and explicit-bounds statement.

This package can support a customer's broader assurance program, but it is not
an ISO, SOC, regulatory, or product certificate by itself. External
certification mappings require a separately governed evidence crosswalk.
