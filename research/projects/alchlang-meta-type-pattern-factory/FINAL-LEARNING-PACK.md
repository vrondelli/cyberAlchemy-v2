# Final learning pack

## Answer

The coherent architecture is not “implement every meta-type as a TypeScript
factory.” It is a profile-bound compiler and proof pipeline in which each layer
has one job:

```text
AlchLang source factory
  -> static semantic AST
  -> Carrier v3 with exact DomainSpec meta-type refs
  -> DomainSpec node/edge formation
  -> realization and pattern dependency plan
  -> generated isolated target sources
  -> DomainSpec factory proofs
  -> conformance receipt
  -> optional runtime observation and separately authorized execution
```

## What “profile” means

The AlchLang Construction Profile is the immutable compatibility envelope for
one build. It composes exact language, frontend, carrier, DomainSpec baseline,
relationships, target realization, integration, pattern, runtime, and evidence
profiles. It is not a meta-type and it does not carry adoption or execution
authority.

## How new meta-types enter

A truly new kind of domain meaning starts in DomainSpec: definition and
criterion, typed edges and obligations, admission kit, family evaluator,
hostiles, per-language realization providers, proof DAG, immutable new
baseline, and owner admission. AlchLang then adds a projection and source
factory under a new construction profile. It cannot create admission by adding
an arrow function or registry row.

## How new AlchLang patterns enter

A pattern starts in CyberAlchemy-v2 with Product Capability and business
ontology. It names existing host meta-types and relations, integration
bindings, generators, conformance, runtime requirements, and owner stability.
The catalog derives three surfaces: describable, generatable, and
runtime-capable. This prevents generated adapter code from being mistaken for
an observed infrastructure guarantee.

## Arrow functions

Arrow syntax is viable if parsed statically. Authored arrows are normalized to
an expression AST and never executed. Generated arrows are target realization
source and live behind provider proof/runtime boundaries. One pleasant source
file may project to many isolated DomainSpec nodes and proof inputs through a
deterministic factory projection manifest.
