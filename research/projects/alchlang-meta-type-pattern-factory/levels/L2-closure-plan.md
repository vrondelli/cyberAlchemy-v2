# L2 — closure plan

## Vertical 1 — profile and Carrier v3

1. Owner decides BD-01 through BD-08.
2. Revise AlchLang definitions and Product Capability without changing the
   compiler.
3. Author capability-local business ontology for construction profiles,
   meta-type projections, pattern catalogs, and factory projections.
4. Create DomainSpec v2 authored source and compile the graph/system ontology.
5. Specify Carrier v3 and the construction-profile schema.

Exit: semantic and schema closure only.

## Vertical 2 — resolver and static arrow frontend

6. Implement exact-digest profile resolver and receipt.
7. Implement static TypeScript AST decoder with hostile corpus.
8. Lower Markdown and arrow frontends to byte-identical Carrier v3 fixtures.
9. Reject arbitrary execution, unknown factories, hidden captures, and
   unresolved meta-type projections.

Exit: two frontends, one semantic carrier, no code generation expansion.

## Vertical 3 — DomainSpec projection and proof bridge

10. Split Carrier v3 into canonical node/relationship inputs.
11. Reuse canonical CLI planning for selected instantiations.
12. Emit deterministic factory projection and proof requests.
13. Run direct/join proof replay and bind results into the AlchLang construction
    receipt.

Exit: AlchLang compilation reaches DomainSpec proofs without moving frontend
logic into the factory.

## Vertical 4 — generalized pattern catalog

14. Replace Operation-only baseline extraction with a closed baseline catalog.
15. Add multi-host meta-types, typed-edge prerequisites, profile refs, formation
    and provider bindings, static conformance, runtime observations, and owner
    stability decisions.
16. Derive describable/generatable/runtime-capable surfaces with collect-all
    blockers.
17. Migrate Operation port and transactional Outbox as fixtures.

Exit: adding a binding or generator can expose a pattern only through closed
dependencies; it cannot silently alter language meaning.

## Vertical 5 — first governed end-to-end examples

18. Compile the same customer-approval model from Markdown and arrow syntax.
19. Compile one pure Rule/Calculation slice with no integration provider.
20. Compile one Operation + Event + SQLite Outbox slice, then separately run
    provider-runtime observation under explicit local authority.
21. Compare receipts, graphs, generated sources, proof outcomes, and blockers.

Exit: evidence for owner review; not automatic adoption or release.
