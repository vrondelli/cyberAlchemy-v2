## Work-stream A — Observability wiring (Phase 1)

**Goal:** a subagent dispatch under Claude Code lands a matched
`dispatch.started` + `dispatch.closed` pair in the one existing ledger
`<observability_dir>/signals/sigil-invocations.jsonl` — closing the
"32 ungoverned folders" gate (findings §2.1; system-view central-value claim).

**Architecture (settled, do not relitigate):** a **producer feeds the existing
writer** `observe-invocation.sh`; do **NOT** port domainspec's appender — it would
fight the existing dedupe/index/counter owner (D1; R-06 closed; findings:99).

### A0 — Blocker spikes (gate everything else in A)

Two empirical unknowns block the first usable row. Resolve **before** building the
producer (OQ-B, OQ-C; both CRITICAL):

- **A0.1 — Completion field (OQ-B).** Inspect a live Claude `Stop` payload. Which
  field reliably flips `execution.status` `partial`→`completed`, replacing the
  absent `last_assistant_message`? Prefer a `transcript_path`-derived completion.
  *Exit:* a named, present field documented.
- **A0.2 — `run_id` stability (OQ-C).** Confirm empirically over a two-turn session
  that `session_id` + turn-counter is stable and monotonic (two turns → two
  distinct `run_id`s so dedupe holds). *Exit:* confirmed derivation rule.

> If A0 fails, Phase 1 produces **zero usable rows** — "fits now ≠ works now"
> (R-01, R-02). Do not proceed to A1–A3 on an unverified payload assumption.

### A1 — Patch Codex-coupling in the canonical hook scripts (D3, M6a) — CRITICAL

Edit `framework/observability/scripts/arcanum-hook-user-prompt-submit.sh` and
`…/arcanum-hook-stop.sh`:
- replace `.turn_id // "unknown-turn"` `run_id` derivation with the Claude-native
  rule from A0.2 (every Claude turn currently collapses to one `run_dir`,
  overwriting `pending-envelope.json`, tripping identical dedupe keys);
- replace the `.last_assistant_message` completion test with the A0.1 field
  (today every dispatch logs `partial`, firing a false-positive reflection storm
  at threshold 3, `config.json` `related_workflow_gaps: 3`).

### A2 — Emit a Claude hook surface from the generator (D3, M6b) — CRITICAL

Extend `tools/bootstrap_arcanum.sh` (today only emits the `.codex/` surface; the
`claude_root` branch writes `CLAUDE.md` + skills but **no settings hooks block**)
to also write a `.claude/settings.json` hooks block (~25 lines) wiring the three
events `UserPromptSubmit` / `PostToolUse` (matcher `Bash|apply_patch|Edit|Write`) /
`Stop` to the patched scripts. Regenerate; confirm the block lands.

### A3 — Build the dispatch-envelope-producer Formula (D1, OQ-A)

~60-line Formula: writes a conformant `invocation-envelope.json` (template
`framework/observability/templates/invocation-envelope.json`) carrying authored
typed extensions `goal` / `angle` / `anti_bias` / `exit_reason`, then calls
`observe-invocation.sh --envelope <path>`. Map `started → "partial"`,
`closed → "completed"` (dedupe key `dispatch-<id>:close`). This is the absent head
of the emit chain (M2) — `register-dispatch` writes only
`telemetry/agents/subagents-dispatch.yaml` and never calls the writer.

### A4 — Scaffold the ledger dir canonically (D2, M3)

Materialize `signals/` + `reflection-state.json` via the canonical
`observability-setup` Formula (gives a *managed* `reflection-state.json`), not bare
`mkdir+touch`. Low stakes — the writer self-heals the dir at
`observe-invocation.sh` `mkdir -p` — so this is correctness-for-counters, not a
blocker (OQ-E).

### A5 — Decouple the producer from skill-detection (D4, OQ-F)

Drive the producer from the **dispatch envelope/record**, not prompt-side skill
detection (which reads only `.agents/skills` — 26 of 46 skills — so `.claude/skills`
incl. `dispatch-spec` is invisible). Recommendation, not a blocker.

### A — Exit gate (Definition of Done)

One real Claude dispatch produces a matched `started`+`closed` pair in
`signals/sigil-invocations.jsonl`, `closed` carrying `status:"completed"` and the
authored extensions; no `partial`-storm; dedupe holds across two turns.
**Out of scope:** L2 (wave) and L3 (agent) receipt rows — they need the Craft Stage
Receipt YAML, a later increment (R-07 closed; findings:30).

## Work-stream B — dispatch-spec schema (Phase 2)

**Goal:** give the route spec a band above steps and a named, reusable strategy —
without copying sigil internals. Edit target throughout: **canonical**
`formulae/dispatch-spec/` (schema `dispatch.schema.json`/`.yml`, `SKILL.md`,
validator `scripts/validate-dispatch.py`, `development/fixtures/`) — never the
generated `.claude/skills/dispatch-spec/SKILL.md`.

> **A schema field with no validator rule + fixture is inert** — the validator
> "neither requires nor rejects" it (M4). Every B step ships field **and** rule
> **and** fixture together, or it is not done.

### B-2a — Additive, NO cross-repo decision (ship this)

- **B1 — Wave band (D5).** Add optional `waves[]` grouping wrapping `steps[]`, each
  wave carrying `wave_id` / `lane` / `intent` + typed edges. Existing routes stay
  valid (steps still validated by Rules 3–7). Add `wave_id` FK into the lifecycle
  receipts (Rules 23–25) for L2 logging. Absent `waves` → nothing breaks.
- **B2 — `strategy_ref` (D6).** Add `strategy_ref` on the existing
  `subagent_strategy` block (already carries
  `roles`/`parallelism`/`join_policy`/`receipt_requirements`), pointing at a
  colocated `formulae/dispatch-spec/strategies/<name>.yml`. **Create that dir**
  (absent today). Validator rule: a present `strategy_ref` must resolve to an
  existing strategy file. Absent `strategy_ref` → nothing breaks.
- **B3 — Wave-carried vocab (R30-free).** `loop_cap` + `verdict` on waves; L1/L2/L3
  row schema; `verdict` vocab `pass | flag | block` (findings:38).
- **B4 — Mode-conflation cleanup, minimum safe slice (R-05).** Drop the 4
  function-words (`distill`/`synthesis`/`validation`/`decision`) from the Rule 3
  `pattern` enum, **require them in `roles[]`** (tightening Rule 21); move the 2
  overlays (`xray`/`toy_game`) to Rule 12. **Defer** `route`/`sequential`/`handoff`
  to 2b — entangled with the Connection/edge layer (findings:39).

**B-2a honesty flag (D7, CRITICAL — non-negotiable):** 2a lands as **structure
only**. The band's governance teeth — the `reviews`/`reopens` review-wave
semantics — partly need 2b. Name it out loud in the schema docs: *bands + strategy
typing under-deliver the review-loop story until 2b clears the Vlad gate.* Do not
ship 2a implying the review-loop is governed.

## Boundary note (how this relates to the private subagents-strategy work)

This plan touches **public `arcanum`** canonical sources only — generic
observability wiring and generic route vocabulary; **nothing private leaks**.
`strategy_ref` (B2) is the *seam*: a later private `subagents-strategy` definition
can be referenced by id from a public route, while the strategy's judgment/law/
ledger stay in the private parent. The two efforts compose through that thin
string and are otherwise independent.
