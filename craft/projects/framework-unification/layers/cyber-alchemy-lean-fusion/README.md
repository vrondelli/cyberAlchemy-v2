# CyberAlchemy × Lean Residue — Fusion

This project seed is for fusing two things you already own into one tool for
*creating things*:

- **Arcanum / CyberAlchemy** (`arcanum/`, `cyberAlchemy/`) — the capability
  **lifecycle machine**: vague intent → reusable sigil/spell, with observability,
  experiment harness, installer, and Pass/Flag/Block gates. Its tension/quality
  layer is governed by **prose** (qualitative).
- **domainspec-lean-formalization** (sibling repo) — the **typed-residue
  epistemic core**: the subset rule (claim ≤ proof), a typed residue object
  (`FunctorialResidueStructure.lean`), adversarial precedent gates, collapse-test,
  and Brier scoring (`predict`).

**One-line thesis.** Arcanum has the skeleton and organs (fabricate + promote);
the Lean repo has the immune system (refuse inflation + book the loss *with a
type*). The fusion fills empty slots on each side — engineering, not metaphor.

## Starting Point

- Design packet: `DESIGN.md` — the fusion map, the honest-typing line, and the
  collapse-test that decides whether this is real or a rename.
- The load-bearing open problem lives in `DESIGN.md §5–§6`: *what TYPE does an
  artifact-level residue carry so it mechanically fires the subset-rule gate?*
  Until that is answered, only the `subset-rule` gate (layer 1) is honest to build.

## What this project is NOT (yet)

Nothing here is promoted to Arcanum's registry or to the Lean repo. The
residue-ledger is the **goal**, not a built artifact — it is gated behind the
type question above. Do not write the ledger as free-text "what we dropped"; that
collapses it to Arcanum's existing `residuality-spec` (see `DESIGN.md §5`).
