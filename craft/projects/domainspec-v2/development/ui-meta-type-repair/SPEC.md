# UI Meta-Type Evidence Repair Specification

## Purpose

Repair the evidence machinery exposed by UIF-010 so later experiments can
produce reproducible, reviewable evidence. This package does not repair a
candidate by declaration and does not decide UI meta-type identity.

## Source Contract

- Accepted research: `research/2026-07-11-findings-repair-architecture/findings.md`.
- Existing zero-survivor result: `../ui-meta-type-formalization/replication/findings.md`.
- Inventory precedent selection: `research/2026-07-11-findings-repair-architecture/INVENTORY-LOOKUP.md`.

All nine current UI candidates remain deferred. Prior evidence is immutable.

## Outcomes

The package shall make seven bounded contracts implementable:

1. A versioned nonempty-value rule without changing `attribute-present`.
2. An immutable mutation ledger with a mandatory 165-case base.
3. A two-sided reroute receipt with explicit external-owner pending states.
4. A conjunctive formation-evidence dossier.
5. A provenance-preserving corpus receipt.
6. A relationship-owner handoff packet.
7. An append-only orchestration index with deterministic mechanical replay.

## Invariants

- Evidence completeness is not semantic identity.
- Source rejection is not destination acceptance.
- DS-D8 endpoint use is not DS-D1 formation authority.
- `EVIDENCE-COMPLETE` opens a later route only.
- Content identity and generation lineage are separate.
- A missing or disputed hard dossier conjunct yields `DEFER`.
- No run overwrites prior UIF evidence.
- Candidate, validator, DS-D1, and DS-D8 mutation occurs only in a later,
  explicitly selected Task Session SWU.

## Acceptance Criteria

| ID | Criterion |
| --- | --- |
| AC-01 | Every record has a versioned contract, stable ID, semantic content digest, and separate lineage. |
| AC-02 | Markdown and generated-instance paths agree on normalized outcome and stable violation code. |
| AC-03 | The mutation base contains 52 deletion, 52 empty, 52 whitespace, and 9 wrong-fixed cases. |
| AC-04 | Reroute evidence records independently executed source and destination outcomes. |
| AC-05 | Corpus facts are immutable and reviewer projections are separate. |
| AC-06 | Relationship packets name an owner and prohibited inference but resolve no owner question. |
| AC-07 | Dossier evaluation is conjunctive, typed, and defaults to `DEFER`. |
| AC-08 | Replay is mechanically deterministic for frozen inputs and preserves every generation. |
| AC-09 | Integrated validation proves package behavior without changing candidate status or authority. |

## Prohibited Inferences

- A passing rule proves a type.
- The 165-case base is complete mutation evidence.
- A label, filename, framework symbol, or authored criterion is an independent witness.
- A weighted score can replace a missing hard gate.
- `not-observed` means absent.
- An owner acknowledgement means an owner decision.
- A deterministic index is an authority engine.
- This work-pack authorizes promotion or production activation.

## Scope

In scope: development contracts, fixtures, generated evidence, replay tooling,
owner handoffs, and package audits. Out of scope: candidate promotion,
canonical definitions, DS-D8 signature changes, semantic execution, and
rewriting accepted UIF history.
