# L2 Backend Running Through the CLI

## Decision and Boundary

After this layer, we know whether the complete compiled backend executes coherently through `domainspec run` without using generator self-checks as its behavioral oracle.

- Minimum working unit: stable runtime contract, deterministic in-memory provider, CLI command, full corpus coverage, and one independent non-generated target.
- Operator outcome: execute an Operation or Query from DomainSpec source and receive a typed runtime receipt.
- Risk reduced: generated bytes are tested as behavior rather than treated as proof of behavior.
- Main costs: runtime interfaces, deterministic state/effect orchestration, CLI loading/execution, coverage binding, and an independently authored comparison target.
- Boundary: durable infrastructure and failure recovery remain L3.

## CAV2-D65 Chain Accounting

| D65 stage | L2 requirement |
|---|---|
| Canonical definitions | Select runtime-relevant DS-D1/DS-D8 meanings and the runtime contract meanings already within the adopted capability. |
| Product Capability | `domainspec.meta-type-semantic-enforcement` explicitly includes bounded native runtime observation. Any broader product outcome requires a separate owner decision. |
| Business ontology | Preserve compiled contract → native realization → observation → conformance-evidence relations. |
| Authored source | Execute the frozen L1 complete backend corpus; runtime configuration cannot add semantic facts. |
| Compiled graph/system ontology | `run` consumes the certified compiled project graph, not raw generator conventions. |
| Exact implementation binding | In-memory provider and independent target are exact candidate bindings, each using the required one-helper authoring/join rule when materially created or revised. |
| Conformance evidence | Runtime receipts, coverage binding, typed failure cases, and independent-target semantic mutants. |

## Work and Deferral

- R01 runtime invocation contract → R02 in-memory provider → R03 `domainspec run`.
- R04 complete runtime coverage and R05 independent target may then proceed in parallel.
- Defer PostgreSQL, broker choice, outbox relay, leases, retries, quarantine, recovery, and production effects.

## Exit Evidence and Promotion

- A fresh process executes every backend type and relationship at least once through the certified graph.
- Unknown entries, invalid inputs, and runtime failures produce typed nonzero results.
- Runtime receipts remain distinct from static and formal receipts.
- Promote only after R04 and R05 pass; otherwise keep the failure within L2.
