# Whisper composition — interactive operational roadmap

Status: candidate transport, human-comprehension revision implemented

## Intent substrate

- Objective: let an internal owner understand what is done, what is next, what is
  blocked, why it matters, and where the proof lives.
- Audience: DomainSpec-v2 engineering, product, semantic, validation, and research
  owners already authorized to view the private repository.
- Resonance: exact, calm, dense but navigable; no launch theater or confidence inflation.
- Relevance: current gate, dependency graph, node proof/exit/omission, active research
  frontiers, Body War sequence, and refresh provenance.
- Trajectory: orient -> inspect the whole -> select a node -> inspect frontiers -> follow
  the critical sequence -> verify sources.

## Candidate transports

1. Markdown-only status report — precise but poor for dependency traversal.
2. SVG export — graph-like but weak for filtering, details, and maintenance.
3. Interactive self-contained HTML — selected because it can show the whole and reveal
   evidence on demand while remaining a generated local artifact.

This is not a presenter-led narrative. It is a self-serve operational roadmap, so a
live three-moment voice audition is not applicable.

## Composition contract

- Opening surface: `production authorization: no`, Craft gate, stage, and next move.
- Main surface: dependency graph with state and release-timing filters.
- Detail surface: owner route, dependencies, artifacts, proof, negative controls, exit,
  omission, next move, evidence provenance, and reopen trigger.
- Research surface: frontiers joined to Craft gap state and their blocked nodes.
- Pilot surface: exact ordered Body War critical steps.
- Trust surface: source paths, input fingerprint, and refresh/check commands.

## Language constraints

Allowed: `closed prerequisite`, `blocked open`, `planned`, `seeded`, `candidate
projection`, `continuation authority`, `production unauthorized`.

Forbidden: `production-ready`, `complete platform`, `formal equivalence` outside the
bounded retraction claim, `full coverage` without the defined obligation denominator,
or any implication that graph color changes Craft state.

## Surface mapping

| Surface | Audience-visible | Detail-on-demand | Authoring-only |
|---|---|---|---|
| Header | claim boundary, authorization, fingerprint | refresh help | template slots |
| Graph | id, title, state, timing, dependencies | full node contract | normalized coordinates |
| Frontiers | state, owner, blocks, condition | trigger and Craft match | join diagnostics |
| Critical path | ordered step ids and labels | linked node details | array invariants |
| Sources | repository-relative links | source roles | loader implementation |

## Validation plan

- Source fidelity: all displayed state originates in the normalized payload.
- Structure: every edge and frontier target resolves.
- Trajectory: keyboard navigation reaches filter, graph node, detail, frontier, and
  critical path without requiring a mouse.
- Claim safety: production unauthorized remains visible at the top and in provenance.
- Transport status: stays candidate until real users demonstrate that it reduces
  reorientation or stale-status errors.

## Human-comprehension correction — 2026-07-14

The first implementation preserved source fidelity but exposed the control model before
the reader had a usable mental model. The result was technically inspectable and still
too expert-facing. The user's correction changes the composition rule from `dense but
navigable` to `plain-language orientation first; exact contract on demand`.

### Smallest coherent unit

- Resonance core: calm, direct, and honest about what is not done; no governance theater.
- Relevance core: in about 30 seconds, a reader should find current release status, the
  next concrete action, the five phases, and the reason Body War matters.
- Trajectory core: situation -> now/next -> five phases -> exact dependency inspection ->
  bounded research questions -> Body War proof -> sources and refresh.

### Revision candidates

1. Add a glossary while retaining the expert-first dashboard — rejected because it
   makes the reader translate every sentence.
2. Replace the exact graph with a simplified story — rejected because it would hide
   proof and dependency obligations.
3. Add a human translation layer and preserve the exact contract under progressive
   disclosure — selected because it lowers cognitive load without weakening authority.

### Selected composition

- Open with `The direction is agreed. The release is not.`
- State `done`, `now`, and `then` before counts or dependency mechanics.
- Explain the roadmap as five phases before showing the exact graph.
- Give every FPR node, research frontier, and Body War critical step a human title.
- Translate raw status values into sentences while retaining raw values under `Show
  exact technical contract`.
- Default node selection to the first open step rather than the closed decision.
- Preserve the production-unauthorized boundary, exact fingerprint, Craft state, source
  next move, proofs, negative controls, provenance, and refresh behavior.

### Proof status

- Structural and source-fidelity validation can pass mechanically.
- Human comprehension remains `flag` until an intended reader can correctly answer:
  where are we, what is next, why can we not release, what does Body War prove, and where
  does the exact contract live?
