# Design context

## Activation

- Define inputs: `SPEC.md`, `REQUIREMENTS.md`, `GLOSSARY.md`, and the accepted decision.
- Define status: authored and internally validated; no implementation evidence claimed.
- Design mode: normal, not discovery.
- Target footprint: the immutable Define outputs plus `DESIGN.md` and planned witness contracts.
- Human actors: internal CLI operator and release/verification owners.
- Rendered semantic UI: none.

## Design obligations

1. Preserve all six baseline views.
2. Keep CLI/profile/conformance/release authority separate.
3. Select architecture extensions for security, state/failure, integration,
   migration, data lifecycle, performance, and validation.
4. Define closed result, pagination, project-root, package, and evidence-binding contracts.
5. Mark every fixture/validator as planned and unexecuted.
6. Produce one independently extracted denominator and unchanged two-pass selection.

## Source contracts

The Design consumes the exact hashes recorded in `DESIGN-SCOPE-MANIFEST.json`.
Current implementation bytes are precedent and migration input, not the target
architecture or proof that the design exists.
