## What a Rule receives

A Rule receives plain typed facts, not a factory's branded snapshot:

```typescript
ruleBalance({
  customer: {
    id: "customer-a",
    label: "Alex",
    balance: {amount: "18446744073709551614", currency: "GBP"}
  },
  cap: "18446744073709551615"
});
```

This example reads the explicitly declared property path and compares the
normalized amount with the supplied cap. Named declarations retain their
semantic role: Entity equality uses declared identity, while Value Object
equality uses every field. All Entity state is validated even when it is not
part of identity. A Rule does not construct an Entity, claim provider ownership,
execute a referenced invariant, resolve a reference or check database existence.

Inputs are closed plain/null-prototype data objects and dense plain arrays.
Accessors, hidden/symbol/extra fields, missing required fields, sparse arrays,
wrong tags and unsafe numbers reject. Optional data fields may be omitted and
normalize to null. All formal Rule arguments remain required, including those
with optional types. Inputs are copied and frozen without freezing caller data.
This is a data boundary, not a sandbox for arbitrary JavaScript Proxy traps.

UInt64 accepts canonical decimal strings, in-range bigint, and safe integer
numbers, storing bigint throughout. No Number round-trip or Unicode
normalization is introduced. Empty strings, zero, null, distinct Unicode
representations and different sum tags remain distinct.

## Generated code and composition

The emitter specializes native TypeScript aliases, field normalizers, equality
keys and direct expressions from the checked graph. It emits no runtime graph,
expression interpreter, record-schema interpreter, class or invariant executor.
Static typed combinators handle optional values, sequences and sums.

List equality retains order and occurrences. Input sets reject duplicates under
the declared element equality and normalize their order. List property
projection retains repeated values; set projection produces a duplicate-free
image using the projected field's equality. Explicit `to_set` deduplicates
lists. Entity-set membership is identity-based; VO membership is value-based.

The supported expression operators remain `all`, `any`, `not`, `eq`,
String/UInt64 `lt`, `contains`, `set_equal`, `exists`, `exactly_one`,
`unique` with an identical-path key, `to_set`, and declared `rule_ref`.
Ontology property selectors lower to checked field names. Declared payload-free
Enum variant expressions are supported. Imported Rules receive normalized facts
through explicit arguments and normalize them under their own checked types.

Factory v12 validates field shapes and ownership first. It then emits explicit
fact projections for each validator argument: owned Entity/VO snapshots expose
their fields recursively; Enum and sum cases expose only tags and payloads.
No branded snapshot is passed directly into a Rule. Optional and collection
boundaries are preserved. Required owned paths can end at any exactly matching
supported type; they cannot traverse optional, collection or sum boundaries.
There is no automatic whole-factory parameter.

Base and extension validators remain additive and local. Every construction
route applies them after normalization. Failed ownership checks happen before
any Rule runs. Value Object invariant coverage, Entity identity preservation
and existing reference descriptors retain their previous contracts.
