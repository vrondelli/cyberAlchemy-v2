# Descriptor-bound Calculation generation

Date: 2026-09-09. PCR-06 product construction, following the checked DSR-011
composition boundary. Authority effect: none. The full working-CLI goal remains
active; this is not public CLI integration or profile admission.

## Implemented behavior

`planConfiguredCalculations` accepts a registered checked composition boundary,
its exact digest, explicit Calculation roots, a portable module root, TypeScript
and the existing `domainspec.typescript-exact-uint64/v1` value selection. The
configuration, base/TypeScript profile and new candidate contract bytes are
pinned and checked before producing any artifacts. Planning is in memory only.

Each selected typed Calculation produces two modules:

```text
commerce/features/alpha/src/domain/calculations/
  compute-add.provider.ts   pure typed arrow, input checks, static arithmetic
  compute-add.ts            frozen callable with immutable descriptor binding
```

The descriptor binds the authored ontology Calculation, exact typed input/result
contract, source evidence, provider identity and provider byte digest, failure
set, rounding, numeric realization and descriptor digest. Nested descriptor
values and the exported callable are frozen. Separate provider and binding
artifacts avoid a self-referential provider hash. No new domain input/output
concept is invented from a TypeScript type; the authored scalar type and source
contract remain the limit of those bindings.

For an authored addition, the provider executes the equivalent of:

```typescript
const p0 = normalize(d["left"]!.value);
const p1 = normalize(d["right"]!.value);
const v0 = checked(p0 + p1);
return v0;
```

All declared inputs, including unused inputs, are normalized once before
arithmetic. Input objects must have the exact own enumerable data properties.
Plain and null-prototype objects work; inherited values, accessors, hidden or
extra properties, symbols and coercible boxed values reject. The tested accessor
and coercion callbacks are not executed.

Arithmetic produces eager primitive `bigint` values across UInt64's full range.
Inputs may be bigint, safe integer numbers or canonical unsigned decimal
strings. Source `typed-calculation/v1` literals remain safe JSON integers.
Addition, subtraction and multiplication check every intermediate result.
Division preserves the declared floor, ceil or reject policy. Underflow,
overflow, division by zero, inexact division and invalid inputs remain distinct
declared failures. There is no runtime expression interpreter, hidden query,
Operation execution, clock, random source or application effect provider.

## Preserved meanings and compatibility

The pinned TypeScript overlay requires a descriptor-bound pure-value Calculation;
a bare arrow is not treated as sufficient conformance. The existing profile
files and historical admission records are unchanged. This implementation is a
new construction candidate, not activation of their historical provider status.

The old configuration's DSR-011 dependency is discharged for this explicit
planner only by its registered boundary input. Its original blocker field is
not edited. The current project compiler still requires a lawful `calculates`
edge to a real Operation. That edge does not execute the Operation, and this
planner neither creates a support Operation nor changes source admission.
Standalone source admission remains DSR-013 work.

Changing module layout preserves provider and binding content. Changing root
order preserves the whole plan; extending the selected roots preserves existing
module bytes. Plans survive source relocation because they consume the checked
snapshot, not a second filesystem read. Existing project-build and exact-number
renderers retain their behavior and defaults.

## Validation

The five focused Calculation tests pass. Final five-suite regression passes
**32/32**, zero failures or skips, in **35.00 seconds**. Suites: configured
Calculations, composition boundary, exact UInt64, project composition and
project model. CLI source typecheck, 39-row frozen catalog, 31-signature
relationship authority and integration-profile checks pass. The final source
identities below are the tested bytes.

The new tests compile generated TypeScript using the pinned TypeScript 7.0.2
toolchain image, execute native JavaScript, and compare small arithmetic truth
tables plus full-width boundaries. Separate processes return the same fully
consumed maximum-width value. Tests also cover source/selection drift, forged
boundaries, missing canonical relationships, frozen descriptors, rejected input
shapes and preservation of existing generated bytes.

The independent observer does not import the generator or execute target source.
It pins the normalization support perimeter, decodes the small generated
arithmetic grammar, reconstructs the authored expression and checks postorder
instructions and complete primitive return. The binding observer checks exact
provider and descriptor hashes, the supplied checked contract, and the closed
immutable wrapper grammar. Expected bindings come from the checked-plan caller,
not from metadata claimed by the target.

Six changed providers still compile but fail observation: changed arithmetic,
wrong returned value, clock access, randomness, global write and a Boolean
masquerading as bigint. Additional controls reject changed normalization support,
detached bindings, stale descriptor/provider bytes and mismatched contracts.
These results cover inert inputs and ordinary standard intrinsics; they do not
prove purity for hostile Proxies, modified realms or arbitrary TypeScript.
