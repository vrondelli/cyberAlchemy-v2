### Compatibility details for continuation

- The private reference reads checked source expressions; type-only compiler
  interfaces do not provide its expected answers. Its low-level fixture entry
  does not certify arbitrary contracts. Project verification must use the
  registered-graph entry and the subsequent independently checked native binding.
- Parameterized Mappings are evaluated per call. Zero-input declarations cache
  successful computation only within one invocation. Query filtering precedes
  all projection calls. Neither record-shaped output nor a structural core
  binding performs implicit Value Object validation.
- Authored `uint64` failures preserve `FUNCTION_UINT64`. The selected native
  Calculation surface additionally accepts safe integer and canonical numeric
  string representations. Its uncoded input TypeError becomes
  `EVALUATION_FAILED` in composition observations; arithmetic errors retain their
  existing named codes. The reference now preserves this distinction.
- Reference `source_sha256` currently identifies authored `source_text` bytes.
  Existing composition-plan metadata uses `source_sha256` for canonical whole
  `composition.source`. The next binding descriptor must distinguish these
  identities explicitly, not compare the differently scoped hashes as equals.
- Input capture and detached evidence have separate bounded budgets. Exhaustion
  raises `CompositionReferenceUnavailable`; it never returns a partial passing
  trace or masquerades as an expected domain failure. These verifier limits do
  not change the application language or add production input validation.
