# Order / FindOrder — DomainSpec-only vertical

Status: tested candidate example. Alch reconciliation is deferred by the user.

This example declares an Entity, a read-only Query and one canonical reads edge:

```text
FindOrder (Query) --reads--> Order (Entity)
```

Order owns a stable `order_id`. `FindOrder` filters an explicitly supplied snapshot by that identity,
returns at most one match, and projects only `order_id` and `status`. It does not fetch from a database.

```js
findOrder(
  [{ order_id: "order-1", status: "submitted", internal_note: "not public" }],
  { order_id: "order-1" }
)
// [{ order_id: "order-1", status: "submitted" }]
```

## Repeat the checks

From DomainSpec v2's `impl/cli` directory:

```sh
node --import tsx ../../development/reconciliation-v1/verticals/entity-query/run.ts
```

The runner uses the existing CLI source through its transitional test loader. Generated TypeScript is
compiled using the locally installed, repository-pinned toolchain image, with networking disabled; the emitted
JavaScript is then executed with Node. No image is downloaded and no dependencies are installed. Temporary
builds and mutated fixtures are created under a fresh `/tmp/dsr007-order-query-*` directory and removed afterward.
Successful output contains the report, normalized graph and generated bytes; exit is nonzero if any check fails.

The generated directory is an exact DomainSpec build with its original receipt. Do not hand-edit it; the
CLI `verify` command detects drift. The evidence is tied to the current source and compiler bytes, not a
claim that this entire working tree or a newly published package is accepted.
