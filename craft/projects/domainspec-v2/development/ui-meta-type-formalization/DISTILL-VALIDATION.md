# Distill Validation: UI Meta-Type Formalization

## Intent And Budget

- Target context: a parallel candidate package for formalizing 11 UI labels.
- Output: specification, architecture, experiments, layering, and executable
  work-pack.
- Optimization goal: smallest evidence unit and first proof that preserve
  per-type meaning without forcing promotion.
- Mode: Standard, assumed because no explicit Distill budget was requested.
- Budget: one proposal track, Proposer/Balancer role simulation, two recursive
  rounds, one reconciliation.

## Discovery Baseline

- Current state: all 11 UI labels are formation-deferred.
- Evidence: candidate prose and DS-D8 pressure exist; per-type criteria,
  fixtures, correction contracts, portability, and promotion evidence do not.
- Constraint: structural public validation only; no semantic execution or
  private derivation.
- Evolution pressure: the package must support parallel type investigation and
  later owner decisions without preselecting survivors.

## Role Conversation Trace

### Round 1

- Proposer claim: formalize all 11 labels through one schema/card/fixture plan.
- Evidence/assumption: the existing backend method can be reused and current
  DS-D8 signatures provide specimen pressure.
- Balancer objection - hidden confirmation bias: an all-schema plan assumes all
  labels deserve node status and cannot demonstrate a collapse result.
- Reconciliation: add a counterbalanced E0 method proof before broad fan-out.
  Use Form versus Component as plausible survival pressure and Adapter versus
  Mapping as collapse pressure. These are experiment contrasts, not promotion
  ordering.

### Round 2

- Proposer claim: after E0, run one independent worker per type for speed.
- Evidence/assumption: fixtures and result records can use disjoint paths.
- Balancer objection - coordination and abstraction leakage: per-type workers
  could edit shared validator rules, drift protocol versions, and self-author
  evidence that clears their own candidates.
- Reconciliation: partition all labels into three disjoint experiment lanes,
  join through one adjudication SWU, allow per-type candidate authoring only for
  adjudicated survivors, and serialize shared validator work. Independent
  replication/adversarial review follows candidate authoring.

## Smallest Coherent Unit

One UI candidate hypothesis plus one result record containing constructibility,
positive, malformed-negative, nearest-neighbor, graph-coherence, portability,
repeatability, provisional outcome, evidence, correction route, and residue.

This is smaller than a schema package but large enough to decide whether schema
authoring is justified. Splitting it further loses non-collapse or correction
meaning.

## First Executable Proof

The first meaningful package proof is the three-SWU E0 sequence:

1. UIF-001 freezes the complete hypothesis and neighbor map.
2. UIF-002 freezes the protocol, corpus contract, and expected fixtures.
3. UIF-003 runs the two counterbalanced pairs twice.

UIF-001 is the first executable SWU; E0 is the smallest promotion-to-W1 gate.

Tournament mode was skipped: the user asked for one parallel package, and the
known tension is better tested by counterbalanced experiments than by competing
whole-package architectures.

## Closure And Recomposition

- Responsibility closes: each result decides candidate evidence status only.
- Inputs close: hypothesis, specimens, criterion, active DS-D8 refs, protocol.
- Outputs close: normalized result, correction route, residue, next owner.
- Recomposition: result records -> lane receipts -> 11-row adjudication ->
  survivor artifacts -> replication -> owner packet.
- Hidden glue is avoided by one protocol version and explicit Task Session
  receipts.

## Deferred Complexity

- Canonical promotion and DS-D8 changes.
- Semantic solvers, custom criterion DSL, and private derivation checks.
- Production-scale corpus infrastructure.
- Per-framework canonical variants unless portability experiments justify them.

## Tension Ledger

| Tension | Disposition |
| --- | --- |
| Formalize versus force novelty | resolved by multi-outcome adjudication and E0 collapse lane |
| Parallel speed versus protocol drift | resolved by frozen protocol, disjoint writes, and parent join |
| Edge evidence versus formation authority | resolved by exercised support plus explicit authority boundary |
| Generic UI ontology versus framework vocabulary | remains evidence-dependent; portability owns the decision |
| Real-corpus availability | flagged; UIF-002 owns selection and provenance |
| Promotion decision | intentionally external; definitions-governance owns it |

## Premortem

Likely failure: every label gets a schema because workers optimize for artifact
completion instead of discrimination. Guardrail: E0 must demonstrate a credible
collapse result, UIF-007 owns outcomes, and UIF-008 cannot author schemas for
non-survivors.

## Frame Expiry

This optimization point expires if the canonical UI label set changes, DS-D1
adopts a different formation/non-collapse rule, DS-D8 UI signatures materially
change, or the public/private validator boundary is revised. In those cases,
refresh hypotheses and rerun E0 before continuing.

## Verdict And Navigation

Verdict: `flag`. The package is coherent and L0 is executable. Real-corpus
selection and external promotion authority remain named gaps, so the package
cannot claim promotion readiness.

Start at `WORK-PACK.md` -> `SWU-UIF-001`. Use `EXPERIMENTS.md` for protocol,
`ARCHITECTURE.md` for boundaries, and task files for execution details.
