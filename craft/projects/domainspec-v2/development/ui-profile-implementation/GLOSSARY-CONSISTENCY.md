Status: `pass` for planning.

| Term | Meaning in this package | Existing owner boundary |
| --- | --- | --- |
| required-by-design | the UI concept must be expressible by the DomainSpec UI profile | not canonical activation |
| representation | node, role, relationship, projection, alias, or split placement | DS-D1/DS-D8 owners decide canonical placement |
| mechanical admission | the development profile parses, validates, compiles, traverses, and rejects named negatives | not release admission |
| synthetic calibration | controlled fixtures that test implementation and separation | not independent real-corpus proof |
| empirical confidence | append-only breadth and portability assessment | cannot add/remove authority automatically |
| authority packet | exact proposed changes and residue for owners | not the changes themselves |

No existing canonical term is redefined. The package introduces development
status vocabulary only and keeps `active`, `candidate`, `deferred`, and
`release admission` under their existing owners.
