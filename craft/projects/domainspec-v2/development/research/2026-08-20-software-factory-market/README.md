# DomainSpec v2 Software-Factory Market Research Tower

Status: `closed-local-research`

Promotion scope: `local-research-only`

## Purpose

Establish how the agentic software-development market stands on 2026-08-20,
then determine which product, runtime, control, and evidence patterns DomainSpec
v2 should borrow, adapt, reject, or leave to an adjacent owner if it is to work
as a software factory as well as a typed specification system.

The research does **not** assume that “v2 is a software factory” means placing
every runner, agent, UI, or authority mechanism inside the DomainSpec v2 codebase.
One of the central questions is which responsibilities belong to DomainSpec v2,
which belong to Arcanum or another runtime, and which are product-facing
composition rather than new ontology.

## Research Questions

1. What product categories, buyer expectations, maturity signals, and unresolved
   risks define the 2026 agentic software-development market?
2. Which capabilities are now table stakes, which are differentiating, and which
   remain mostly marketing or preview-stage claims?
3. What does DomainSpec v2 already own or evidence that is relevant to a software
   factory, and what is only planned, candidate-local, blocked, or absent?
4. Which external patterns should v2 borrow carefully, expose through adapters,
   build from existing owners, treat as analogy only, or reject?
5. What is the smallest evidence-producing experiment needed for each promising
   pattern before design or implementation is justified?

## Source Boundary

- Market cutoff: `2026-08-20`.
- External product claims: official documentation, API references, security or
  architecture material, pricing/status pages, and release notes.
- Market signals: named survey or analyst sources with date, denominator,
  methodology, and caveat preserved.
- Local current-state authority: `projects/domainspec-v2/.craft/ledger.yml` at
  the digest recorded in `strategy-inventory-packet.json`.
- Local discovery: validated `.arcanum/inventory/index.json`, treated only as a
  non-authority read model.
- Prior direction: the Factory.ai handoff and its `FIX` review are inputs, not a
  DomainSpec v2 market conclusion.

## Non-Goals

- selecting, buying, integrating, or endorsing a vendor;
- changing DomainSpec v2 implementation, definitions, ontology, Craft state, or
  authority;
- changing or publishing public Arcanum;
- claiming production readiness, deployment readiness, novelty, market
  leadership, or measured productivity gains;
- benchmarking live vendor systems or sending repository material to them;
- treating successful agent execution as semantic validation or promotion.
