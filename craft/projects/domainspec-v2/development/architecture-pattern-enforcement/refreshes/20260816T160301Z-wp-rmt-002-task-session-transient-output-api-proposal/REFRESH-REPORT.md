# Task Session transient-output API proposal

The direct user selected Decision Gate Option A. This isolated proposal stages 33 changed targets: 11 canonical public Task Session files, 8 Codex projections, 8 Claude projections, and 6 dependent WP-RMT-002 plan files. No live target changed.

The generic public contract keeps durable `declared_outputs` one-to-one with material reconciliation and keeps mutation-admission baselines material-only. Version 1.3 adds a separate typed `transient_outputs` partition. Each transient must be repository-contained, collision/symlink/overlap checked, admitted in the execution union, touched-evidenced, cleanup-evidenced, and absent before the terminal receipt. Transient scopes are also disjoint by equality and ancestry from the run directory, plan admission ledger, deterministic pre-execution prerequisite ledger and resume receipt, executor receipt, durable outputs, and terminal receipt. The executor receipt remains exactly `<run-dir>/terminal-executor-receipt.json`. The live ticket is bound to checkpoint 04 and re-reads its exact request, controls, plan admission, ordered transient descriptors, and full write partition at status, launch/join, reconciliation, and commit without changing legacy non-transient ticket bytes.

The dependent proof preserves 70 SWUs and 74 dependency edges and maps exactly seven Cargo target directories through the candidate API. It does not select, admit, or execute a SWU.

Independent audit and fresh exact-byte owner acceptance remain open. `PROPOSAL-RECEIPT.json` must remain absent until that audit authorizes receipt creation.
