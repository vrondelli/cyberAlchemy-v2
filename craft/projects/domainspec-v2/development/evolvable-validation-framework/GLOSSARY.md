# Plain-Language Glossary

This is a package-local explanation for readers who are new to graph testing.
It explains the terms without changing the canonical DomainSpec or Arcanum
definitions.

| Term | Plain-language meaning | What to look for |
| --- | --- | --- |
| Graph | A small map of things and the links between them. | named nodes, named edges, source digest |
| Node | One thing in the map, such as a `Rule` or `Operation`. | stable ID, kind, source location |
| Edge | One link between two nodes, such as `enforces`. | from-node, to-node, registered signature |
| Relationship signature | The rule saying which kinds of nodes an edge may connect. | endpoint kinds and admission rule |
| Obligation | A check that follows from what the graph says. | rule type, source edge, deterministic key |
| Test case | A runnable question created from an obligation. | inputs, expected predicate, test ID |
| Binding | The adapter that tells a logical test how to run in a real harness. | runtime target, fixture, adapter, digest |
| Evaluator | The checker that decides whether the evidence satisfies a claim. | scope, inputs, verdict vocabulary |
| Receipt | A dated record of what was checked and what happened. | inputs, verdict, evidence, residue |
| Structural validation | Checking shape and allowed links, without proving business truth. | endpoint and schema failures |
| Local evaluator | Checks one node, edge, obligation, or test. | one graph fragment or one obligation |
| Graph-level evaluator | Checks a property involving several nodes or edges. | reachability, cycles, closure, composition |
| Source authority | The authored file that is allowed to define a fact. | registry, source YAML, source graph |
| Generated read model | A searchable copy derived from authority. | Inventory index, generated report |
| Proof boundary | The exact claim a receipt supports. | structural, execution, or semantic label |
| Negative mutation | A deliberately broken input used to show the checker rejects it. | changed endpoint, signature, or digest |
| `needs_formal` | An honest result meaning the structure exists but no formal executable predicate is available yet. | typed gap, not a pass |
| `O_spec` | The independent set of obligations expected by the specification. | produced outside the generator under test |
| `O_gen` | The obligations actually generated by the derivation engine. | compared with `O_spec` |

## How To Read The Example

Start with `Rule` and `Operation` as two nodes. The `enforces` edge says the
rule constrains the operation. Structural validation checks that this edge is
allowed. Derivation turns it into an obligation. A binding connects that
obligation to a fixture and harness. The test runs, an evaluator interprets
the result, and the receipt preserves enough evidence for somebody else to
replay the claim.
