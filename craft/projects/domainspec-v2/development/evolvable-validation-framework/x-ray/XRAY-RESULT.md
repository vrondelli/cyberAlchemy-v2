## Architecture Finding

The architecture is coherent as a candidate design because it separates four
ownership planes—Source, Derivation, Execution, and Evidence—and gives every
handoff a named contract and digest boundary. Its smallest proof is not broad
backend coverage. It is one `Rule --enforces--> Operation` edge that produces a
real TestCase, binds to an implementation, receives a scoped verdict, and leaves
positive and causal-negative receipts.

That proof does not exist yet. The current Task Session stops honestly at test
emission because the key-and-door Rule does not author the formal predicate or
fixture input needed for a real assertion. `DEC-GCP-001` remains pending in the
current decision artifact. Consequently, the x-ray does not claim graph
composability, S1 completion, backend completeness, or release readiness.

`DEC-GCP-002` is accepted and adds a second, independently closable proof. Once
the core and IOLM candidate substrate exist, `SWU-IOLM-DSC-A` consumes the exact
EVF handle and must preserve identity, direction, provenance, semantic bytes,
and graph/hierarchy/table parity in a fresh receipt. That consumer result cannot
change the core verdict. A later, separate `SWU-IOLM-DSC-B` reruns the same
machine contract over BTE breadth; the narrow receipt cannot substitute for it.

## Evidence And Inference Boundary

- Source-backed: the nine candidate contracts, four planes, explicit workflow,
  invariants, L0-L3 layering, accepted two-proof IOLM boundary, backend
  13-kind/16-signature target, and current blocked Task Session.
- Inference: the nine-contract seam is a viable evolvable framework boundary;
  consumer receipts should prove integration without becoming semantic
  authority; broad backend coverage should consume the proven L0-L2 seam rather
  than block L0.
- Not proven: end-to-end TestCase-to-Receipt execution, negative mutation
  sensitivity, a fresh IOLM consumer receipt, open-profile extensibility,
  graph-law evaluators, or complete consumer coverage.
