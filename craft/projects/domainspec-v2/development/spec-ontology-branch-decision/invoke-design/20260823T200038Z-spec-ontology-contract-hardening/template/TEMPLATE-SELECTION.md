# Template and Profile Selection

The DomainSpec specification architecture bundle remains the only eligible
primary profile. The hardening work changes who is proposed to hold roles, how
verification is assigned, and what exact package/receipt shapes are required;
it does not reopen the connected four-branch architecture.

- Selected template: `invoke.architecture`.
- Selected profile: DomainSpec specification architecture bundle.
- Six required views: context, high-level structure, low-level components,
  workflow process, decision flow, and dependency interface.
- Required companions: authority/trust, security, state/currentness,
  persistence, quality, integration, migration boundary, data lifecycle, and
  validation contracts.
- Tie: none.
- Inventory evidence: reused from the permitted prior Design receipt and
  confirmed against the current Invoke Design contract. The repository
  Inventory index was not re-read or revalidated by this bounded helper.
- Authority effect: `none`.

Define, UX, research, and execution-pack templates are not selected because
the architecture baseline and decisions already exist, no rendered human
surface is changing, no research blocker remains, and Plan/execution are
outside the authorization.
