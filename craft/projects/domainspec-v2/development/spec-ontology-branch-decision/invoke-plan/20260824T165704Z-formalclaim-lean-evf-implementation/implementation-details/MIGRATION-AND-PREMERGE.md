# Migration and Pre-merge Detail

Migration is additive and candidate-local. It preserves the @2 FOL semantics,
adds @3 multiformalism references, and authors only the canonical directions
`derived_from` and `formalizes`; inverse views are generated navigation. All
entries retain `authority_effect: none` and explicit source digests.

Pre-merge preparation inventories the complete repository diff, not only
DomainSpec paths. It freezes target branch, base, head, all changed bytes,
validation evidence with `status=pass` and exact head hashes, assigned
verification level, and fixed claim ceiling. The target branch must still equal
the frozen base and the base must be an ancestor of head. Advanced target,
partial inventory, stale validation, or any mismatch rejects.

The approval receipt remains outside its candidate digest. The validator checks
its exact bindings and response evidence but does not authenticate Victor. The
merge owner performs that human confirmation immediately before merge.
