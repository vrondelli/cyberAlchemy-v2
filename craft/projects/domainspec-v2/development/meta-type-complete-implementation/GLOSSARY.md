# Package Glossary

These terms are package-local unless an existing canonical reference is named.

| Term | Meaning | Authority posture |
| --- | --- | --- |
| MetaTypeInstanceIntent | Complete proposal input for one candidate meta-type. | authored candidate |
| CandidateOntologyPacket | Proposed definition card, catalog row, criterion, fixtures, relationship delta, and non-collapse case. | candidate only |
| OntologyAdmissionReceipt | Human-owner decision plus canonical validation evidence for one admitted or rejected candidate. | evidence of owner action, not authority itself |
| MetaTypeDesignClosure | Language-neutral behavior, data, state/effect, interface, failure, and obligation contract. | approved design input |
| ImplementationObligation | Stable, language-neutral property that a realization must witness. | selected profile contract |
| LanguageRealization | One TypeScript, Python, or Rust implementation and its native evidence. | implementation evidence |
| ObservationProjection | Language-adapter output containing provenance, observed facts, unsupported cases, and native evidence references. | generated non-authorizing evidence |
| NormalizedLanguageReceipt | Deterministic projection of native evidence keyed by obligation. | generated non-authorizing evidence |
| ParityReceipt | Comparison of three normalized receipts against one design digest. | generated non-authorizing evidence |
| complete-witnessed | All four gates passed for the bounded reference implementations. | not release or production readiness |

Canonical ontology and authority terms remain owned by `projects/domainspec-v2/definitions/` and `cyberAlchemy-v2/authority/`; this glossary does not redefine them.
