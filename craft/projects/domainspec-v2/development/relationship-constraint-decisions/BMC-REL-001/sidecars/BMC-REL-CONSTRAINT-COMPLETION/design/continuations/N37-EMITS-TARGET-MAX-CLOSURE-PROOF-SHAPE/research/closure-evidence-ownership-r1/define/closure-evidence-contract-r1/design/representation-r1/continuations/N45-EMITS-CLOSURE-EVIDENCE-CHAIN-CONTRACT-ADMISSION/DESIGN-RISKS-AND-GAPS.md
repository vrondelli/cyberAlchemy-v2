# N45 risks and gaps

| Risk or gap | Required containment |
| --- | --- |
| Partial admission looks usable | Reject envelope-only or receipt-only admission; the Design unit is the complete chain. |
| Compiler evidence is mistaken for completeness | Keep the consumer project owner as the only completeness declarer. |
| Evaluator receipt is mistaken for semantic authority | Bind prior owner receipts and keep evaluator authority evidence-only. |
| A historical receipt is treated as current | Keep currentness external and require exact selection. |
| Design admission is mistaken for implementation | Keep producer/evaluator implementation, packet/profile projection, and execution separately gated. |
| Candidate schemas are mistaken for canonical schemas | N45 governs a candidate Design target only; canonical placement remains later Plan/apply work. |

N45-A is selected. The next route is bounded Invoke Plan activation and authoring for one complete implementation work pack. The Plan-entry handoff keeps delivery-boundary approval, implementation-objective approval, companion-creation approval, validation strategy, lifecycle-owner approval, and template/profile selection explicit rather than inferring them from N45-A.
