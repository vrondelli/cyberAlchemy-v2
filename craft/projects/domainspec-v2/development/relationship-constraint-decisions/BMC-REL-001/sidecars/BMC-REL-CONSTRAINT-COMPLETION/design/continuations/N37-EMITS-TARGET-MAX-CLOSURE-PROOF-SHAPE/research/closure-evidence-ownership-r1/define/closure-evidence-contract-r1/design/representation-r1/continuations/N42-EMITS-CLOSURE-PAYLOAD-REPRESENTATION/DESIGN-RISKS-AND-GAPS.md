# N42 risks and gaps

| Risk or gap | Boundary |
| --- | --- |
| Inline payloads grow large | A is recommended only because no measured scale pressure is currently admitted; later evidence may reopen carrier design. |
| External manifest is mistaken for compiler authority | B/C references must be consumer-owned completeness payloads; generated projection evidence remains non-authoritative provenance. |
| Tagged union permits ambiguous dual forms | C requires exactly one closed carrier variant per payload group and rejects untagged or dual values. |
| Missing external payload is treated as empty | Fail closed as unresolved input; absence is never completeness evidence. |
| Payload representation is mistaken for currentness | N40 currentness remains external; N41 coexistence remains unchanged. |
| Serialization or schema authority is inferred | N42 chooses only carrier semantics; field names, encoding, schema admission, producers, and compatibility remain later decisions. |
| Packet or runtime behavior is inferred | Packet projection, implementation, Event runtime behavior, profile admission, and release remain forbidden. |
