# N40 risks and gaps

| Risk or gap | Boundary |
| --- | --- |
| Historical receipt presented as current | Receipt claim text must say exact snapshot only; currentness is external or unknown. |
| Timestamp/filename/path treated as freshness | Structurally reject those inference rules. |
| Evaluator becomes currentness owner | Reject current-head-only evaluation as responsibility collapse. |
| Old receipt rewritten after drift | Preserve immutable history; new snapshot produces new artifacts. |
| Currentness vocabulary absent | Keep the reference opaque or unknown; route vocabulary separately if required. |
| Multiple sidecars and supersession | Remains a later lifecycle decision; N40 does not define active uniqueness. |
| Canonical schema and implementation absent | Later Design/Plan only after N40 selection and separate acceptance. |
