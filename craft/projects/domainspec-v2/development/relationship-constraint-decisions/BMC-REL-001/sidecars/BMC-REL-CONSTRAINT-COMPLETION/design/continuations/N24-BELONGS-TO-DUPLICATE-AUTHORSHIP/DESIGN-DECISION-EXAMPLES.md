# N24 Complexity-Aligned Decision Examples

All scenarios are hypothetical. The invariant is exact duplicate authorship under the
same five-part proposition identity. Decision effect: `none`.

## Low — One Exact Fact Authored Twice

Scenario: two source declarations both say `Reply-42 belongs-to_classification
Post-7` in the same admitted authority/feature context.

- A: reject the repeated authorship, preserve both source handles, and require repair.
- B: admit one fact only after later deterministic merge-provenance obligations close.
- C: leave this exact duplicate unresolved and block downstream admission.
- D: end the continuation without changing either source declaration.

Demonstrates the smallest exact duplicate. It does not prove either behavior or a
representation shape.

## Medium — Kind And Parent Diagnostics Interact

Added complexity: the same source/target also has `home-assignment`, while another
classification fact points the same source to a different target.

- A: reject only the repeated exact classification fact; retain the different-kind
  fact and report the different target as a separate D07 competing-parent conflict.
- B: conditionally coalesce only the exact repeat; preserve the different-kind fact
  and separate D07 conflict.
- C: keep only exact-duplicate behavior unresolved; existing diagnostic classes stay distinct.
- D: stop without collapsing kind or competing-parent semantics.

Demonstrates diagnostic partitioning. It does not decide which parent survives or
global duplicate policy.

## Complex — Cross-Feature Sources, Runtime Retry, And Partial View

Added complexity: two cross-feature authoring sources repeat one exact future-admitted
kind-bearing fact, a runtime retry emits the same navigation, and the validation view
lacks closure evidence.

- A: reject only the two authored exact propositions and preserve their handles; do
  not classify the runtime retry as authorship or wait for absence closure.
- B: conditionally coalesce only the authored pair after deterministic provenance
  closes; runtime and partial-view behavior remain separate.
- C: preserve the exact authored diagnostic as unresolved without inferring that the
  open view passes or fails other constraints.
- D: terminate without admitting a future kind, merge rule, or partial-view verdict.

Demonstrates source/context, runtime, and evaluation boundaries. It does not admit a
future kind, prove completeness, or authorize storage/runtime behavior.
