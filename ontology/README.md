# Ontology

Status: candidate authority-model boundary
Owner: CyberAlchemy v2 ontology route

This folder is for the base repository's candidate authority model package:
candidate ontology maps, thick entries, branch maps, authority object and
relation models, projection rules, and promotion requests. The parent
ontology-vault seed is
[../.arcanum/ontology-vault/map-2026-06-18-dispersed-knowledge.md](../../.arcanum/ontology-vault/map-2026-06-18-dispersed-knowledge.md).

Ontology can model authority, condense meaning, and prepare promotion requests.
It cannot promote itself or redefine definitions, constitutions, specs,
capabilities, runtime contracts, schemas, movement edges, or public claims.
The owner-facing authority model lives in
[../authority/AUTHORITY-MODEL.md](../authority/AUTHORITY-MODEL.md); this folder
supplies candidate maps and projections that may support that model without
replacing its owner routes.

## Repository Objective Role

For the future downloadable CyberAlchemy base repository, this folder is where
authority structure becomes explicit and reviewable before downstream projects
build above it. The ontology package should map candidate meaning, authority
kinds, authority postures, relations, lifecycle concepts, evidence, owner
routes, promotion requests, projection boundaries, and residue so the base can
be extended without hidden authority assumptions.

This role does not make ontology the authority owner. Definitions,
constitutions, disciplines, decisions, specs, and runtime contracts still move
through their own owner routes before they count as base authority.
