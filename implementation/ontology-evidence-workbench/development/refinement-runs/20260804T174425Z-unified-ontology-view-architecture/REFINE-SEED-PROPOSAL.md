## Refined objective

Produce one evidence-backed, implementation-ready, non-executed architecture
and Work Pack for a reusable Ontology Evidence Workbench. It must consolidate
the strongest interaction and representation ideas from existing local ontology
views without copying their incompatible renderers. Body War is the full-scale
acceptance fixture, not the product-specific architecture owner.

The target outcome is one coherent frontend contract in which these capabilities
coexist:

- source-backed view/cluster selection;
- bounded home and reversible focus scenes;
- real spatial connections with endpoint attachment and arrow markers;
- exact-predicate color plus redundant pattern, label, and direction cues;
- node-kind/role icons with adjacent text;
- grouped cluster portals with purpose, counts, and exact constituent relations;
- relation-bearing Path comparison;
- evidence/provenance inspection and explicit authority ceiling;
- full graph/index escape;
- desktop, narrow, keyboard, forced-colors, and reduced-motion behavior.

## Architecture questions the loop must resolve

1. What is the shared scene/view model, and which source artifacts own its
   semantics?
2. Which renderer/tool can support compound clusters, semantic zoom, real
   directed edges, labels, keyboard interaction, and large graphs without
   collapsing exact evidence?
3. Which existing view features are reusable concepts, which are reusable code,
   and which are discardable prototypes?
4. How do source views, user-created presentation views, focus scenes, portals,
   and Path results differ?
5. How are exact predicates, presentation patterns, source direction, traversal
   direction, mapping loss, evidence, and authority shown consistently?
6. What is the smallest coherent implementation unit that can render Body War
   correctly and later load Augmentor/Anime.js-style view packs?
7. Which deterministic and human acceptance evidence prevents another
   count-only false positive?

## Preset and research decision

Preset is `full` because the target spans multiple view generations, renderer
architectures, ontology semantics, UX/accessibility contracts, and a future
implementation Work Pack.

Research is `bounded-research`, subject to the same operator confirmation as the
runtime route. The research lane is one primary-source comparison of current
graph visualization tools against requirements derived from local evidence. It
may inspect official documentation and package contracts for candidates such as
React Flow, Cytoscape.js, Sigma.js/Graphology, ELK, and D3. It must not select a
tool by popularity, perform package installation, or make network mutations.

## Done criteria

The Refine run passes only when it produces:

- a deduplicated inventory of existing view families with source posture,
  renderer type, reusable strengths, known failures, and ownership;
- one selected shared scene/view architecture and rejected alternatives;
- explicit source versus presentation semantics;
- a renderer/tool decision record with an adapter boundary and fallback;
- component, state, navigation, accessibility, responsive, and evidence models;
- exact Body War fixture expectations for clusters, nodes, connections, icons,
  portals, Path, inspection, and full-index access;
- negative fixtures that fail when connections become pills, arrows disappear,
  icons are absent, portals flatten, or focus restoration breaks;
- an implementation-ready Work Pack with source-owned build boundaries, atomic
  units, validation commands, and no compiled-bundle string surgery;
- a final `pass`, `flag`, or `block` synthesis grounded in stage receipts.

## Claim ceiling

Refine can produce an implementation-ready design and plan. It cannot claim a
working frontend, human comprehension, accessibility conformance, release,
deployment, production readiness, or ontology promotion. Implementation belongs
to a separately authorized Task Session after this loop.
