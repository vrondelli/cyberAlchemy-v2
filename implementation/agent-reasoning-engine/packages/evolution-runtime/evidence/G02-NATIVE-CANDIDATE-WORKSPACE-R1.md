# G02 native candidate workspace r1 — private experimental construction

## Objective and distinction

Improve selective source acquisition and final evidence selection, not merely
retain history. The r11 runner already instructs source verification; prior
query-then-choose and one-shot causal-delta experiments did not qualify. This
candidate adds an executable `update_candidate` tool, persistent bounded records,
and a current workspace projection on exploration and terminal-review requests.
Every projection goes through the existing native tokenizer/recycler admission.
No gold or reference patch enters this state.

Records distinguish unverified, plausible, and discarded hypotheses. A model
records a short reason, unresolved question, and up to two exact quotations with
delivered read IDs and line bounds. Plausible/discarded records require citations.
Updates check successful receipt-bound delivery, same path, quotation containment,
and native base-source provenance. They commit atomically only when all checks
and the complete bounded projection pass. A valid citation is **not** automatic
verification of semantic relevance, causal responsibility, or repair correctness.
No source evidence or native final selection is silently added or removed.

publication, deployment, or product activation follows from these tests.

budget, semantic/state validity checks, comparator and stopping gate. Preserve
all twelve exposed cases; no fresh case or threshold relaxation after failure.

without claiming general quality. A functional canary alone never admits a fresh
campaign. Advancement needs paired exposed improvement against matched control
and DSH on native Span-F1/File-F1, with complete costs including workspace tokens
and verification reads. Only then consider an untouched confirmation partition.

## Open Questions

reviews two new primary sources without changing this frozen campaign.
[ARISE](https://arxiv.org/html/2605.03117v1) motivates source-backed variable
dependency queries; [A²Agent](https://arxiv.org/html/2608.29831v1) motivates
post-seal separation of acquisition from commitment failure. These are transfer
hypotheses, not ARE results. Hosted GLM training is not established; no
gold-derived inference feedback is permitted. The record also flags a public
worked-example exposure for future confirmation admission.

- Will GLM use explicit hypotheses and targeted verification rather than simply
  restating its existing conclusions?
- Do workspace tokens and verification tool calls yield a net quality/cost gain?
- How should independent semantic review distinguish valid citations from valid
  responsibility judgments without leaking reference labels?
- Can native C++ and documentation needs benefit with existing search/read tools?
- How should resume carry records and their source/receipt identity in a future
  separately sealed version?
