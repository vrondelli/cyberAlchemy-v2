# G01 Java source verifier, r116–r119 — exposed development

Status, 2026-10-05: **provider run completed; strict validity and both matched quality gates failed**. This private post-hoc exposed experiment does not establish superiority or open the untouched GitBug confirmation block.

The [r116 packet builder](../research/g01-gitbug-java-r78/build_source_verifier_packets_r116.py) sealed 36 score-blind Java packets: 12 GitBug and 24 Bears. Each packet gave a single GLM request the failure report, bounded buggy-source excerpts for a union of current production heads, prior nearby files, top-six test-class usage candidates, and top-five failure-anchor candidates. It used neutrally labeled arms A and B for the strong matched and ARE-safe rankings. The model could choose a candidate ID or abstain for each arm; an accepted choice would be moved to second production rank while preserving the arm's all-file and production heads. No fix, gold, provider output, or fresh GitBug case entered packet construction. Maximum prompt was **7,177 bytes**, maximum candidate count **15**. Provider usage was **33,460 prompt** and **4,966 completion tokens**. Among the 13 invalids, six exceeded the frozen reason length, one had wrong keys, four were non-JSON, and two had empty content. The newly reachable r112 candidate ceiling remains real, but this one-shot, short-excerpt, high-evidence verifier did not turn it into gains. Only four of 23 valid answers named any candidate rather than abstaining, and most of those named the current head. A follow-up must address evidence acquisition and model output reliability as separately versioned hypotheses, not relax r117's frozen gate or re-score its invalid outputs as valid. No publication or superiority claim follows.
