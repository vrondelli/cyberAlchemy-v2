# G01 r78 — GitBug-Java unopened-supply screen

Status: prospective, private, source-only. This screen does not select a
superiority method or score a benchmark.

Pin the official GitBug-Java checkout commit and the bytes of each
`data/bugs/*.json` input. Visit files in lexical path order and records in
line order. Retain the first record per repository with Java production-patch
shape, a 40-hex previous commit, and at least one failing test in its stored
actions-run evidence. Exclude all repositories occupied by the pinned prior
BugSwarm, BugsInPy, ARB, and Bears screens. Preserve the resulting order;
do not select by failures, predicted difficulty, archive size, gold paths, or
retrieval performance. This screen may parse records but must never project
`bug_patch`, `test_patch`, fixed commit, commit message, or passing source.

The manifest is a supply census only. A separate, predeclared archive/source
and label-shape admission step must precede a frozen benchmark. The next
mechanism should address the exposed r77 failure mode: ungrounded or
misleading natural-language summaries can demote an already well-ranked
file. Source-grounded stack-frame or symbol retrieval is a candidate, not
an approved superiority claim. Do not use this untouched population to tune
it after scores are opened.

## Open questions

- Will archive and label eligibility leave at least 24 one-per-repository
  independent cases under bounded source caps?
- What strong matched retrieval comparator and cost ceiling will be frozen
  before running this cohort?
