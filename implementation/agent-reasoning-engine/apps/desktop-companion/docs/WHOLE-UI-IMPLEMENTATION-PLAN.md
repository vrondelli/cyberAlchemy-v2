# ARE Companion: complete UI implementation plan

Status: candidate whole-product plan, 2026-09-26. Owner: ARE Companion product
and ARE runtime owners. This is the **parent** plan for the seven
[UX features](ux/README.md); the [adapter work-pack](adapter-observation/WORK-PACK.md)
is one child slice. No runtime work, product approval, installer release, or
deployment is authorized by this document.
The [activated-session control contract](../../../../../development/agent-reasoning-engine/planning/automatic-thread-integration-v1/SESSION-CONTROL-CONTRACT.md)
defines when an external host task may be called ARE-managed. The read-only
Companion observes that state; opening the UI cannot activate or control a chat.

   events, epochs, checkpoints, and frontiers—not hidden model chain-of-thought.
   Threads now uses an ARE-owned, privacy-filtered projection of backend
   threads keyed by a hashed identity. The dashboard does not read ledger
   files directly. When an exact backend thread has a verified C1 plan record,
   the screen shows obligation/completion/open-decision counts and its digest,
   not source text. This is not a projection of all host tasks or this chat.
   A separate aggregate shows gateway-reported threads paused after uncertain
   steering, including when no thread row can be recovered; older wrappers
   report this posture as unavailable rather than clear.
   The durable gateway session index also reports a content-free unresolved
   mutation count across stopped sessions. Threads shows Attention for it even
   with no Reasoning State row; this is not host-outcome reconciliation or a
   safe-retry instruction.

   source anchor: every feature task must reference it, its feature ID, and its
   parent outcome. Complete UI delivery also requires a typed, bounded
   plan-context record in ARE Reasoning State containing the parent plan
   identity/digest, all seven feature obligations, current slice, and open
   decisions. The owning host integration must append/checkpoint it and
   restore/verify it at continuation; a digest alone is insufficient if the
   source cannot be retrieved. The C1 opt-in typed record and wrapper

## Validation and boundaries

- For every page: normal, empty, stale, not configured, unavailable, and
  incompatible fixtures where meaningful; keyboard and screen-reader checks;
  source/time visibility and non-color status cues.
- For each live source: fixed command/endpoint, bounded time and bytes,
  allowlisted projection, no renderer secrets, no arbitrary filesystem read,
  no model or effect call, and no polling while the dashboard is closed.
- Development-only live experiments need a private same-user local boundary.
  If that cannot be guaranteed, use fixtures until step 11. Full security
  hardening is late, but no unsafe general-purpose service is enabled earlier.

  installer and screenshot evidence does not prove cross-platform completion.
