This is a separate, small Tauri 2 shell derived from the existing
[Essays/Workspace desktop pattern](../../../../essays/development/agent-runtime/implementation/desktop/src-tauri/src/main.rs).
It does **not** import the Essays runtime, mount the full Workspace UI, or
expose the existing ARE chat command/approval path.

The 84-pixel floating mark can be dragged and clicked. It opens a lazy-created
dashboard with three local skins. The dashboard runs only ARE's fixed
`doctor --json` command by default and displays a restricted health projection: status,
version, selected component counts, Node match, closure digest, and reason
codes. In explicit development mode, the Adapters page can also call the fixed
`adapter-status --json` read command against an opt-in local gateway
observation socket. That path is off by default, can be explicitly enabled in
an extracted development build, and never joins a
normal gateway session. No repository file browser, arbitrary command execution, model call,
approval control, or ARE mutation is present. Skin selection writes only the
user's companion preference file.

`packages/evolution-runtime/bin/observe.mjs --json --registry-only` path when

`--json --root` path reads durable evidence. The prototype
installer selects this experimental package through an explicit development
closure; ARE Core remains unchanged. The observer verifies
the candidate registry and durable ledger without constructing the writer
kernel, creating a missing root, opening the operational SQLite index, or
activating a cycle. The UI shows at most 24 cycle summaries and distinguishes
candidate definitions from verified records and current execution.

## Repository-local build and run

The first target is Ubuntu 26.04 x86-64. Other Debian-like versions may need
different system package names; other Linux distributions are unverified.
Build prerequisites are Rust through this repository's launcher, Node 26.8.1,
`pkg-config`, GTK 3, WebKitGTK 4.1, D-Bus, and Ayatana AppIndicator development
headers. On Ubuntu 26.04, the missing build packages normally include
`pkgconf`, `libgtk-3-dev`, `libwebkit2gtk-4.1-dev`, `libdbus-1-dev`, and
`libayatana-appindicator3-dev`. Installing system packages is a
separate local-machine action and is not performed by the build script.

From the repository root:

```sh
tools/toolchain/run cargo build --locked --release \
  --manifest-path implementation/agent-reasoning-engine/apps/desktop-companion/src-tauri/Cargo.toml
ARE_COMPANION_NODE="$(realpath "$(command -v node)")" \
ARE_COMPANION_ENTRY="$PWD/implementation/agent-reasoning-engine/bin/are.mjs" \
  implementation/agent-reasoning-engine/apps/desktop-companion/src-tauri/target/release/are-companion
```

This development mode uses this checkout and its installed Node runtime. It is
not the standalone installer. The orb remains in the taskbar for recovery when
a compositor does not honor always-on-top. Linux Wayland may reject pinning or
programmatic placement; drag/pinning require a real compositor test. Named
corner/center presets are now stored as local Companion preferences, while
free drag remains temporary. A seeded Windows cold-start preset was verified;
Linux compositor behavior and an actual save-then-relaunch flow remain open.

## D65 construction boundary

- Product frontier: one observation-only companion prototype with Linux x86-64
  `.deb` and Windows x64 NSIS artifacts; neither is a release candidate.
- Runnable product work: exercise physical pointer input, visible rendering,
  free drag, and saved-preference relaunch on a normal graphical Linux session;
  verify installed-resource resolution on Windows,
  and test a real backend frontier with a host-owned task binding.
- Operational tasks and owners: owner selects supported OS versions, installer
  signing identity, update channel, UI-preference retention, and acceptable
  idle CPU/memory budgets. Local administrators own host prerequisites; this
  task does not change their system packages.
- Affected stages: desktop shell, ARE health projection, source materialization,
  Linux and Windows packaging, and graphical validation.
- Causal blockers: missing platform/display prerequisites prevent their
  corresponding validation; no host-owned task binding prevents a truthful
  current-chat or host-wide reasoning-state claim.
- Deferred operational residue: macOS port, supported Wayland policy, native
  installation/recovery evidence, signing, updater, and stable historical ARE
  decision API.
