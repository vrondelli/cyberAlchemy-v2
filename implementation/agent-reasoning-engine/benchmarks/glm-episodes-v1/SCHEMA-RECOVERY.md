# Schema diagnostic recovery contract

The canonical [patch schema](../../packages/coding-agent-runtime/schemas/patch-set-candidate.schema.json) drives the [local validator](../../packages/coding-agent-runtime/patch-schema.mjs) and native tool parameters. It retains are.patch-set-candidate/v1, now enforcing the already advertised string type for optional rationale. Existing reason codes remain alongside structured issues. New input-bound, duplicate-key and rationale diagnostics are explicit compatibility tightenings. Generic parsing still accepts up to128 changes; native and benchmark callers independently narrow scope.

The validator supports only the schema keywords declared in this canonical contract and rejects unrecognized keywords. It is not a general JSON Schema engine. Every evaluable violation includes JSON Pointer instance/schema paths, a stable code and trusted expected constraints. Wrong parent types stop descent at that parent. No coercion, defaults or property removal occurs. Diagnostics are capped at64 issues and16384 serialized bytes; truncation rejects recovery. Parsing is bounded to1MiB and32 nesting levels. Programmatic objects must be JSON-compatible; duplicate decoded raw JSON keys, cycles, non-finite numbers and accessor/non-JSON objects reject. Format recovery further caps original text at64KiB and rendered prompt at128KiB; token admission remains independently enforced by the existing transport/recycler.

A protected projection must establish the original exact base, operation, path, file hash and complete source for the single diagnostic-runner target. Recovery may fix any remaining schema metadata violations together, including extra nested metadata, while preserving that projection. It never reconstructs missing source or scope. One native model resubmission receives the rejected object, complete diagnostics and generated tool contract. Strict revalidation, protected-projection equality, public checks and separate oracle remain required. Standalone format repair preserves source exactly. Shared correction now uses a validation-only envelope to collect public diagnostics before its one dispatch: passing source remains immutable, while source with public defects may be corrected together with metadata. The local envelope never counts as a model submission. Readiness failures make no model call; transport failure retains unknown accounting and no correction retry occurs. See [joint diagnostics](FORMAT-REPAIR.md#shared-correction-composition).

Fresh matrix recovery additionally requires a recorded passing original completion gate, candidate-invalid reason, complete untruncated text and matching text hash. Invalid candidates now preserve their independently assessed completion gate and structured diagnostics. A correction cannot repair a missing evidence-delivery prerequisite. Retained-case diagnostics evaluate proposal recovery separately and do not retroactively admit original episode gates.

Run schema-recovery-run.mjs with credential reference, fresh evidence directory, fresh private state directory and one retained trial directory. It uses the shared correction composition, owned public container and separate oracle. Existing result directories reject replay. Runtime source snapshots now include the schema JSON itself. Historical prompt variants remain unchanged; generated native schema and recovery guidance are the active contract consumers in this increment.
