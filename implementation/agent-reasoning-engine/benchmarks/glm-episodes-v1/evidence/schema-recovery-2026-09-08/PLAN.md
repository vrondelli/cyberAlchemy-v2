# Schema-driven recovery implementation and evaluation

Implements the immediate product frontier of [the accepted candidate plan](../../SCHEMA-RECOVERY-PLAN.md). DAG: canonical schema -> bounded diagnostics and protected projection -> shared one-call recovery -> local tests and retained corpus -> two retained live corrections -> fresh frozen matrix -> separate first/final/cost/continuity report.

Affected stages: patch parser, native submission schema, recovery, diagnostic evidence and benchmark handoff. Existing candidate wire version retained with documented stricter validation. Provider/native schemas are generated from canonical shape; trusted scope predicates remain explicit. Agent owns bounded local implementation/evidence, provider calls and owned validation workers; user owns activation and unrelated workloads.

Live bounds:one attempt each for retained missing-authority and missing-schema cases (2 model/4 tokenizer maximum), then one matrix at160 initial model/320 tokenizer plus12 correction model/24 tokenizer. No retries, code tuning during frozen runs, patch application or score replacement. Matrix target12 final verified plus all eligible delivery gates, positive headroom, continuity for every recycled initial trial, long8K recycling and verified cleanup. Retained proposal recovery does not retroactively admit its original episode gate.

Causal blockers: invalid source binding, incomplete diagnosis, missing protected source/scope, duplicate JSON keys, failed local tests, source drift, incomplete accounting or unconfirmed cleanup. Operational readiness gates only provider work. Deferred: prompt-policy refactoring, tool-effect diagnostics/retries, declarative public-case migration, unseen-task replication and activation. CAV2-D65 candidate construction; no ontology selector dependency or authority effect.
