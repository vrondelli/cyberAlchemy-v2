# H15 source-preservation instruction conflict

Candidate research; the frozen eight-trial pilot completed under request `glm-source-instruction-62`. During H14, `b0-contract-review` returned exactly the original mutation source, producing `patch-set.change-empty`. Its offered schema and supplied hashes were valid. The native system instruction says “Preserve every inspected requirement and source byte.” That wording conflicts with changing code to repair a defect.

[H15](hypothesis.json) makes this a falsifiable explanation rather than a diagnosis by assertion. The [candidate](candidate-agent.mjs) changes exactly that sentence to distinguish required edits from preserving unrelated behavior. [Manifest](manifest.json) pins old/new candidate hashes and the unchanged pager. The builder rejects missing or duplicate source anchors. No serving source or H14 artifact was edited.

A later experiment must freeze sample size, fixtures, order, exact physical-call cap and evaluation before dispatch. Compare unchanged-source proposals, raw-source semantics, full candidate validity and actual recovery. A lower no-op rate alone does not justify worse semantic results. Missing metadata is a separate failure that this wording is not assumed to fix.

## Bound pilot

The [experiment](prepared/experiment.json) now defines eight trials: 10K and 12K, two repetitions, original-versus-clarified system wording on the same byte pager and archive-start fixture. Both arms receive the same existing metadata card to control structural guidance. Only the system sentence differs. The [prepared manifest](prepared/manifest.json) binds the 96-model/192-tokenizer cap, sources and fixtures. H14 completed before dispatch. [Execution binding](execution-binding.json) pins the evaluation, manifest and effect proposal before the first H15 call. It is a mechanism probe, not whole-chapter qualification.

The prospective [evaluation](EVALUATION.md) specifies schema-independent no-op detection, all-source hidden semantic checks, and explicit inconclusive outcomes for missing attribution or no baseline mechanism exposure. H14 is now complete: its full audit found four unchanged sources, including one rejected before transaction diagnostics. This strengthens the reason to test H15 but does not establish the instruction as their cause.

## Completed result

The [final evaluation](review-final/report.json) supports H15 under its predeclared mechanism screen. Clarified wording passes **4/4** complete repairs; baseline passes **2/4**. Baseline has two unchanged-source proposals; treatment has none. Raw-source hidden semantic passes are also 2/4 versus 4/4. All eight submitted envelopes satisfy the schema. Paired outcomes are two treatment wins and two ties, with one win at each window. This small pilot cannot establish generalization or the model's internal interpretation.

The [evidence verification](verification.json) confirms 96 model calls and 112 tokenizer calls, no retries, 16 actual recycles, archive recovery and required reads in 8/8, and no unsafe dispatch. Both rejected baseline sources were independently tested in pinned containers; each passes only 5/6 cases. Those proposals remain failures. The [canonical observation and decision](review-final/research.json) retain exact source hashes and select replication before adoption. The [joined DAG](../research/dag-source-62-final.json) contains 51 verified records and 67 edges.

`review.mjs NEW_OUTPUT_DIRECTORY` reproduces the completed-row audit, supplemental raw-source tests and canonical evaluation. `evaluate.test.mjs` verifies unknown-attribution and schema-independent no-op handling. A separate [selected-prompt capture probe](capture-binding.json) passed six loopback scenarios with tamper/measurement controls; it made zero provider calls and did not alter the H15 run.

The original small-window profile already passed its historical 36/36 final gate. H15 is a new first-proposal improvement candidate, not a replacement qualification or serving change. Its next targeted replication must include 8K and the archive-end variant. Larger contexts, stronger fact retention and product delivery remain in the [single GLM finish tracker](../../../../../GLM-FINISH-PLAN.md).
