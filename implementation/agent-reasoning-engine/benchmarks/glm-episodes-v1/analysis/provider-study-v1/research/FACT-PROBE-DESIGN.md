# Stronger continuity probe design

Candidate design, not yet frozen or executed. This follows the minimal recovery endpoint in H12/H13/H14 and the original H5 continuity-coverage question. Retrieving one meaningful archive page is not proof that earlier task facts survive.

## Discriminating task

Use a small function repair whose required return value is derived from a versioned fact in an inspected document. Put an obsolete value on the first delivered page and the authoritative revision on a later page. After both are delivered, require enough neutral inspected load to cause a measured recycle before final synthesis. The hidden semantic oracle checks the revised value; separately report use of the obsolete value, a fabricated value and refusal.

The expected value must not appear in the final user request, late contract projection or source attachment. The late contract may specify the precedence rule and how to recover the earlier evidence, but must not repeat the answer. Keep a control with an unrevised fact, and a negative control that changes the earlier fact while retaining the same late instructions. Use fresh deterministic fixture seeds per frozen replicate, not answers from previous model failures.

## Exposure proof

A valid probe must prove all of the following from captured selected prompt bodies and receipts: the exact fact revision was delivered before recycling; final synthesis occurs in a later generation; the final selected context contains either correctly preserved fact evidence or a verified recovery of the relevant earlier page; and the hidden result agrees with the authoritative revision. Journal presence alone is not delivery, and a generic archive read is insufficient.

Add exact prompt capture before token measurement, binding selected payload hashes to transport receipts without saving credentials. Keep baseline and treatment captures separate from scripted fixture setup. Inspect current source/requirements projections for answer leakage before any live claim. A no-recycle run is an exposure failure, not a continuity pass.

## Selected-prompt capture prerequisite

The study-only [capture adapter](../source-instruction-v1/prompt-capture.mjs) now records decorated prompts without changing their bytes. It selects only prompts whose exact string digest appears in an actual dispatch, then reconstructs the transport body using the explicit model/output settings and receipt reasoning effort. Both model and successful tokenizer body hashes must match. Capturing all rendered candidates alone is not selected-context evidence.

The [loopback evidence](../source-instruction-v1/capture-evidence/result.json) passed six scripted cases across 8K/10K/12K with and without forced recycling. Separate negative controls reject altered physical receipts, absent tokenizer measurement, and an unobserved selected digest. [Source bindings](../source-instruction-v1/capture-binding.json) preserve the exact candidate. This is construction evidence with zero provider calls, not a live continuity result; the ongoing H15 cohort does not use this added hook.

The default 2,048 output cap and transport framing are explicit capture assumptions. A differing configuration must be passed and verified against receipts; body reconstruction must fail if the transport changes. The versioned-fact fixture, meaningful pre-recycle delivery, and correct-page recovery still require their own test.

## Experiment boundary

Freeze original-versus-candidate mechanism, fixtures, exact stale/revised values, ordering, number of recycles, live call caps and falsifiers before execution. Preserve output-schema failure separately from wrong-fact behavior. Do not repair hidden-oracle failures and then count the repaired task as held out. Candidate implementation and test design require a fresh exact effect boundary; current H14 model budget cannot be silently reused for this probe.
