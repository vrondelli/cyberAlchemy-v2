# Bounded diagnostic repair workflow

Owner-directed implementation of the approved [success DAG](../success-plan-v1/PLAN.md). Authority effect none; no registry admission, default activation or publication. Current construction frontier is staged-patch attribution, a public reproducer and testable revisions, followed by at most3 functional episodes and1 fresh pressure episode. Provider/evaluator prerequisites and deferred operational work remain as defined by that plan.

The public fixture is operator-authored from the issue's stated distinction: an awaited variable referenced in a snippet without an explicit snippet parameter. A parent boundary provides the required async execution context. No reference patch or private test body was consulted. Earlier scaffolding errors are preserved under `evidence/probe-development/`. The explicit-parameter control changes only this public diagnostic fixture; it is not a source repair or a model success.

`stage.cjs` constructs a delta between actual initial and proposed bytes without mutating the source checkout. `container.mjs` verifies before/after hashes when applying that delta to the pinned image. This excludes pre-existing dependency changes and supports initially dirty source targets. `workflow.mjs` binds public test results to exact candidate IDs, retains hypotheses and bounded failure evidence, and limits the episode to2 candidates and4 probe requests. `contract.mjs` validates entire arguments and aggregates schema issues. `transport.mjs` adds an explicitly identified24-call diagnostic policy to the previous accounting adapter; standard policy limits remain unchanged.

The model sees only the public probe's source, baseline failure and generated client code, plus its own public candidate-test feedback. Private benchmark evaluation runs only after final submission. A passing public probe is necessary diagnostic evidence, not sufficient task success. Success requires all67 repair and5120 regression labels to pass twice in fresh evaluators for the exact model patch. A separate fresh pressure episode follows functional success.

Budget maxima:24 model/48 tokenizer calls per episode; at most96/192 across the campaign; no automatic retries;60s model deadline;30-minute episode ceiling;120s per public probe; sequential2CPU/4GB diagnostic/evaluator jobs. Local threshold12K, hard limit16,384, output cap2,048, and512 margin plus retained-reasoning reservation are preserved. Reserve the last4 model calls for review/finalization. Per-episode USD0.10 reserve, campaign USD0.40, subject to price verification before dispatch.
