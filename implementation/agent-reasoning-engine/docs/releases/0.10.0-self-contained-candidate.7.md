## Result

Candidate 018 is the first ARE candidate whose declared product closure has no
Alch or DomainSpec build-time or runtime dependency. The closure contains 907
files and 7,954,528 bytes. The immutable receipt records 1,158 passing cases
across 146 test files and 20 targets in `isolated-source-closure` mode.

Some ARE-owned frozen ontology records retain a historical `domainspec/`
directory name. They are static product data. Candidate 018 does not include or
invoke the DomainSpec compiler, `domainspec-core`, or the Alch toolchain.

The release verifier reports `PASS` for the `self-contained-source-closure`
distribution. The standalone materializer copies the exact closure into an
empty destination, preserves executable modes, verifies every regular-file
digest, and returns a closure-bound receipt.

The source-distribution lifecycle drill also reports `PASS`. Two normalized
archive builds were byte-identical, and the extracted candidate passed install,
health, gateway restart/reconnect, injected-corruption detection, rollback and
uninstall checks in a disposable prefix. Gateway-session and Reasoning-State
stores also passed 0600 backup, injected-corruption detection, exact restore and
recovery verification.

## Main changes

- Replaced the compiled-language semantic adapter with an ARE-native Unicode
  normalization and phrase-matching adapter.
- Removed the external compiler, generated-language governance cutover, and
  Define CLI integration from the ARE product boundary.
- Moved the bounded local SOPS-age process bridge into ARE-owned source.
- Added a permanent closure guard that rejects DomainSpec and external Alch
  language paths.
- Added a standalone distribution materializer and an isolated runtime test.
- Preserved Candidate 013 and its artifact preflight as historical evidence.
