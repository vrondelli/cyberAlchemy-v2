## Execution rules

- Every wave receives a separately generated execution-time Context Builder
  pack and an exact authorization envelope.
- Execute natively through the repository tools and bounded package adapters,
  following the completed CRABS replay precedent. Do not invoke Task Session.
- Use fresh output directories and append-only attempt indexes. Never overwrite
  completed reference, failed, inconclusive or reviewer evidence.
- Freeze property, source, tool, commands, denominator and expected negative
  controls before provider execution.
- Build C/C++ only through repository `tools/toolchain/run`. Historical GCC13
  paths are not presumed available; changed tool epochs require explicit
  comparability review.
- Stop downstream success promotion on timeout, output overflow, missing case,
  stale binding, wrong assertion, surviving control or reviewer disagreement.
- Repair work starts only from a confirmed defect under separately selected
  mutation scope.

## Completion and stop conditions

W2 stops successfully with any truthful typed CRABS outcome plus complete
negative-control evidence; L2 promotion still depends on W3. W4 stops when the
owner declines both properties, evidence is not comparable, or review remains
unresolved. W5 produces a candidate decision only; customer contact needs a
