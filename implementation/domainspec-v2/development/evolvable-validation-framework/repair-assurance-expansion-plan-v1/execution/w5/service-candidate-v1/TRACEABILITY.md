# Service-claim traceability

| Service claim | Earned evidence | Boundary |
| --- | --- | --- |
| Freeze property, implementation, tools and denominator | CRABS L2 candidate and Auth L3 author manifests | Exact internal candidates only |
| Produce typed counterexample or bounded no-counterexample | CRABS 48/48/2 no-counterexample result; Auth pipeline counterexample | No general proof or guaranteed discovery |
| Detect false-success paths | CRABS ten negative controls and five mechanism tests; Auth twelve hostile controls and ten evidence tests | Selected controls, not exhaustive adversarial assurance |
| Explain and repair a confirmed defect | Auth `.runtime` copy-boundary counterexample, repair patch and causal replay | Evidence-pipeline defect, not Auth product defect |
| Evaluate business-rule implementations | Auth 48 authorization checks and 64 Rust tests | Exact fail-closed authorization candidate only |
| Evaluate bounded distributed-state behavior | CRABS three-replica 48-case campaign plus two CBMC representatives | Frozen cases and finite model bounds only |
| Provide separate technical replay | Independent CRABS and Auth reviewers returned AGREE | Same host; technical replay is not accreditation |
| Verify repair against superficial alternatives | Seeded CRABS/Auth mutations and neutral controls | Calibration evidence; mutants are not natural defects |
| Quote measured delivery | Command timing ledger | Machine-time lower bounds only; labor unmeasured |
