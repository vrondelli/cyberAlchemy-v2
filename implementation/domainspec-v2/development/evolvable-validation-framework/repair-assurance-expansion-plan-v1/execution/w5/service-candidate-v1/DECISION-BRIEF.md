# Product decision: one bounded pilot, revise, or defer

## Recommendation

Select **propose one bounded P1 pilot**, with no customer contact until a
separate authorization names the target and approves outreach. This decision
would approve the service hypothesis and pilot qualification work; it would not
approve a price, contract, data transfer, execution, certificate, publication,
or deployment.

The evidence supports a narrow pilot because two implementation types completed
the property-to-result workflow, both received separate technical replay, the
controls detected selected false-success paths, and Auth produced a natural
pipeline counterexample with a verified repair. The evidence does not yet
support P2/P3 delivery promises, fixed pricing, independent accreditation, or a
claim that a natural product defect will be found.

## Proposed P1 ceiling

- one customer-owned deterministic business rule;
- one implementation revision with an existing reproducible build;
- at most one executable verification route;
- a frozen case denominator agreed during intake;
- one selected control from each of the five control classes;
- one separately assigned technical replay;
- one small repair option only after a confirmed natural counterexample;
- no production effects; and
- time, compute, data and retest caps agreed before work.

## Decision choices

| Choice | Effect |
| --- | --- |
| Pilot | Accept this candidate and authorize internal qualification for one P1 pilot. Customer selection and contact remain separate. |
| Revise | Return named package sections for correction; node O remains open. |
| Defer | Preserve the package without starting pilot qualification. |
