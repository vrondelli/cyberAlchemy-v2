# Stable Repository Stewardship

Status: candidate
Steward: CyberAlchemy v2 authority owner

## Purpose

Govern the recurring practice of turning dispersed CyberAlchemy, Arcanum,
DomainSpec, validation, inventory, ontology, and research material into a
stable repository surface without collapsing authority boundaries.

## Boundary

This discipline names the operating practice. It does not define canonical
terms, author constitutions, promote ontology, decide public/private extraction,
or implement runtime code. Those routes belong to definitions-governance,
constitution-governance, ontology-vault, decision-gate, and task-session.

## Quality Bar

A useful stable repository stewardship entry must:

- preserve source evidence and authority posture,
- keep inventory, ontology, research, specs, implementation, validation, and
  observability separate,
- name the route that owns each promotion,
- keep public/private boundaries explicit,
- make the repository navigable for future humans and agents,
- record open questions instead of hiding unresolved decisions.

## Promotion Guardrail

This discipline can recommend constitution, definition, decision, or
task-session routes. It cannot directly promote source claims, ontology nodes,
definitions, specs, capabilities, or implementation behavior.
