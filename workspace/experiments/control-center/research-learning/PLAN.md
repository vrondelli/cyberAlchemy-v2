# Workspace research-learning prototype

## Scope and product construction

Unit WRL-001: connect exact historical CC006 smoke evidence to ARE research
records, a derived DAG and evidence-bound work state. This is a retrospective
research registration, not a preregistration or proof of repair benefit.

Prototype definitions and ontology: reuse ARE-RL-D01 through D08 from
`are.research-learning`; profile.json binds the source ontology. No canonical
terms or ontology admission are changed. Product intent is inspectable learning
from Workspace tests; business ownership remains Workspace research/test owners.
The typed profile and adapter are the local implementation prototype; JSON and
HTML are derived read models, not authoritative task state or a new ledger.

## Implementation sequence

1. Bind source evidence and ontology; declare rejected-host semantics.
2. Add strict adapter: verify exact report/candidate/budget/protocol/log bytes,
   replay raw performance samples and host qualification, preserve failures.
3. Add explicit verifier injection to existing ARE DAG/work derivation. Default
   ARE behavior stays unchanged. Adapter callbacks are trusted code, not data.
4. Derive six research nodes and a separate work plan. Complete only the evidence
   inspection criterion with a substantive verifier; keep causal research ready.
5. Emit read-only JSON/HTML views and test malformed inputs, digest drift,
   contradictory outcomes, missing logs, readiness and completion checks.
6. Bind exact implementation dependencies in a candidate manifest and retain
   current deterministic test evidence. Product approval remains not requested.

## Lanes and blockers

Runnable product construction: adapter, derivation, view, tests. No live-model,
desktop or benchmark execution is part of this unit.

Operational support: test operator owns host qualification for a future native
product-test stage. Rejected host measurements block a performance conclusion,
not this integration. Native reruns require their own exact run boundary.

Deferred residue: app embedding, durable state persistence, future experiment
criterion adapters, product approval, lab reconciliation and publication.
No dispatch, activation, acceptance or external effect follows from readiness.
